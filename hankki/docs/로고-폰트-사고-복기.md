# 로고·폰트 사고 복기 (2026-07-16)

로고의 '한끼'가 주아체 대신 고운돋움으로 계속 잘못 나오고, HANKKI 서체가 오락가락하고,
확정 파일이 덮어쓰기로 뒤바뀌던 하루의 복기. **다시는 반복하지 않기 위한 기록.**

---

## 1. 무슨 일이 있었나 (타임라인)

1. 로고 확정본(곰=ㅎ '한끼' + HANKKI)을 만들어 커밋했는데, '한끼'가 **주아체가 아니라 고운돋움**으로 렌더된 채 확정됨 → 그걸로 앱 아이콘까지 생성·커밋.
2. 사용자가 "주아체 아니야 / 고운돋움체야"라고 지적 → 원인 조사 시작.
3. 조사 중 잘못된 검증("겹쳐보니 같으니 임베드 폰트는 진짜 주아다")으로 한 번 더 헛다리.
4. 진짜 원인 발견: **fonts-embed.css 의 unicode-range** 가 붙은 @font-face 를 canvas `fillText` 가 못 골라 **엉뚱한 폰트로 폴백**되고 있었음. (DOM 텍스트는 정상, canvas 만 문제 → 목업은 예뻤는데 생성기 출력만 이상했던 이유)
5. HANKKI 서체도 혼선: 세리프로 보여서 시스템 세리프 후보를 보여줬으나, **원본 목업 HTML** 을 확인하니 `.en { font-family:'GowunDodum'; 38px; letter-spacing:14px; 700 }` — 고운돋움이 정답이었음. (획 끝이 살짝 퍼져 세리프처럼 보였던 것)
6. 이 과정에서 확정 프리뷰 파일들을 같은 이름으로 여러 번 덮어써서 "파일 없어진 거 아니냐"는 불안을 만듦. (실제 유실은 없었음 — git 에 있었음)

## 2. 근본 원인

| # | 원인 | 설명 |
|---|------|------|
| 1 | **unicode-range + canvas 폴백 버그** | base64 인라인 폰트에 unicode-range 를 붙였더니 canvas fillText 가 face 를 못 고르고 조용히 폴백. 에러가 없어서 눈치 못 챔. |
| 2 | **렌더 결과를 눈으로 검증 안 함** | "겹쳐보니 동일" 같은 간접 검증은 둘 다 폴백이면 통과해버림. 실제 글꼴 모양을 눈으로 봐야 했음. |
| 3 | **기억으로 추측, 원본 미확인** | HANKKI 서체를 기억으로 추측(세리프 후보 나열)함. 원본 목업 HTML/git 기록에 스펙이 그대로 있었음. |
| 4 | **같은 이름으로 덮어쓰기** | 확정본을 같은 파일명으로 반복 덮어써서 이전 상태가 사라진 것처럼 보임 → 불안·혼란. |

## 3. 고친 것 (코드)

- `design/promo/mkfonts.mjs` — **unicode-range 제거**. 라틴 face 먼저 + 한글 face 뒤에, 글리프 커버리지로 매칭. (주석에 이유 기록)
- `design/promo/logo/gen-logo.mjs` —
  - 폰트를 fonts-embed.css 에 의존하지 않고 **저장된 woff2 를 유니크 패밀리(JuaWM/GDWM)로 직접 주입** → 폴백 자체가 불가능.
  - `document.fonts.load()` 로 실제 로드 보장 후 그리기.
  - **덮어쓰기 금지**: 출력 파일명이 이미 있으면 `-2, -3…` 자동 새 이름. 확정본 교체는 사람이 확인 후 명시적 cp 만.
  - 확정 스펙을 기본값으로 고정, 실험은 CLI 인자로만: `node gen-logo.mjs [outDir] [border] [up]`
- 폰트 원본은 `design/promo/fonts/` 에 영구 보관 (npm @fontsource, OFL 라이선스): 주아·고운돋움·개구·나눔펜 각 한글+라틴 woff2. **다시 다운로드할 필요 없음.**

## 4. 로고 확정 스펙 (2026-07-16)

- 워드마크 '한끼': **주아(Jua) 172px** — `fonts/jua-korean-400.woff2`
- 곰(곰곰 셰프) = '한'의 ㅎ 동그라미: 픽셀 검출로 링 정중앙, **테두리 5px · 위 3px**, 좌우대칭, 귀 온전(모자 위)
- 'HANKKI': **고운돋움(GowunDodum) 38px · 자간 14px · 굵기 700** — `fonts/gowun-dodum-latin-400.woff2` (+ strokeText 0.9 로 합성볼드 재현)
- 색상 2종: ① 밝은 크림 `#fffdf8` + 브라운 `#6b4f3a` (앱 아이콘용) ② 클레이 브라운 `#c9784f` + 크림 (대표그래픽·확장용)
- 생성: `/opt/node22/bin/node design/promo/logo/gen-logo.mjs` → previews/ 에 새 이름으로 출력

## 5. 재발 방지 수칙 (작업 규칙)

1. **폰트는 반드시 저장본 직접 주입** — CDN·구글폰트 링크 금지(프록시 차단), fonts-embed.css 의 패밀리명도 canvas 에선 신뢰하지 않는다. `design/promo/fonts/` 의 woff2 를 base64 로 심고 `document.fonts.load()` 확인 후 그린다.
2. **보여주기 전에 눈으로 검증** — 렌더 결과 PNG 를 직접 열어 글꼴 모양·위치를 확인한 뒤에만 사용자에게 보여준다. 간접 검증(겹침·치수)만으로 통과시키지 않는다.
3. **과거 스펙은 기록에서 복기** — "예전에 어땠지?"는 추측 금지. 원본 목업 HTML, git log/show, docs 를 먼저 뒤진다.
4. **덮어쓰기 금지** — 산출물은 항상 새 이름(자동 suffix)으로. 확정본 교체는 사용자 확인 후 명시적으로만. 확정 커밋은 메시지에 '확정'을 남겨 git 에서 바로 찾게 한다.
5. **확정본 위치** — `design/promo/logo/previews/한끼로고-크림-512.png`(앱 아이콘 원본), `한끼로고-클레이-512.png`, `확정-2색.png`. 앱 아이콘은 이 크림 512 에서 `public/icons/*-v4.png` 4종(192/512/maskable 0.86/apple-touch 180)으로 생성.
