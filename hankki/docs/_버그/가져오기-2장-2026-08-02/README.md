⭐⭐ **이로써 「가져오기」 한 화면에 버그가 다섯이다** (A·B·C ＋ D·E).
   우연이 아니라 **제일 복잡하고 손을 제일 많이 탄 화면**이라는 신호다.
   📌 하나씩 땜질하지 말고 **다섯을 같이 재현해서 한 번에 정리**한다.

## D. 크롭이 「내가 자른 것보다 더 작게」 잘린다

**의심 = 크롭 비율의 «기준»이 보이는 이미지가 아니라 컨테이너다**

`components/CropSheet.jsx`
```js
53:  const b = boxRef.current.getBoundingClientRect()     // ← 기준이 «박스»
89:  const sx = Math.round(rect.x * img.naturalWidth)     // ← 비율을 원본에 곱한다
90:  const sy = Math.round(rect.y * img.naturalHeight)
```

⭐ **왜 「더 작게」가 되나** — 캡처는 **세로로 아주 길다**(1080×2340).
   `object-fit: contain` 이면 **좌우에 빈 여백(레터박스)** 이 크게 생긴다.
   그런데 비율을 **여백까지 포함한 박스** 기준으로 재면, 같은 비율이 **실제 이미지에선 더 좁은 영역**이 된다.
   → **손가락으로 잡은 것보다 작게 잘린다.** 증상과 정확히 맞는다.

✅ **고칠 방향** = 비율의 기준을 **「실제로 그려진 이미지 영역」**으로 잡는다
   (컨테이너 크기와 `naturalWidth/Height` 비를 견줘 레터박스를 빼고 계산).
🔎 **재현** = 세로로 아주 긴 캡처(위 증거 사진 그대로)로 해야 티가 난다. **정사각에 가까운 사진은 오차가 작아 안 보인다.**

## E. 「사진 닫기」를 못 누른다 — 버튼이 화면 밖으로 나간다

`screens/EditorScreen.jsx` **443~450줄**
```js
onClick={() => setPin(null)}
aria-label="캡처 사진 닫기"
style={{ position: 'absolute', top: 8, right: 8, … }}   // ← «패널» 기준 absolute
```

⭐ **`absolute` 는 「패널의 위쪽」에 붙는다.** 패널이 길거나 스크롤되면
   **버튼이 화면 밖으로 밀려나 누를 수가 없다.** 그러면 사진이 레시피를 덮은 채로 **치울 방법이 사라진다.**

✅ **고칠 방향 (셋 중에 고른다 · 재현 뒤 결정)**
1. **버튼을 `sticky` 로** — 패널이 스크롤돼도 늘 화면 안에 남는다 (제일 작게 고치는 길)
2. **패널 자체를 접을 수 있게** — 「사진 보기/숨기기」 토글을 **고정 자리**에 둔다
3. **뒤로가기로도 닫히게** — 이미 전체보기(zoom)는 그렇게 돼 있다(159줄). 같은 방식을 여기에도

⚠️ **닫아도 사진이 사라지면 안 된다** — `refs` 에 남아 있어야 「크게 보기」로 다시 볼 수 있다.
   `setPin(null)` 은 «가리기»지 «삭제»가 아니다. 고칠 때 그 성질을 지킨다.
