# 한끼 작업 명령어 (지시어)

> 창업자가 이 단어를 말하면 클로드가 정해진 절차를 실행한다. **언제든 "명령어"라고 하면 이 목록을 보여준다.**
> 확정 11개. 필요하면 추가·수정.

---

## ✅ 확정 명령어 (11)

각 명령어는 **한 단어**만 말해도 아래 절차가 그대로 실행된다.

### 1. `doc저장`
**하는 일:** 지금까지 한 작업을 복기 → 검토 → 수정 → 정리해서 문서로 저장 → 창업자에게 보여준다.
**왜:** 결정·자산을 글로 남겨 나중에 잃지 않기 위해.
**주의(이중장치):** 문서든 산출물이든 **덮어쓰지 않는다.** 같은 이름이 있으면 반드시 새 이름(번호 -2, -3…)으로 저장하고, 이전 버전을 남긴다.

### 2. `점검` (= 전수점검)
**하는 일:** 빌드 오류 확인 + 주요 화면 런타임 스모크 테스트 + 버그 사냥 → 요약 보고.
**왜:** 배포 전에 깨진 곳이 없는지 한 번에 훑기 위해.

### 3. `청소`
**하는 일:** 죽은 코드·안 쓰는 import·찌꺼기 파일 정리 → 빌드 확인 → 커밋.
**왜:** 프로젝트가 무거워지고 헷갈리는 걸 막기 위해.

### 4. `배포확인`
**하는 일:** 방금 푸시가 실제로 배포됐는지(GitHub Actions → Pages) 확인, 실패 시 원인까지.
**왜:** "올렸는데 왜 안 바뀌지?"를 없애기 위해.

### 5. `복기`
**하는 일:** 저장 없이, 지금까지 한 것만 요약해서 보고.
**왜:** 문서로 남기기 전에 상황만 빠르게 짚고 싶을 때.

### 6. `아카이브`
**하는 일:** 기능-아카이브 문서 내용을 채팅에 요약해 보여줌(필요하면 최신화).
**왜:** "지금까지 만든 기능이 뭐였지?"를 한눈에 보기 위해.

### 7. `릴리즈` (= 배포)
**하는 일:** 버전 올림 → 빌드 → 커밋 → 푸시 (기능 완성 시 표준 출고 절차).
**왜:** 완성된 기능을 정해진 순서로 안전하게 내보내기 위해.

### 8. `마무리` (= 쉬자)
**하는 일:** 세션 정리 — 남은 변경 커밋·푸시 + 문서 최신화 + 요약 + 대기 중인 항목 정리.
**왜:** 하루를 깔끔하게 닫고, 다음에 이어서 시작하기 위해.

### 9. `문구점검`
**하는 일:** 오타·맞춤법·톤(과장된 말투) 전수 점검 후 수정.
**왜:** 출시물의 글이 어색하거나 과장되지 않게.

### 10. `스샷`
**하는 일:** 특정 화면을 렌더·캡처해서 보여줌(디자인 확인용).
**왜:** 글로 설명하는 대신 눈으로 바로 확인하기 위해.

### 11. `확정` ⭐ 신규
**하는 일:** 지금 보고 있는 산출물(로고·이미지·문구·화면 등)을 **확정본으로 명시적으로 교체**한다.
- 이전 확정본은 **절대 지우지 않고** 새 이름(번호)으로 보존한다.
- 교체 후 어디에 뭐가 저장됐는지, 이전 버전은 어디 있는지 알려준다.
- 필요하면 그 확정본에서 파생물(예: 앱 아이콘 규격들)까지 새로 뽑는다.

**왜:** 창업자가 눈으로 확인하고 "이게 최종"이라고 말할 때만 확정본이 바뀌게 하기 위해.
클로드가 제멋대로 확정본을 갈아치우거나, 덮어써서 이전 버전이 사라지는 사고를 막는다.
**핵심:** 클로드는 창업자가 `확정`이라고 말하기 전엔 확정본을 건드리지 않는다. (그 전까진 결과물을 임시·번호 이름으로만 저장)
