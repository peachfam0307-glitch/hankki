## A. 코드·앱 삽질

### A1. 뒤로가기 누르면 앱이 꺼짐 (최대 난이도, 폴드7에서 심함) ⭐
- **증상**: 팝업(꾸미기·미리보기·장바구니 시트·아바타) 열고 뒤로가기 → 가끔/반복 시 앱 종료. 창업자 폰은 괜찮은데 **남편 폴드7에서 심하게** 재현.
- **원인 3단**: ①`popAll`이 `history.go(-n)`인데 popstate는 1번만 쏘는데 n번 억제 → 카운터 고착. ②탭 화면 필터 핸들러가 위에 뜬 상세 화면 뒤로가기를 가로챔. ③**최종 보스**: popstate 안에서 터치 없이 `pushState`로 트랩 재보충 → 크롬 history intervention이 그 칸을 skip-on-back 처리 → 히스토리 바닥 → TWA 종료.
- **해결**: 모달=열 때(터치 시점) 진짜 히스토리 칸 1개(`App.openModal`, gesture-backed). `useModalBack`/`useLayerBack`으로 전 모달 이관. 겹친 모달 동시닫힘은 마이크로태스크 배칭 `go(-n)` 1회. **루트 종료 가드는 pointerdown이 아니라 pointerup/click/keydown에** (폴드7 최종 해결 열쇠). 크롬 intervention 시뮬 15+9 시나리오 + 실기기 검증.
- **교훈**: popstate 안에서 gesture-less pushState 금지 / 터치 제스처 인정 시점=pointerup / "홈에서 뒤로=종료 확인창"은 기기 따라 안 뜰 수 있음(완벽 보장 대상 아님).
- (상세: `작업복기-2026-07-17.md` 2)

### A2. 아바타 시트가 안 닫히거나 같이 꺼짐
- **증상**: 아바타 시트 + 그 안 픽커가 동시에 닫히며 히스토리 꼬임.
- **원인**: 시트와 픽커가 동시에 close → `go(-n)` 중복.
- **해결**: 픽커 onChange에서 `setAvatarSheet(false)` 제거(동시 이중닫힘 제거), 배칭으로 1회 처리.
- **교훈**: 겹친 모달은 "동시에 닫지 말고" 배칭 1회로.

### A3. 폴드(넓은 화면) 꾸미기 메뉴 안 보임
- **증상**: 남편 폴드7 펼치면 꾸미기 서랍이 안 보임.
- **원인**: `.decor-editor`가 화면 전체 폭 → 정사각 캔버스가 거대해져 서랍을 밀어냄.
- **해결**: max-width 440px 중앙 정렬.
- **교훈**: 넓은 화면(폴드/태블릿)에서 정사각 요소 폭 상한 두기.

### A4. iOS localStorage 5MB 조용한 유실
- **증상**: 사진 많이 저장 시 iOS에서 조용히 데이터 유실 가능.
- **원인**: localStorage 5MB 한계(특히 iOS), 에러 없이 실패.
- **해결**: 경고 토스트 추가. 근본 해결(IndexedDB 이전)은 백로그.
- **교훈**: 조용히 실패하는 저장 한계엔 사용자 경고부터.

### A5. 회귀 3건
- 탭 핸들러가 상세 뒤로가기 가로챔 / 공유 인입 시 히스토리 칸 누락 / 프로필 백업 시트 back 미처리 → 각각 수정.
- **교훈**: 뒤로가기 리팩터 후엔 모든 진입경로(공유인입·백업시트) 회귀 점검.

### A6. (디버깅 삽질) 앱이 너무 빨리 꺼져 스샷 불가
- **증상**: 원격(남편 폰) 문제인데 종료가 빨라 원인 못 봄.
- **해결**: 화면에 로그 찍는 임시 진단(localStorage 보존) → 창업자 스샷으로 흐름 포착 → 원인 확정 후 진단 제거.
- **교훈**: 원격 기기 디버깅엔 화면-온 로그(영속)가 결정타. 해결 후 반드시 제거.

## B. 배포·콘솔 삽질

### B1. 설치 앱 위에 주소창 뜸 (assetlinks) ⭐
- **증상**: 곰곰이 앱 깔면 화면 위 주소막대가 뜸(풀스크린 아님).
- **원인**: `.well-known/assetlinks.json`에 **Google Play 앱 서명 지문(28:DF:DB…)이 빠짐**(업로드키 63:89:0D만 있었음).
- **해결**: 지문 2개 다 넣어 수정. 근데 **파일 편집 자체가 대삽질**(아래 B2).
- (상세·삽질 8건: `assetlinks-고치는법.md`)

### B2. assetlinks 파일을 못 고침 (8번 헤맴)
- **증상**: GitHub 편집기가 "404" 또는 "Error loading page"로 계속 뻗음(폰·PC 둘 다).
- **원인**: ①파일은 hankki가 아니라 도메인 루트 레포에 있음 ②브랜치가 `main`이 아니라 **한글 `오답끝`** ③GitHub 웹 편집기(`/edit/`)가 **한글 브랜치를 못 읽고 SPA가 뻗음**(폰 탓 아님).
- **해결**: **PC + github.dev(`.`키)** 로 열어서 편집(다른 편집기라 한글 브랜치 OK) → OAuth 허용 → sudo 이메일 코드 → 소스 제어에서 커밋. raw URL로 지문 2개 반영 확인.
- **교훈**: 이 레포 편집은 무조건 PC github.dev. 일반 연필 편집기 금지. "컴퓨터?" 나오면 즉시 컴퓨터로.
- (상세: `assetlinks-고치는법.md`)

### B3. add_repo 승인이 도구까지 안 먹힘
- **증상**: 클로드가 직접 그 레포 고치려 `add_repo` 호출 → "승인 필요"만 반복, 창업자 승인해도 도구엔 반영 안 됨.
- **원인**: 이 환경의 MCP 승인 연결이 먹통 + 세션 스코프가 hankki뿐.
- **해결**: 클로드 직접 수정 포기 → 창업자가 PC github.dev로 직접(B2).
- **교훈**: 스코프 밖 레포는 클로드가 못 만짐. 창업자 직접 경로를 빨리 확정.

### B4. Play Console 스토어 이미지 "저장" 버튼이 없음
- **증상**: 곰곰이 아이콘·그래픽 올렸는데 저장 버튼이 화면 아래에도 위에도 없음. 나가려니 "저장 안 된 변경 삭제됨" 경고.
- **원인**: 스토어 등록정보엔 눈에 띄는 "저장"이 없고, **최종 저장=`게시 개요`에서 "검토를 위해 변경사항 제출"**.
- **해결**: 게시 개요 → "검토를 위해 변경사항 2개 제출" → 빠른검사(≤14분) 후 자동 제출.
- **교훈**: 콘솔에서 "저장 안 돼" 싶으면 별도 제출/게시 단계 의심. 경고창의 "나가기 및 삭제" 누르지 말 것.
- (상세: `play-console-스토어이미지-교체법.md`)

### B5. (이전) PWABuilder AAB 이름·버전코드 에러
- **증상**: "Name must be 3-50 / Launcher name 3-30"(한끼=2글자), "version code 1 already used".
- **해결**: 이름 임시로 "한끼 - 나만의 레시피 아카이브"/"한끼 레시피", version code 2로. 런처명 "한끼"는 **투명글자 트릭(AAB v3)** 로 별도 진행 예정(⬜ 남은 일).
- **교훈**: 런처명 3글자 미만 불가 → 투명글자로 3글자.
