### ④ 나가기 점검 — **홈 뒤로가기 → 「나가기」가 진짜로는 안 닫힌다**

창업자: *"홈에서 뒤로가기 누르면 지금은 팝업뜨자나. 나가기 누르면 앱에서는 안된다고 그냥 끄라고 해. 그거말하는거야"*

**증상 재현 = 코드에 그대로 있다.** `src/App.jsx` 종료 팝업:
```js
onConfirm={() => {
  setExitAsk(false)
  try { window.close() } catch {}                                   // ← 설치형 앱에선 막힌다
  showToast('나가려면 폰 홈 버튼을 눌러주세요 (앱은 스스로 못 닫아요)')  // ← 그래서 이 안내가 뜬다
}}
```

**원인 두 겹**
1. `window.close()` 는 **스크립트가 연 창만** 닫을 수 있다. 설치한 앱 창은 유저가 연 거라 브라우저가 막는다 → 아무 일도 안 일어남.
2. **TWA(Play에 올린 형태)는 「히스토리가 다 떨어진 상태에서 시스템 뒤로가기」를 눌러야 앱이 닫힌다.** 그런데 우리는 갑작스런 종료를 막으려고 `index.html:26` 트랩 + `App.jsx` `ensureGuard()`(탭할 때마다 칸 재보충)로 **히스토리를 일부러 안 떨어지게** 해뒀다 → 영원히 안 닫힘.

**⛔ JS로 앱을 닫는 방법은 없다.** 버튼을 고치는 게 아니라 **설계를 바꿔야 한다.**

**✅ v9.06 에서 고침 = 안드로이드 표준 「뒤로가기 두 번」**
- 홈에서 뒤로 1번 → 토스트 *"한 번 더 누르면 나가요"* + **우리가 심은 칸을 비우고** 2초간 가드를 안 심는다
- 2초 안에 뒤로 1번 더 → **히스토리가 떨어짐 → TWA가 액티비티를 종료 = 진짜로 닫힌다**
- 2초가 지나면 다음 터치에 가드가 되살아난다 → 실수로 나가는 것 방지
- 못 지킬 약속이던 **종료 팝업은 없앴다**

**⚠️ 고치면서 별개 버그를 하나 더 잡았다** — `탭 → 뒤로(홈)` 경로가 보호 칸을 안 깔아서
그 직후 뒤로가기가 **안내도 없이 앱을 꺼버렸다.** 테스트가 잡았고 같이 고쳤다.

**🧪 `scripts/test-exit.mjs` 신설 · `npm run smoke` 에 포함** (이 코드는 과거 재종료 버그가 났던 자리라 회귀 방어를 붙였다).
헤드리스 브라우저엔 '앱 종료'가 없어서 종료 자체는 못 재현한다 → **종료의 전제조건인 "첫 뒤로가기 뒤 우리 히스토리 칸 0"** 을 못 박았다.
👉 **실제 종료는 창업자 폰에서 확인 필요** (홈에서 뒤로 두 번).
