## 1️⃣ Context — 왜 바꾸나

📮 창업자 걱정(원문) = *"기기번호를 줄 경우 앞으로는 대부분 로그인으로 들어올텐데 그때마다 열쇠만 소모되고
**앱지웠다가 깔면 또 가져가고** 그렇게 되지 않을까;; 앞으로는 구글계정으로 밀고나가는게 맞는데.. 어째야하지
로그인하면 30개주고 안하면 기본 5개만 주고 써보라고 할까.."*

⛔ **「5개」는 접었다** — 지금 유저는 깔면 바로 30개를 받는다. 30 → 5는 **여섯 배 낙차**라
　 창업자 절대 규칙 **「한 번 준 것은 빼앗지 않는다」**에 정면으로 닿고,
　 5개면 AI 가 한두 번만 실패해도 **앱을 겪어보지도 못하고 나간다**(우리 AI 가 오늘에서야 제대로 돌기 시작했다).

✅ **확정 = 같은 목적을 「더 주는 말」로 이룬다**

| | 지금 | **새 판** |
|---|---:|---:|
| 그냥 깐 사람 | 30 | **10** |
| 로그인한 사람 | 30 | **30** (＝로그인하면 ＋20) |
| 매달 무료 | 5 | **5** ⛔안 건드린다(창업자가 정한 유일한 마진 레버 · 7/26) |
| 행동 열쇠 다섯 | — | **＋5** (평생 1회 · 로그인 무관) |

⭐ 유저가 보는 문장 = **「로그인하면 열쇠 20개를 더 드려요」** — 못 받는 게 아니라 **받는 말**이다.
⭐ 어뷰징 방어는 창업자 안과 **똑같다**(지웠다 깔아도 10개뿐). 오히려 **지금보다 통이 안전해진다.**

### ✅ 막고 있던 게 없다 — 확인했다
로그인을 조건으로 걸면 Play 신고를 다시 해야 하나 걱정했는데 **전부 끝나 있다**:
· Play 데이터 보안 재신고(이름·이메일·사용자 ID) = **2026-08-27 게시 완료**
· `privacy.html` · `delete-account.html` = **v11.58 로 나갔다** · 명의 이전 = **8/31 완료**
⚠️ **선결 조건 하나** = `src/nudges.js` 의 **`클라우드_전체공개 = false`** — 지금 로그인은 창업자에게만 보인다.
　 이게 켜지기 전엔 「로그인하면 30개」가 성립하지 않는다.

## 2️⃣ 🕳 구멍 열둘 — 하나씩 막는다

> ⭐ 이 절이 이 문서의 심장이다. **막는 법이 안 적힌 구멍은 「모른다」로 남긴다**(⛔짐작으로 덮지 않는다).

### 🕳1 ⭐⭐ 웰컴이 «1년마다 리필»되고 있다 — **이미 있던 구멍**
🔢 실측 = `worker.js:184` 은 `w:<uid>` 가 **없으면** 웰컴 만땅으로 본다. 그런데 `:248` 은 **차감할 때만** put 하고
　 TTL 이 **365일**이다 → 1년 뒤 만료 → 값이 없어짐 → **웰컴을 처음부터 새로 받는다.**
　 📌 `CLAUDE.md:583·587` 에 *"주석엔 «첫 1회만»인데 실제로는 1년마다 리필된다 — 코드가 이미 설계와 다르다"*
　 라고 **적혀 있었다.** 이번에 같이 닫는다.
✅ **막는 법 = 첫 요청에서 «무조건» 쓴다.** 차감을 하든 안 하든 그 키를 다시 써서 TTL 이 매번 밀린다.
　 → **1년 «내내 한 번도 안 쓴 사람»만 리셋**된다. 그건 손해가 아니다. ＋`privacy.html` 「최대 1년」 문구와도 맞는다.

### 🕳2 ⭐⭐⭐ 「남은 수」로 저장하면 10↔30 전환이 깨진다
지금 `w:<uid>` 에는 **남은 수**가 들어 있다. 비로그인으로 7개 쓰고(남은 3) 로그인하면
계정 통을 30으로 새로 만들게 되고 → **총 37개**를 얻는다. 로그아웃·로그인을 되풀이하면 **무한**이다.
✅ **막는 법 = 「쓴 수」로 저장한다.** `wu:<id>` = 웰컴에서 **쓴 개수**.
```
남은 = (로그인이면 30, 아니면 10) + 받은보너스 − 쓴수
```
⭐⭐ 그러면 **로그인하는 순간 남은 게 저절로 ＋20 된다.** 더할 코드가 없다 — 상한만 바뀐다.
⭐ 되돌리기도 저절로 맞는다(로그아웃하면 상한이 10으로 돌아가고, **쓴 수는 그대로**라 잃는 게 없다).

### 🕳3 이미 30개를 받아 쓰고 있는 사람 — ⛔한 개도 줄면 안 된다
`w:`(남은 수) → `wu:`(쓴 수) 로 갈아탈 때 **옛 값을 그대로 존중**한다.
```
wu = max(0, 30 − 옛w)      // 옛 판 웰컴이 20이던 사람도 이 식이면 남은 수가 «늘거나 같다»
```
⛔ **절대 줄지 않는다**는 것을 게이트가 확인한다(아래 검증 ②).

### 🕳4 로그인했다는 걸 서버가 어떻게 믿나 — ⚠️**이번 판에선 «안 믿는다»(정직하게 남긴다)**
앱이 구글 번호를 그냥 보내면 **아무 번호나 적어 보낼 수 있다** = 20개를 공짜로 얻는 길.
✅ 제대로 막는 법 = **Firebase ID 토큰을 보내고 워커가 RS256 으로 검증**(구글 공개키 6시간 캐시).
⛔ **이번 판엔 «안 넣는다».** 근거 넷 —
　 ⑴ **돈이 안 걸려 있다**(무료 열쇠다) ⑵ 어차피 **기기 번호를 갈면 10개씩 무한**이라 더 큰 구멍이 이미 열려 있다
　 ⑶ **전역 월 900 · 일 120 이 비용을 지킨다**(뚫려도 청구가 0원) ⑷ 창업자 복붙 부담을 줄인다
🚨 **⛔ 결제를 켜는 날엔 «반드시» 넣는다** — 그날은 돈이 걸린다. 이 줄을 그날 다시 읽는다.

### 🕳5 「일기 썼어」를 서버가 확인 못 한다
서버는 유저가 진짜 일기를 썼는지 알 길이 없다.
✅ **막는 법 = 상한으로 막는다** — 다섯 가지가 **각각 평생 1회**라 최대 **5개**다. 앱 토큰·오리진·IP 분당 제한은 이미 있다.
　 최악의 경우가 5개면 감당된다(전역 상한이 그 위를 또 막는다).

### 🕳6 오프라인이라 「받았다」가 서버에 안 닿았다
✅ **막는 법 = 앱에 «보낼 목록» 큐 ＋ 서버는 멱등(idempotent).**
　 못 보낸 행동을 폰에 쌓아 두고 다음에 앱을 열 때·OCR 을 부를 때 다시 보낸다.
　 이미 준 행동이면 서버는 **아무것도 더 주지 않고 지금 잔량만 돌려준다** → 몇 번을 보내도 안전하다.

### 🕳7 앱이 보여주는 숫자와 서버가 세는 숫자가 갈린다
지금은 `ocr.js:105` 의 `WELCOME_FREE = 30` 과 워커 `LIMITS` 를 **손으로 맞춘다.** 10/30 이 되면 어긋날 자리가 두 배다.
✅ **막는 법 = 서버가 상한을 «응답에 실어 보낸다»**(`left` 에 상한을 같이).
　 앱은 받은 값을 쓰고, **못 받았을 때만** 상수를 쓴다. ＋두 파일 값 대조를 게이트가 본다.

### 🕳8 한 번도 안 써 본 사람에게 뭘 보여주나
`getOcrLeft()` 는 서버 응답이 없으면 웰컴 상수를 보여준다 → **비로그인인데 30이 뜬다.**
✅ **막는 법 = 화면 표시만 `로그인해뒀나()`(`cloud.js:102`) 로 10/30 을 가른다.**
　 ⛔ 그 표식은 «진짜 로그인 상태»가 아니라 **표식**이다(주석에 그렇게 박혀 있다) —
　 **표시에만 쓰고 «차감 판정»엔 절대 안 쓴다.** 판정은 언제나 서버다.

### 🕳9 로그아웃하면 남은 게 갑자기 준다
30 기준 → 10 기준으로 돌아가므로 **숫자가 줄어 보인다.**
✅ **막는 법 = 잃는 게 «실제로는» 없게 설계했다**(🕳2 — 쓴 수는 그대로 남는다) ＋ **말로 미리 알린다**:
　 로그아웃 확인 창에 「로그아웃하면 **로그인 혜택 열쇠 20개가 다시 잠겨요**」.
⛔ 「로그인 한 번 하면 30 영구」로 만들지 않는다 — 그러면 로그인→로그아웃으로 **누구나 30을 얻는다.**

### 🕳10 같은 계정에 폰·패드 둘
각 기기가 비로그인으로 10씩 쓰고 로그인하면 어느 쪽 값을 쓰나.
✅ **막는 법 = 로그인할 때 「쓴 수」를 «큰 쪽»으로 맞춘다**(계정과 기기 중 큰 값).
　 기기를 갈아가며 안 쓴 척 못 한다. 보너스도 같은 방식.

### 🕳11 `privacy.html` 문구가 이미 낡았다
🔢 실측 `privacy.html:138` = *"무료 이용권(**첫 20회**)"* — **웰컴은 8/31에 30이 됐다.** 이미 틀린 글자다.
✅ **막는 법 = 이번 판에 같이 고친다** — 숫자를 빼고 **「무료 이용권이 남아 있는 동안」**으로.
　 ⭐ 숫자를 안 적으면 다음에 또 바뀌어도 안 낡는다(레시피열쇠 이름을 한 곳에서 읽게 한 것과 같은 생각).

### 🕳12 ❓ **서버가 진짜 30인지 아직 아무도 안 봤다**
앱은 30인데 **서버가 20이면 21장째에 막힌다** — `무료열쇠-확정-2026-08-31.md` 가 콕 집어 경고한 사고다.
✅ **막는 법 = 창업자가 OCR 워커의 운영자 통로를 열어 `웰컴` 칸을 확인한다.**

### 🕳13 🚨🚨 **저장소의 `worker.js` ≠ 지금 도는 서버** — 그대로 복붙하면 사고가 난다

## 3️⃣ 🔧 서버 설계 (`ocr-proxy/worker.js`)

### 열쇠 통 — KV 키 넷
| 키 | 뜻 | 만료 |
|---|---|---|
| `wu:<id>` | 웰컴에서 **쓴 개수** | 365일 (요청마다 밀린다 · 🕳1) |
| `bo:<id>` | **행동으로 받은 개수** 합 | 365일 (같이 밀린다) |
| `earn:<id>:<행동>` | 그 행동을 **이미 줬다**는 표식 | 없음(영구) |
| `u:<uid>:<ym>` | 그 달 쓴 개수 (⛔지금 그대로) | 40일 |

⭐ `<id>` = **로그인했으면 계정 번호 · 아니면 기기 번호** — 한 글자로 갈린다.
⭐ **통이 하나**라 화면 표시도 하나다(웰컴·보너스를 따로 안 센다).

### 상한
```
WELCOME_ANON: 10,   // 그냥 깐 사람      (창업자 확정 2026-09-01)
WELCOME_ACCT: 30,   // 로그인한 사람     (＝＋20)
PER_USER_MONTHLY: 5 // ⛔안 건드린다
EARN_ACTIONS: 자랑 · 레꾸 · 일기 · 요리 · 냉장고   // 각 1개 · 평생 1회
```

### 남은 개수 = 한 줄
```
상한 = (로그인 ? 30 : 10) + bo
남은 = max(0, 상한 − wu)          // 웰컴이 0이면 그때부터 월 5장
```

### 새로 여는 길 = 몸통에 `earn` 이 있으면 (⛔Vision 을 안 부른다)
```
받는 것 : { earn: 일기, uid, 계정번호(있으면) }
하는 일 : ① 아는 행동인가 ② 이미 준 표식이 있으면 → 아무것도 안 주고 잔량만 돌려준다(멱등 · 🕳6)
          ③ 없으면 bo +1 · 표식 남기기 ④ 준 것과 잔량을 돌려준다
```
⛔ 오리진·앱 토큰 검사는 **기존 길과 똑같이** 지난다. ⛔전역 카운터는 **안 올린다**(Vision 을 안 불렀으니까).

### 로그인 갈아타기 (🕳2·🕳10)
계정 번호가 실려 오면 — 계정 통이 없으면 만들고, 있으면 **기기 통과 «큰 쪽»으로 맞춘다.**
⛔ 기기 통을 **지우지 않는다** — 로그아웃하면 돌아갈 자리다.

### 옛 판에서 갈아타기 (🕳3)
새 키가 없고 옛 `w:<uid>`(남은 수)가 있으면 → `wu = max(0, 30 − 옛값)`. **절대 줄지 않는다.**
