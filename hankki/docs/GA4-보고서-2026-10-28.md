## 0. 이 보고서를 읽는 법 (먼저)
- **기간** = 30일 **2026-09-28 ~ 10-27** · 7일 **2026-10-21 ~ 10-27** (오늘 10/28 은 하루가 안 끝나서 뺐다). 날짜는 GA4 속성 시간대(한국 시간) 그대로다.
- **받은 길** = `node hankki/scripts/ga4.mjs` 와 같은 열쇠·같은 API(runReport)로 받았다. 속성 ID 553169378.
- **가림(thresholding)** = 받은 응답 28개 어디에도 「작은 숫자를 가렸다」 표시(`subjectToThresholding`)가 **없었다.** 그래서 1·2 같은 작은 숫자도 GA4 가 준 그대로다.
- **사람 수 ≠ 횟수.** 표마다 「사람」= 활성 사용자(activeUsers) · 「번」= 페이지 조회수(screenPageViews = 우리가 보내는 page_view 수)로 갈라 적었다.
- **사람 수는 더하면 안 된다.** 한 사람이 여러 날·여러 줄에 같이 세진다. 기간 합은 따로 받은 «기간 표» 숫자를 썼다.
- **로그인 수로 사람을 세지 않는다**(CLAUDE.md 절대원칙). 매일 볼 숫자 = **앱 홈을 연 사람(`home`)·앱을 처음 켠 사람(`first_open`)** · 새 가입 = `signup_*` 만.
- **빼는 계정(창업자·우리 것·심사관)** — GA4 엔 계정(메일)이 안 실린다. 그래서 «계정으로» 빼지는 못했다. 대신
  · 우리 기기(`hankki:founder` 표시가 있는 폰)는 앱이 통계를 **아예 안 보낸다**(`src/stats.js:129` `보낼까()`). ⚠️ 우리 기기 «전부»에 그 표시가 있는지는 이 보고서에서 확인 못 했다.
  · 심사로 보이는 **미국은 따로 줄**로 뺐다.
- **경로 넷** = `/hankki/app` 갤럭시 앱(＋아이폰 홈 화면에 깐 웹 2명 섞임 · 아래 1-3) · `/hankki/ios` 아이폰 앱 · `/hankki/` 웹 브라우저 · `/hankki/get.html` 「한끼 받기」 안내 페이지(인스타에서 오는 곳 · 로그인 화면 없음).
