# 🗄 사진 이사 설계 — `localStorage` → IndexedDB (2026-09-02 · ⭐여기가 현행이다)

> 📮 창업자 = *"데이터이사는 가능하긴한거야??"* → *"리서치 하고 다각도로 분석해서 데이터이사하는 것 설계 해줘. **촘촘하게** 해줘"*

## 1️⃣ 왜 지금인가 — 오늘 «실제로» 데이터를 잃었다

📮 창업자 = *"방금 하나 저장한거 **흔적도 없이 증발함**"* (2026-09-02 08:42 · 창업자 폰 실물)

🔢 그때 잰 값 = 한끼 데이터 **4.88MB** / 폰 한도 **약 5MB** → **꽉 찼다.**
　 · 글자(레시피 257편)는 다 합쳐도 **0.2MB** 밖에 안 된다
　 · 나머지 **4.7MB 가 「가져오기로 담은 캡처 사진」**이다
　 ⭐ 창업자는 *"사진 거의 안 넣었는데"* 라고 했고 **그 말이 맞다** —
　 　 레시피를 담았을 뿐인데 **앱이 그때마다 캡처를 같이 저장하고 있었다.**

✅ **오늘 v12.23 으로 급한 불은 껐다** (임시 방편)
| 무엇 | 값 |
|---|---|
| 캡처 저장 크기 | 1600px **202KB** → 900px **78KB** |
| 5MB 에 들어가는 장수 | 25장 → **65장** |
| 저장 실패했을 때 | 「저장했어요」를 **안 말한다** ＋ 화면에 빨간 띠 ＋ 매번 알림 |

⛔ **그런데 이건 «미루기»지 «없애기»가 아니다.** 65장이면 몇 달이면 또 찬다.
　 **한도 자체를 없애는 게 이사다.**

## 3️⃣ 실물 측정 — 「된다더라」가 아니라 재봤다

🛠 `scripts/_probe-idb-0902.mjs` (이 판을 돌리면 언제든 다시 잰다)

| 잰 것 | 값 | 뜻 |
|---|---|---|
| 사진 100장 **쓰기** | **129ms** | 이사 자체가 눈 깜짝할 새 |
| 사진 100장 **읽기** | **111ms** | ⭐**앱 켤 때 드는 값** — 사람이 못 느낀다 |

⭐⭐ **제일 중요한 실측 = 앱을 켤 때 111ms.** 「느려지지 않나」가 이 설계의 유일한 무서운 점이었는데 **숫자로 닫혔다.**

## 5️⃣ 갈래 셋 — 다각도로

| | Ⓐ **통째로 이사** | Ⓑ **사진만 · 메모리엔 그대로** ⭐추천 | Ⓒ **사진만 · 화면에서 그때그때** |
|---|---|---|---|
| 무엇 | `hankki:v1` 전부를 IndexedDB 로 | 글자는 localStorage 그대로, **사진만** IndexedDB. 앱을 켤 때 한 번에 읽어 메모리에 합친다 | 사진을 IndexedDB 에 두고 **화면이 필요할 때** 꺼낸다 |
| 고치는 파일 | `store.jsx` ＋ **앱 첫 화면 전체** | **`store.jsx` 하나** | `store.jsx` ＋ 화면 **8파일 35군데** |
| 앱 켤 때 | ⛔**첫 그림이 늦어진다**(읽기가 비동기라 「켜자마자 보이는」 구조가 깨진다) | ✅ 글자는 지금처럼 즉시 · 사진만 **111ms 뒤** 얹힌다 | ✅ 즉시 |
| 메모리 | 같음 | 사진 65장 ≈ **5MB**(문제 없음) | 제일 적다 |
| 위험 | **높다** — 켜는 길 자체를 바꾼다 | **낮다** — 한 파일, 되돌리기 쉽다 | 중간 — 손댈 데가 많아 «빠뜨림»이 난다 |
| 5MB 벽 | 없어짐 | **없어짐** | 없어짐 |

### ⭐ 추천 = **Ⓑ**, 근거 넷
1. **고치는 곳이 한 파일** — 오늘만 해도 내가 치환 하나를 놓쳐 앱을 죽였다. 손댈 데가 적을수록 안전하다.
2. **111ms 는 안 느껴진다** — Ⓒ 로 아낄 값이 사람 눈에 안 보인다.
3. **오늘 고침과 맞물린다** — 이제 **캡처는 표지로 안 쓴다.** 그래서 목록 화면엔 사진이 거의 안 뜨고,
   　사진이 진짜 필요한 곳은 **편집 화면 「보면서 쓰기」 하나**다. 늦게 얹혀도 티가 안 난다.
4. **화면 코드가 그대로** = `Thumb`·`상세`·`레꾸`·**백업 만들기**가 지금처럼 `recipe.image` 를 읽는다.
   　⭐ 특히 **백업이 저절로 살아난다** — 35군데를 고치는 갈래에선 백업이 조용히 사진을 빠뜨릴 수 있다.

## 6️⃣ 어떻게 — 다섯 단계 (안전장치 포함)

### 0단계 · 안전망 (⛔이거 먼저)
· 창업자 폰 **백업 파일**을 하나 더 받아 둔다(오늘 것 말고 «이사 직전» 것)
· 이사 코드는 **`hold/` 브랜치**에서 만든다 — 다 되기 전엔 배포 브랜치에 안 올린다(규칙 13)

### 1단계 · 사진 창고 만들기 (`src/photoStore.js` · 새 파일)
· `열기 / 넣기 / 꺼내기 / 지우기 / 전부꺼내기` 다섯 가지만
· ⛔ 라이브러리 안 쓴다 — 순수 IndexedDB 40줄이면 된다(위 판이 그걸로 쟀다)
· ⛔ **실패하면 «조용히» 넘어가지 않는다** — 오늘 사고의 뿌리가 그거였다

### 2단계 · 저장할 때 사진을 뺀다 (`store.jsx` 쓰기)
```
지금 : localStorage ← { recipes: [ {…, image: "data:…78KB"} ] }
바뀜 : IndexedDB   ← img:<레시피id> = 사진
       localStorage ← { recipes: [ {…, image: null, 사진있음: true} ] }
```
· ⭐ **메모리(state)는 안 건드린다** — 화면은 지금처럼 `recipe.image` 를 본다
· 사진이 바뀌거나 레시피가 지워지면 창고도 같이 정리

### 3단계 · 켤 때 도로 얹는다 (`store.jsx` 부팅)
· localStorage 를 지금처럼 **즉시** 읽어 화면을 그린다(글자 다 나온다)
· 그 «뒤에» 창고에서 사진을 꺼내 state 에 합친다(111ms)
· ⛔ 못 꺼내도 **앱은 멀쩡히 돈다** — `Thumb.jsx` 가 사진 없으면 아이콘으로 그린다(실측 확인)

### 4단계 · 이미 담긴 것 옮기기 (한 번만 · 규칙 18 ⓙ)
```
① localStorage 에서 사진 든 레시피를 찾는다
② 창고에 넣는다
③ 넣은 걸 «다시 꺼내» 원본과 같은지 확인한다   ← ⭐이게 안전장치
④ 같을 때만 localStorage 에서 사진을 뺀다
⑤ 하나라도 어긋나면 → 그 레시피는 그대로 둔다(안 잃는다)
```
· ⛔ **①~⑤를 한 레시피씩** 한다. 통째로 하다 중간에 죽으면 반쪽이 된다.
· 끝나면 「사진 N장을 옮겨 4.8MB 를 비웠어요」

### 5단계 · 되돌릴 길을 남긴다
· 이사 뒤 **7일간** localStorage 안 사진을 «안 지우고» 둘까? → ⛔**안 된다**(그러면 5MB 가 그대로다)
· ✅ 대신 **이사 직전 백업 파일**이 되돌릴 길이다(0단계). 그걸 확인하고 시작한다.

## 7️⃣ 위험과 막는 법 — 빠짐없이

| 위험 | 얼마나 | 막는 법 |
|---|---|---|
| 이사 중에 앱이 꺼진다 | 중간 | **한 장씩 · 확인하고 지운다**(4단계 ③④). 다음에 켜면 남은 것부터 이어서 |
| 창고에 못 넣는다(브라우저가 막음) | 낮음 | 못 넣으면 **localStorage 에 그대로 둔다** — 지금과 같아질 뿐 나빠지지 않는다 |
| 창고에서 못 꺼낸다 | 낮음 | 사진만 안 보인다. **글자는 멀쩡** · 아이콘으로 그려진다(실측) |
| 백업·복원이 사진을 빠뜨린다 | **높았다** | ⭐Ⓑ 라서 백업 코드가 그대로 memory 를 읽는다 → 저절로 해결. **게이트로 못 박는다** |
| 「사용기록 삭제」로 통째 날아감 | 지금과 같음 | 지금도 localStorage 가 날아간다. **더 나빠지지 않는다.** ＋`persist()` 는 이미 켜져 있다(창업자 폰 실측) |
| 클라우드 동기화와 충돌 | 없음 | `cloud.js` 는 **사진을 안 올린다**(`사진털기`) — 이사와 무관 |
| 두 탭에서 동시에 | 낮음 | 창고 쓰기는 트랜잭션이라 안전. 마지막 것이 이긴다(지금 localStorage 와 같은 규칙) |

| 칸 | 재는 것 |
