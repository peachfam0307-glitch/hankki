# 🍳 주간 레시피 — 어떻게 만들 것인가 (2026-08-01 설계)

창업자: *"주간레시피도. 이 기능은 **매주 올라가야 하는데 니가 나한테 물어보면 절대 안 되는 거야.**
**레시피는 우리 핵심 서비스**잖아."* · *"구체적으로 정해봐. **진짜진짜 중요한 거야.**"*

---

## 0️⃣ 이 문서가 지켜야 할 조건 세 개

| | 조건 | 어기면 |
|---|---|---|
| ① | **매주 올라간다** | 한 주만 빵꾸나도 «관리 안 하는 앱»이 된다 — **안 하느니 못하다** |
| ② | ⛔ **매주 물어보지 않는다** | 창업자가 매주 판단하면 **두 달 안에 무너진다**(규칙 8) |
| ③ | **레시피는 핵심 서비스다** | 대충 채우면 **앱의 정체성이 흔들린다** |

⭐ **①과 ②를 동시에 만족시키는 방법은 하나뿐이다 — 「미리 채워두고 날짜가 열게 한다」.**
   사람이 매주 개입하는 구조는 ①·② 중 하나를 반드시 깬다.

---

## 1️⃣ 뼈대 — 이미 있는 장치를 그대로 쓴다

우리는 **「날짜가 되면 저절로 열리는 문」**을 이미 세 군데서 쓰고 있다
(스티커 계절 그룹 `from` · 카드 시즌 `win` · 출시기념 팩).

```
src/data/weekly.js
  [{ from: '2026-09-04', kind: 'seasonal'|'recipe', ... }, …]
```
- 앱은 **오늘 날짜 이하 중 가장 최근 한 편**을 보여준다.
- **그날 아무도 아무것도 안 해도 열린다.** ← 조건 ①②를 구조가 보장한다.
- ⛔ **재고가 떨어지면 그 줄을 아예 안 그린다** — 빈 «이번 주 레시피» 자리를 남기지 않는다
  (`LAB_SURVEY_URL` 이 비면 그 칸을 안 그리는 것과 같은 방식 · 죽은 카드 방지).
- 🤖 **`scripts/release-calendar.mjs` 가 이미 읽는 형식으로 맞춘다** → `--brief` 로 «몇 주치 남았나»가 보인다.

## 2️⃣ ⚖️ 제일 중요한 제약 — 저작권 (⛔여기서 지어내지 말 것)

우리 문서 `docs/출시전-법무체크.md` §3 **원문**:
> **"우리가 앱에 기본 탑재하는 레시피·사진은 남의 것(캡처 등) 금지 —
> 직접 작성/촬영 or 출처 안전한 것만."**

⛔ 그러므로 **남의 레시피 글·사진을 그대로 가져오는 방식은 처음부터 불가능하다.**
⚠️ *"재료·순서는 사실이라 저작권이 약하다"* 는 말이 흔하지만 **우리 문서에 확인된 사실이 아니다** → 근거로 쓰지 않는다.

✅ **그래서 서치는 「무엇이 뜨는지」를 아는 데만 쓰고, 레시피 자체는 우리가 쓴다.**
✅ **사진 문제는 이미 풀려 있다** — 우리 앱은 **음식 아이콘 218종 + 꼬르곰·펭펭**으로
   사진 없이도 예쁜 표지가 나온다. *사진이 없어도 되는 앱을 우리가 이미 만들어 놨다.*

## 3️⃣ 무엇을 매주 올리나 — 후보 셋

| | 무엇 | 재고가 마르나 | 만드는 품 |
|---|---|---|---|
| (a) | **레시피 한 편** (재료·순서를 우리가 씀) | ⚠️ **마른다** — 매주 한 편은 사람이 써야 한다 | 크다 |
| (b) | 「이번 주 뭐 해먹지」 한 줄 | 안 마름 | 작다 — 근데 **레시피가 아니다**(조건 ③ 위반) |
| (c) | ⭐ **이번 주 제철 재료 1 + 그걸로 하는 요리 3** | ⭐ **안 마른다 — 제철은 달력이다** | 표 한 번 만들면 끝 |

### ⭐⭐ 확정안 = **(c)를 바닥에 깔고, (a)를 얹는다**

- **(c) 제철 = 마르지 않는 바닥.** `아이디어-로드맵.md` 에 이미 있는 발견 그대로:
  > *"제철은 **달력 기반 고정 데이터** → AI 없이 규칙만으로 가능(비용 0).
  >  월별 제철 재료표 한 번만 정리해두면 됨"*
  → **52주 표를 한 번 만들면 매년 저절로 돈다.** 조건 ①이 **영구히** 보장된다.
- **(a) 레시피 한 편은 「덮어쓰기」로.** 창업자가 여유될 때 한 편 쓰면 그 주의 (c)를 대신한다.
  안 쓰면 **(c)가 그대로 나간다 — 빵꾸가 안 난다.**

📌 **이 구조의 핵심 = 「좋은 게 있으면 좋은 게 나가고, 없으면 바닥이 나간다. 빈칸은 없다.」**

## 4️⃣ 창업자는 언제 무엇을 판단하나

| | |
|---|---|
| **횟수** | ⭐ **분기 1회 (1년에 4번)** — 12~13주치를 한 번에 |
| **보는 것** | 클로드가 만든 **후보 한 장** (주차 · 제철 재료 · 요리 3 · 한 줄) |
| **하는 것** | **✅/❌ 만.** 고치고 싶은 것만 말한다 |
| ⛔ 안 하는 것 | 매주 확인 · 매주 고르기 · 매주 승인 |

- 📅 **분기 검수일** = 8/31 (가을분) · 11/30 (겨울분) · 2/28 (봄분) · 5/31 (여름분)
  → **이미 있는 「자동 공개 전날 검수」 절대원칙과 같은 날에 붙인다.** 새 습관을 안 만든다.
- 🤖 클로드 = 후보 수집·표 만들기·날짜 붙이기·앱 반영 **전부**(규칙 8).

## 5️⃣ 어디에 보이나

- **홈 검색창 아래 한 줄** — 백업 유도 넛지·미정리 칩이 이미 쓰는 자리.
- 문구는 담백하게 — **「금요일엔 새 레시피가 올라와요」** 정도.
  ⛔ *"오늘의 미션"·"출석"* 금지 (`docs/리텐션-설계원칙-2026-07-30.md`).
- 누르면 **레시피 상세와 같은 화면** — 그대로 **「내 레시피로 담기」** 가 되어야 한다.
  ⭐ 그래야 «읽고 마는 콘텐츠»가 아니라 **우리 핵심 서비스(레시피 저장)로 들어온다.**

## 6️⃣ 언제 만드나

| | |
|---|---|
| **지금** | ⛔ 아직 만들지 않는다 — **52주 제철 표부터** (그게 없으면 ①이 안 지켜진다) |
| **다음** | 제철 표 → `weekly.js` → 홈 한 줄 → 분기 검수판 |
| ⚠️ **첫 공개 전 조건** | **최소 12주치가 채워져 있을 것.** 재고 없이 열면 «관리 안 하는 앱»이 된다 |

## 7️⃣ ⛔ 하지 말 것

- **매주 창업자에게 묻기** — 이 문서의 존재 이유다.
- **남의 레시피·사진 가져오기** — 법무체크 §3 위반.
- **빈 「이번 주 레시피」 자리 남기기** — 없으면 줄을 아예 안 그린다.
- **주기를 약속하는 문구를 앱에 박고 못 지키기** — 재고가 마르면 **문구부터 조용히 내린다.**
