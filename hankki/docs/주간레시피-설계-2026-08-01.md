# 🍳 주간 레시피 — 어떻게 만들 것인가 (2026-08-01 설계)

창업자: *"주간레시피도. 이 기능은 **매주 올라가야 하는데 니가 나한테 물어보면 절대 안 되는 거야.**
**레시피는 우리 핵심 서비스**잖아."* · *"구체적으로 정해봐. **진짜진짜 중요한 거야.**"*

---

## 0️⃣ 이 문서가 지켜야 할 조건 세 개

| | 조건 | 어기면 |
|---|---|---|
| ① | **매주 올라간다** | 한 주만 빵꾸나도 «관리 안 하는 앱»이 된다 — **안 하느니 못하다** |
| ② | ⛔ **매주 물어보지 않는다** | 창업자가 매주 판단하면 **두 달 안에 무너진다**(규칙 8) |
| ③ | **레시피는 핵심 서비스다** | 대충 채우면 **앱의 정체성이 흔들린다** |

⭐ **①과 ②를 동시에 만족시키는 방법은 하나뿐이다 — 「미리 채워두고 날짜가 열게 한다」.**
   사람이 매주 개입하는 구조는 ①·② 중 하나를 반드시 깬다.

## 1️⃣ 뼈대 — 이미 있는 장치를 그대로 쓴다

우리는 **「날짜가 되면 저절로 열리는 문」**을 이미 세 군데서 쓰고 있다
(스티커 계절 그룹 `from` · 카드 시즌 `win` · 출시기념 팩).

```
src/data/weekly.js
  [{ from: '2026-09-04', kind: 'seasonal'|'recipe', ... }, …]
```
- 앱은 **오늘 날짜 이하 중 가장 최근 한 편**을 보여준다.
- **그날 아무도 아무것도 안 해도 열린다.** ← 조건 ①②를 구조가 보장한다.
- ⛔ **재고가 떨어지면 그 줄을 아예 안 그린다** — 빈 «이번 주 레시피» 자리를 남기지 않는다
  (`LAB_SURVEY_URL` 이 비면 그 칸을 안 그리는 것과 같은 방식 · 죽은 카드 방지).
- 🤖 **`scripts/release-calendar.mjs` 가 이미 읽는 형식으로 맞춘다** → `--brief` 로 «몇 주치 남았나»가 보인다.

## 2️⃣ ⚖️ 제일 중요한 제약 — 저작권 (⛔여기서 지어내지 말 것)

우리 문서 `docs/출시전-법무체크.md` §3 **원문**:
> **"우리가 앱에 기본 탑재하는 레시피·사진은 남의 것(캡처 등) 금지 —
> 직접 작성/촬영 or 출처 안전한 것만."**

⛔ 이 문장이 막는 건 **「캡처 등」 = 남의 글·사진을 통째로 가져오는 것**이다.

### ✅✅ 2026-08-01 확인 완료 — **조리법을 배워 우리 말로 쓰는 것은 막지 않는다**
**문화체육관광부 정책브리핑 「저작권 들리ZIP」 10화** (전문 = `docs/레시피-저작권-확인-2026-08-01.md`):
> *"재료나 순서, 방법(레시피)을 습득한 후 **작성자만의 독자적인 표현으로 그 과정을 소개한다면
>  저작권 침해가 되지 않습니다.**"* · *"요리 방법 자체를 의미하는 '레시피'는 **아이디어로서
>  저작권법의 보호대상이 되지 않으며**… 저작권 침해가 되지 않습니다."*
> *"다만 …독창적으로 표현한다면 그 표현된 **'말이나 글, 사진, 영상' 등은 새로운 저작물**로 보호받을 수 있습니다."*

⚠️ **내가 이 문장을 「조리법도 못 쓴다」로 넓게 읽어 창업자를 붙잡았다.** 창업자가 세 번 눌러줘서 바로잡혔다.
📌 **현실(다들 베끼는데 아무 일 없다)과 내 설명이 안 맞으면 현실이 맞고 내 설명이 틀린 것이다.**

✅ **그래서 서치는 「무엇이 뜨는지」를 아는 데만 쓰고, 레시피 자체는 «우리가» 쓴다.**

### ⭐⭐ 「우리가 쓴다」 = **클로드가 쓴다.** 창업자가 쓰는 게 아니다 (창업자 2026-08-01 *"레시피를 내가 써야한다고??"*)
법무 문서의 *"직접 작성"* 은 **「한끼가 만든 글」**이라는 뜻이지 **「창업자 손으로 쓴 글」**이 아니다.
⛔ **매주 레시피를 쓰는 건 전형적인 반복 노동이다 — 규칙 8 위반.**

| | 누가 |
|---|---|
| 뭐가 뜨는지 서치 · 후보 고르기 · **재료·순서 쓰기** · 아이콘 붙이기 · 날짜 붙이기 · 앱 반영 | **클로드 전부** |
| **「이건 이렇게 하면 안 돼」 짚기** (분기 1회) | 창업자 |

⚠️ **정직하게 = 나는 요리를 해보고 맛볼 수 없다.** 안 되는 레시피는 없느니만 못하다.
   → **그래서 창업자 판정이 필요한 것**이고, 그건 **쓰는 일이 아니라 읽고 걸러내는 일**이다.
   ⭐ 창업자는 18년차 주부다 — *"이건 물 더 필요해"* 한 줄이면 된다.
✅ **사진 문제는 이미 풀려 있다** — 우리 앱은 **음식 아이콘 218종 + 꼬르곰·펭펭**으로
   사진 없이도 예쁜 표지가 나온다. *사진이 없어도 되는 앱을 우리가 이미 만들어 놨다.*

## 3️⃣ 무엇을 매주 올리나 — 후보 셋

| | 무엇 | 재고가 마르나 | 만드는 품 |
|---|---|---|---|
| (a) | **레시피 한 편** (재료·순서를 우리가 씀) | ⚠️ **마른다** — 매주 한 편은 사람이 써야 한다 | 크다 |
| (b) | 「이번 주 뭐 해먹지」 한 줄 | 안 마름 | 작다 — 근데 **레시피가 아니다**(조건 ③ 위반) |
| (c) | ⭐ **이번 주 제철 재료 1 + 그걸로 하는 요리 3** | ⭐ **안 마른다 — 제철은 달력이다** | 표 한 번 만들면 끝 |

### ⭐⭐ 확정안 = **(c)를 바닥에 깔고, (a)를 얹는다**

- **(c) 제철 = 마르지 않는 바닥.** `아이디어-로드맵.md` 에 이미 있는 발견 그대로:
  > *"제철은 **달력 기반 고정 데이터** → AI 없이 규칙만으로 가능(비용 0).
  >  월별 제철 재료표 한 번만 정리해두면 됨"*
  → **52주 표를 한 번 만들면 매년 저절로 돈다.** 조건 ①이 **영구히** 보장된다.
- **(a) 레시피 한 편은 「덮어쓰기」로.** **클로드가 써 두면** 그 주의 (c)를 대신한다.
  못 채운 주는 **(c)가 그대로 나간다 — 빵꾸가 안 난다.**
  ⭐ 그리고 **(c)는 레시피 「이름」만 나열하는 것**이라 애초에 쓸 글이 없다 — 바닥은 손이 아예 안 간다.

📌 **이 구조의 핵심 = 「좋은 게 있으면 좋은 게 나가고, 없으면 바닥이 나간다. 빈칸은 없다.」**

## 3.5️⃣ ⭐⭐ 만드는 순서 — 창업자가 직접 정한 흐름 (2026-08-01)

> *"그거 내보내기 전에 나한테 보여줘. **내가 쓰는 재료로 바꿔줄게.** 설탕양이나 간장양 줄여도 되잖아."*
> *"내가 쓰는 재료들로 바꾸면 되잖아. 참치액, 국간장 → 초피액젓 등등"*

| | 누가 | 무엇 |
|---|---|---|
| ① | **클로드** | 뭐가 뜨는지 찾고 → **조리법을 우리 말로 새로 쓴다**(초안) |
| ② | **창업자** | ⭐ **「내 재료로」 바꾸고 양을 조절한다** — 국간장·참치액 → **초피액젓**, 미원·연두 → **백간장**, 설탕·간장 **양 줄이기** |
| ③ | **클로드** | 아이콘·날짜 붙이고 앱에 넣는다 |
| ⛔ | | **②를 건너뛰고 내보내지 않는다** |

### ⭐⭐ 「내 재료로」 = 두 층이다 — 섞으면 안 된다 (창업자 2026-08-01)

> *"다른건 거의 **브랜드**인데. **초피랑 백간장, 연두 같은거만 추가해도 다른레시피가 돼.**"*

⛔ **내가 여기서 틀렸다** — 처음엔 *"설탕 → 아우노슈가"* 라고 적었는데 **그건 브랜드 갈아끼우기라
   레시피가 하나도 안 달라진다.** 창업자가 바로 잡아줬다.

| | 어디에 쓰나 | 실제 글자 (지금 `basics.js`) | 레시피가 달라지나 |
|---|---|---|---|
| **층① 재료** | **재료 줄** | `초피액젓 2큰술 (없으면 일반 국간장)`<br>`백간장 약간 (없으면 미원·연두 조금 · 감칠맛용)` | ⭐ **달라진다** — 맛이 바뀐다 |
| **층② 브랜드** | **메모 꼬리줄** | `제가 쓰는 양념 — 간장 「성가정 우리콩 진간장」 · 설탕 「아우노슈가」` | ❌ 안 달라진다 — 같은 설탕 |

⭐⭐ **이 구조가 이미 우리 레시피에 들어가 있었다.** 새로 만들 게 아니라 **지키면 되는 것**이다.
- **층①은 「없으면 ○○」를 꼭 같이 쓴다** — 안 사도 만들 수 있어야 한다. 안 그러면 **레시피가 아니라 광고**가 된다.
- **층②는 재료 줄에 넣지 않는다** — 재료 줄에 상표가 박히면 그 순간 레시피가 전단지로 읽힌다.

⚠️ **지금 어긋난 곳 = 재료 줄에 「아우노」 12곳 · 「맥된장」·「백합된장」** — 브랜드인데 층①에 들어가 있다.
   → 재료 줄은 `설탕`·`된장`으로 되돌리고 브랜드는 꼬리줄로 내린다. (⏳앱 코드라 창업자 신호 뒤에)

### ⭐⭐⭐ 왜 이 단계가 이 기능의 핵심인가 (셋 다다)

1. **⚖️ 저작권** — 재료와 양이 바뀌면 「보고 알아낸 뒤 우리 표현으로 쓴 것」이 **더 확실해진다.**
2. **💰 돈** — 우리 양념이 레시피에 박히면 **주부의 장바구니로 자동 연결된다.**
   ⭐ 이건 **이미 만들어져 있다** — 기본 레시피 38개에 우리 양념이 **122곳**(`초피액젓` 27 · `아우노` 39 ·
   `성가정` 17 · `백간장` 12 · `요리맛샘` 10 · `복이네` 9 · `올바른가` 4 · `백합` 4).
   ⚠️ **단 연결은 반쪽이다 — §3.6 참조.**
3. **⭐ 우리다움 — 이게 제일 크다.**
   조리법은 저작권이 없어서 **누구나 베낄 수 있다.** 그런데
   **「이 사람이 실제로 쓰는 양념과 양」은 아무도 못 베낀다** — 그건 남의 살림이니까.
   📌 **우리가 파는 건 레시피가 아니라 「18년차 주부의 손」이다.**

⚠️ **그리고 이 단계가 내가 못 하는 걸 메운다** — 나는 **요리를 해보고 맛볼 수 없다.**
   *"설탕 줄여도 돼"* 는 **해본 사람만 할 수 있는 말**이다.

## 3.6️⃣ ⚠️⚠️ 큐레이션이 계속 늘어난다 — 지금 연결 방식은 못 버틴다

> 창업자 2026-08-01: *"앞으로 큐레이션 계속 올릴거니까."*

### 🔎 실측 — 지금 이미 반쪽이다

```
큐레이션 제품 37개 중
  ✅ 레시피에 연결된 것   12
  ⛔ 어느 레시피에도 안 붙은 것   25   ← 3분의 2
```

⭐ **원인 = 매칭이 「제품 풀네임 글자 그대로」다.**

```js
// src/data/curation.js
export const picksForIngredients = (ingredients = []) => {
  const text = (ingredients || []).join('  ')
  return PRODUCTS.filter((p) => p.name && text.includes(p.name))   // ← 풀네임이 있어야만 붙는다
}
```

- 레시피에 `순두부 1팩` 이라 써도 → 「**한살림 몽글이** 순두부」는 **안 붙는다**
- `어묵 200g` → 「**명태살 가득 참** 어묵」 **안 붙는다** · `카레가루` → 「**채담**카레」 **안 붙는다**
- 그래서 메모 꼬리줄에 **풀네임을 손으로 박아** 억지로 붙여 왔다(29개 레시피에 꼬리줄이 있다).

### ⛔ 큐레이션을 올릴수록 «더» 나빠진다

| | |
|---|---|
| 새 제품을 올리면 | **옛 레시피 38개 어디에도 안 붙는다** (꼬리줄에 이름이 없으니까) |
| 붙이려면 | **레시피를 하나씩 열어 꼬리줄을 고쳐야 한다** = 제품 하나 올릴 때마다 노가다 → **규칙 8 위반** |
| 매주 레시피를 쓸 때 | 클로드가 **제품 100개 이름을 다 외우고** 꼬리줄을 써야 한다 |
| 제품명이 바뀌면 | **연결이 조용히 끊긴다** — 아무도 모른다 |

### ✅ 해법 = 사전을 «큐레이션 쪽»에 둔다 (제품 한 줄, 레시피는 안 건드림)

```js
{ name: '한살림 몽글이 순두부', matches: ['순두부'], … }
{ name: '명태살 가득 참 어묵',  matches: ['어묵'], … }
{ name: '와촌식품 초피액젓',    matches: ['초피액젓'], … }
```
`picksForIngredients` 가 `name` **또는** `matches` 로 찾게 한 줄 고친다.

| 좋아지는 것 | |
|---|---|
| ⭐ **새 제품 = 한 줄** | `matches` 만 적으면 **기존 레시피 전부에 저절로 붙는다.** 레시피를 안 연다 |
| ⭐ **매주 레시피가 가벼워진다** | 꼬리줄을 손으로 쓸 일이 없다 — **재료 줄만 제대로 쓰면 연결은 자동** |
| ⭐ **지금 끊긴 25개가 바로 붙는다** | 순두부·어묵·카레·훈제오리·국수… 이미 레시피에 있는 재료들이다 |

⚠️ **주의 = 너무 넓게 잡으면 엉뚱한 게 붙는다** — `['간장']` 으로 두면 **간장 들어간 레시피 전부**에
   진간장·맛간장·백간장이 다 뜬다. **재료 줄에 실제로 쓰는 말**로 좁게(`초피액젓`·`순두부`·`대패목심`).
📌 **이건 앱 코드 변경이다** → ⛔규칙 13. 창업자 신호 전엔 배포 브랜치에 커밋도 안 한다.

## 3.7️⃣ ⭐⭐ 창업자의 «안 푼» 레시피 — 이게 제일 큰 자산이다

> 창업자 2026-08-01: *"그리고 **진짜 내 레시피도 좀 있어. 아직 안푼거.**"*

| | 클로드가 쓴 초안 | ⭐ 창업자의 진짜 레시피 |
|---|---|---|
| ⚖️ 저작권 | 우리 말로 새로 써서 **안전** | **원래부터 우리 것** — 걱정 자체가 없다 |
| ⭐ 우리다움 | ②단계(내 재료로)로 만들어 넣는다 | **처음부터 100%** |
| 🍳 검증 | ⚠️ 나는 **해보고 맛볼 수 없다** | **이미 해먹어 본 것** |
| 📦 재고 | 무한 | 한정 — **아껴 써야 한다** |

⭐ **그래서 이건 「바닥」이 아니라 「간판」이다.** 매주 나가는 자리에 흘려보내면 아깝다.

**쓰는 법 (제안 · ⏳창업자 확정)**
1. **먼저 다 받아 재고로 쌓는다** — 몇 개인지부터 알아야 배치를 정한다.
   (창업자는 **말하거나 사진만** 주면 된다. **글로 옮기고 재료·순서로 다듬는 건 클로드** — 규칙 8)
2. **분기마다 한두 편씩 「이번 주는 진짜 우리 레시피」** 로 낸다 — 흔한 주와 확실히 구분되게.
3. 배치는 **제철과 맞춰서** — 재료가 나는 주에 넣으면 값어치가 두 배다.
4. ⛔ **한 번에 다 풀지 않는다.** 이건 **다시 안 생기는 재고**다.

📌 `basics.js` 에 이미 **`파운더의 실사용 레시피 ✨`** · **`파운더의 개발 레시피 ✨`** 표시가 있다
   (공심채 볶음·대구뭉티기). **이 표시를 그대로 쓴다** — 새 문법을 만들지 않는다.

## 4️⃣ 창업자는 언제 무엇을 판단하나

> ✅ **창업자가 직접 확인한 역할 분담 (2026-08-01)**
> *"**내가 검수할게. 네가 레시피 가져와서 우리 문체로 작성하면.**"*
> → **쓰는 사람 = 클로드 · 검수하는 사람 = 창업자.** 이 줄로 확정.

| | |
|---|---|
| **횟수** | ⭐ **분기 1회 (1년에 4번)** — 12~13주치를 한 번에 |
| **보는 것** | 클로드가 만든 **후보 한 장** (주차 · 제철 재료 · 요리 3 · 한 줄) |
| **하는 것** | ⭐**「내 재료로」 바꾸고 양 조절** ＋ *"이건 물 더 필요해"* 한 줄. ⛔**글을 쓰는 일은 없다** |
| ⛔ 안 하는 것 | 매주 확인 · 매주 고르기 · 매주 승인 |

- 📅 **분기 검수일** = 8/31 (가을분) · 11/30 (겨울분) · 2/28 (봄분) · 5/31 (여름분)
  → **이미 있는 「자동 공개 전날 검수」 절대원칙과 같은 날에 붙인다.** 새 습관을 안 만든다.
- 🤖 클로드 = 후보 수집·표 만들기·날짜 붙이기·앱 반영 **전부**(규칙 8).

## 5️⃣ 어디에 보이나

- **홈 검색창 아래 한 줄** — 백업 유도 넛지·미정리 칩이 이미 쓰는 자리.
- 문구는 담백하게 — **「금요일엔 새 레시피가 올라와요」** 정도.
  ⛔ *"오늘의 미션"·"출석"* 금지 (`docs/리텐션-설계원칙-2026-07-30.md`).
- 누르면 **레시피 상세와 같은 화면** — 그대로 **「내 레시피로 담기」** 가 되어야 한다.
  ⭐ 그래야 «읽고 마는 콘텐츠»가 아니라 **우리 핵심 서비스(레시피 저장)로 들어온다.**

## 6️⃣ 언제 만드나

| | |
|---|---|
| **지금** | ⛔ 아직 만들지 않는다 — **52주 제철 표부터** (그게 없으면 ①이 안 지켜진다) |
| **다음** | 제철 표 → `weekly.js` → 홈 한 줄 → 분기 검수판 |
| ⚠️ **첫 공개 전 조건** | **최소 12주치가 채워져 있을 것.** 재고 없이 열면 «관리 안 하는 앱»이 된다 |

### 📋 할 일 순서 (2026-08-01 확정)

| | 무엇 | 누가 | 왜 이 순서인가 |
|---|---|---|---|
| **①** | **52주 제철 표** | 클로드 | ⭐**바닥.** 이게 없으면 「매주 올라간다」가 안 지켜진다 |
| **②** | **큐레이션 `matches` 연결** (§3.6) | 클로드 | 지금 **25개가 끊겨 있다.** 표를 만들기 전에 고쳐야 제철 재료가 바로 장바구니로 이어진다 |
| **③** | **창업자 미공개 레시피 받기** (§3.7) | 창업자 말 → 클로드가 글로 | 몇 개인지 알아야 **어느 주에 배치할지**가 정해진다 |
| **④** | `weekly.js` · 홈 한 줄 · 분기 검수판 | 클로드 | 위 셋이 재료다 |

⛔ **②③은 앱 코드·데이터라 창업자 신호 전엔 배포 브랜치에 커밋도 안 한다**(규칙 13 · `hold/검수대기`).

## 7️⃣ ⛔ 하지 말 것

- **매주 창업자에게 묻기** — 이 문서의 존재 이유다.
- **창업자에게 레시피를 쓰게 하기** — 반복 노동은 클로드 몫이다(규칙 8). 창업자는 **판정만.**
- **남의 레시피·사진 가져오기** — 법무체크 §3 위반.
- **빈 「이번 주 레시피」 자리 남기기** — 없으면 줄을 아예 안 그린다.
- **주기를 약속하는 문구를 앱에 박고 못 지키기** — 재고가 마르면 **문구부터 조용히 내린다.**
