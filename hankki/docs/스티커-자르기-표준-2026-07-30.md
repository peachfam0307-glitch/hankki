# ✂️ 스티커 자르기 표준 — 왜 지저분했고, 어떻게 한 번에 깔끔하게 자르나

> 창업자 2026-07-30: *"우리 이거 구조적으로 잡자. 반복적으로 프레임 고친거 원인 찾고 거기에 맞는 코드
> 만들어서 이제 한번에 가자. 그리고 제대로 검수하는 시스템도 만들어"* ·
> *"자를때 어떻게 하면 계단식으로 지저분하게 안잘리고 깔끔하게 잘리는지 그걸 어떻게 검수하면 찾아내는지"*

**하루에 프레임을 네 번 고쳤다.** 매번 다른 증상이었고 매번 다른 도구로 땜질했다.
그래서 원인을 끝까지 파고 **도구 하나 + 게이트 하나**로 정리했다.

---

## 1️⃣ 왜 지저분했나 — 원인은 하나였다

하루 동안 나온 증상은 넷인데, **뿌리는 같다.**

| 증상 | 언제 보였나 |
|---|---|
| ① **잘림** | 요트 프레임 왼쪽 선이 싹둑 |
| ② **잡조각** | 레몬 프레임에 옆 컷 돛이 붙어 옴 · 하트곰 옆 반쪽 하트 |
| ③ **계단** | 프레임을 크게 키우면 곡선이 픽셀 계단 |
| ④ **흰 테** | 보라 배경에 얹으니 테두리에 흰 선 |

### 🔍 뿌리 — 옛 도구는 알파를 **판정**했다

```python
배경 후보 = (채도 낮음) & (밝기 >= 234)     # ← 둘 중 하나로 자름
```

**중간이 없다.** 그런데 흰 배경에 그린 그림의 가장자리는 **원래 흰색과 반쯤 섞여** 있다.
그 반투명한 픽셀을 "배경(투명) 아니면 그림(불투명)" 으로 강제로 나누니 두 가지가 동시에 터진다.

- 반쯤 흰 픽셀이 **배경으로 판정** → 잘려 나감 → **계단**
- 반쯤 흰 픽셀이 **그림으로 판정** → 흰 기운을 띤 채 불투명으로 굳음 → **흰 테**

그리고 ③④를 **나중에 흐려서 부드럽게** 만들려 하면, 그 흰 기운이 바깥으로 번져
**흰 테가 오히려 더 넓어진다.** (실제로 그렇게 만들었다가 창업자가 잡았다)

①②는 별개 원인 — **격자(그리드)로 잘랐기 때문.** 칼이 선 위를 지나가면
본체가 잘리거나(①) 옆 그림이 딸려 온다(②).

## 2️⃣ 어떻게 자르나 — 표준 5단계

> 도구 = **`python3 tools/cut.py <시트> <폴더> <접두어> [--frame]`**
> ⛔ 다른 컷 도구는 이제 쓰지 않는다(과거 기록용으로만 남김).

### ① 덩어리(blob)로 자른다 — 격자 금지
그림이 **서로 안 닿게** 그려져 있으면, 이어진 덩어리를 찾아 그 덩어리만 잘라낸다.
칼이 선 위를 지나갈 일이 없으니 **잘림·잡조각이 원천적으로 안 생긴다.**

### ② 알파를 판정하지 말고 **계산**한다 ⭐ 핵심
흰 배경에 그린 그림은 이렇게 섞여 있다:
```
보이는색 = 원래색 × α + 255 × (1 − α)
```
그러니 거꾸로 풀면 α가 나온다:
```
α = (255 − 보이는색) ÷ (255 − 원래색)
```
'원래색'은 **속살**(안쪽으로 몇 px 들어간 진짜 그림 색)에서 가져온다.
→ 반투명 가장자리가 **원본 그대로** 살아난다. **계단도 흰 테도 안 생긴다.**

### ③ 흰색 되돌리기는 **바깥 테두리 띠에서만**
⚠️ 이걸 그림 전체에 하면 **돛·갈매기 배·밀짚모자의 흰 부분이 통째로 비친다.**
이 식은 "흰색에 가까우면 배경"으로 보는데 **흰 그림도 흰색**이기 때문이다.
→ **안쪽은 그냥 불투명. 색도 원래 색 그대로.** 테두리 7px 띠에서만 손댄다.

### ④ 프레임이면 **가운데에서** 창을 뚫는다
한가운데에 씨앗을 두고 **흰색만 번지게** 한다. 프레임 선이 벽이 되어 막아준다.
⚠️ 바깥에서 번지게 하면 선의 틈으로 새어 **그림까지 지운다.**
안전장치: 창이 6~92% 범위 밖이거나 테두리에 닿으면 **안 뚫는다**(샌 것).

### ⑤ 여백 12px
가장자리에 딱 붙으면 잘린 것처럼 보이고 게이트에도 걸린다.

## 3️⃣ 어떻게 검수하나 — 사람 눈을 안 믿는다

### 🚧 게이트 — `npm run smoke` 에 물려 있다. 걸리면 **배포가 막힌다.**
```
node scripts/check-cutouts.mjs
```
| 보는 것 | 어떻게 판단하나 |
|---|---|
| **잘림** | 그림이 이미지 테두리에 닿았나 (짧은 변의 2% 이상) |
| **잡조각** | 본체와 떨어진 작은 덩어리가 **테두리에 닿았나** |
| **계단** | 반투명 픽셀이 거의 없나 (알파가 0/255뿐) |

⚠️ **'가늘면 조각'은 일부러 뺐다.** 점선 프레임의 점·물방울이 40개씩 걸려서
게이트가 시끄러워졌다. **시끄러운 게이트는 아무도 안 본다.**

⚠️ **예외는 `scripts/cutout-allow.json` 에 이유와 함께.** 이유 없이 넣으면 게이트가 무의미해진다.

### 🔎 손으로 훑을 때 (게이트보다 넓게 보는 도구)
| 도구 | 언제 |
|---|---|
| `tools/find-fragments.py` | 잡조각 후보를 넓게(가는 것 포함) 훑어보기 |
| `tools/clean-cutouts.py --fix` | 잡조각 + **다이컷 흰 테두리 안 색 번짐** 지우기 |
| `tools/dewhite-edges.py --fix` | 이미 잘린 파일의 **흰 테** 걷어내기 |
| `tools/soften-edges.py` | 이미 잘린 파일의 **계단** 없애기 |
| `npm run assets` | 자산 현황 + 정원 대조 + 깨진 참조 |

### ✅ 게이트가 진짜 막는지 확인했다
일부러 잡조각을 심어 넣고 돌렸더니 **종료코드 1**로 배포를 막았다.
(검사를 만들면 **그 검사가 실제로 잡는지**까지 확인한다 — 전부 0이라고 나오면
검사가 도는 건지 알 수 없다)

## 4️⃣ 창업자가 시트 뽑을 때 (이거 세 줄만)

```
배경은 완전한 흰색(#FFFFFF).
스티커끼리 서로 닿지 않게 띄워서.
크게. (프레임처럼 크게 쓰는 건 한 장에 4컷 정도)
```

⛔ **`transparent background` 라고 쓰지 말 것** — AI가 회색 격자를 진짜로 그려 넣는다(v9.00 사고).
⛔ 격자·행·열·개수 지정하지 말 것 — 그걸 맞추느라 **그림 퀄이 떨어진다.**

**서로 안 닿게만 그려주면 나머지는 도구가 다 한다.** 덩어리로 찾아 자르니까 배치는 자유다.

## 4️⃣-b ⛔⛔ **원본이 "투명"으로 오면 이 사고가 난다** (2026-07-30 여름 프레임)

> 창업자 제보: *"검은선이 지저분하게 지워졌어. 이 프레임 쓰지말까?"* (스크린샷)

**증상.** 프레임 바깥 윤곽을 따라 **검은 점선**이 붙어 있다. 선을 지우다 만 것처럼 보인다.

**원인 — 우리 잘못도, 그림 잘못도 아니었다.**
원본 시트 이름이 `여름프레임-16종-투명.png` 인데, 열어 보니
**AI가 "투명 배경"을 회색 체커 격자로 진짜 그려 넣었다.** (원본은 RGB, 알파가 아예 없다)
그 격자가 **246 / 253 두 톤**이라, 옛 도구의 배경 문턱(246)이 **253쪽만 배경으로 보고 246쪽은 그림으로 남겼다.**
→ 프레임 테두리를 따라 **회색 격자 조각이 점점이** 붙었고, 파스텔 선 위에서 검은 점선처럼 보였다.

**고친 법 (둘 다 씀).**
1. **격자를 흰색으로 눕히고 다시 자르기** — `(채널차 ≤ 2) & (밝기 ≥ 240)` 을 255로 바꾼 뒤 `tools/cut.py`.
   → `pf_sm07·08·10` 깨끗해짐.
   ⚠️ 처음에 채널차를 ≤8 로 잡았다가 **크림색 선까지 격자로 오인**해 지웠다. **격자는 완전 무채색(≤2)이다.**
   ⚠️ 다시 자르면 원본 해상도(≈280px)라 **표시 크기(626px)에 못 미쳐 해상도 게이트에 걸린다** →
      예전 파일과 **같은 긴변으로 키워** 넣는다(예전 것도 같은 원본을 키운 것이라 화질 손해가 없다).
2. **수술식 — 다시 안 자르고 격자 조각만 지우기** (`pf_sm05·11·12`)
   조건 = ①완전 무채색 ②밝기 232~252 ③덩어리 ≤90px ④테두리 9px 안쪽에 절반 이상 걸침
   ⚠️ **이쪽을 먼저 시도해야 한다.** 다시 자르면 `--frame` 의 가운데 창 뚫기가
      **조개 프레임의 진주를 먹어 버렸다**(알맹이가 창 안에 있으면 같이 사라진다).

📌 **교훈 — 시트를 받을 때:**
   ⛔ **`transparent background` 라고 쓰지 말 것.** 이미 `docs/스티커-자르기-표준` 4️⃣에 있는 규칙인데
      이 시트가 그 전에 뽑힌 것이었다. **파일 이름에 "투명"이 있으면 열어서 알파가 진짜 있는지 먼저 본다.**
   ⛔ 알파가 없는데 이름만 투명이면 = **격자가 그려진 것**이다. 자르기 전에 격자부터 눕힌다.

## 5️⃣ 오늘 실제로 잡은 사고 (같은 실수 반복 방지)

| 사고 | 원인 | 교훈 |
|---|---|---|
| 프레임 계단 | 알파를 이진 판정 | **판정하지 말고 계산하라** |
| 흰 테 | 흰 기운 띤 픽셀을 불투명으로 굳히고 바깥으로 번지게 함 | **흐려서 고치려 하지 마라** |
| 돛·갈매기 비침 | 흰색 되돌리기를 그림 전체에 적용 | **흰 그림도 흰색이다** |
| 색 뭉개짐 | 색까지 속살 색으로 덮음 | **안쪽은 원래 색 그대로** |
| 곰 몸통 흰색 됨 | 테두리 띠를 22px로 넓게 잡고 조건 없이 지움 | **좁게, 조건 달고** |
| 장식까지 지울 뻔 | "떨어져 있으면 잡조각" | **반짝이·하트는 통통하다. 조각은 가늘다** |
| 리컬러 세트 깨질 뻔 | "모양이 겹친다"고 뺌 | **빼기 전에 어떤 기능에 묶였는지 본다** |
| 프레임에 검은 점선 | 원본에 **가짜 투명 격자**가 그려져 있었고, 그 두 톤 중 하나가 문턱을 통과 | **이름만 "투명"인 시트는 열어서 알파를 확인** |
| 조개 진주 사라짐 | 다시 자르면서 `--frame` 창 뚫기가 알맹이를 먹음 | **먼저 수술(조각만 제거), 다시 자르기는 그다음** |

📌 **한 줄로**: **증상을 내 가설로 바꿔 읽지 말고, 먼저 픽셀을 재고, 그다음 고친다.**

## 4️⃣-c 가짜 투명 격자 — **전수검사 (2026-07-31)**

⚠️ 7/30에 여름 프레임 **6컷만** 고치고 끝낸 줄 알았는데, 창업자가 폰에서 다시 잡아냈다:
> *"내가 다 찍진 못했는데 **어두운색 테두리 있는 애들이 거의 이래.** 네가 레꾸템들 전수검사해야할듯."*

**맞았다.** 등록된 **853컷 전수 스캔** 결과 같은 찌꺼기가 앱 전체에 퍼져 있었다.

### 찾는 법 (숫자로 후보 좁히기)
```
바깥 테두리 띠(5px)에서   어둡고(max<130) 무채색(max-min≤24)  픽셀 비율
  ─ 속살에서의 같은 비율보다 2.5배 이상 높으면 = 의심
```
→ 853컷 중 **71컷**이 걸렸다.

### ⚠️ 마지막 판정은 반드시 눈으로
**숫자로는 「우리 진갈색 마감」과 「격자 찌꺼기」를 못 가른다. 둘 다 어둡다.**
실제로 71컷 안에 **꼬르곰·펭펭(흰 다이컷 테두리)** 과 **뚝배기 음식(검은 뚝배기가 그림)** 이 잔뜩 섞여 있었다.
→ 컨택트시트를 **진한 판(`#22263A`)** 에 깔고 보면 1분이면 갈린다.

### 처방은 모양에 따라 다르다 — ⭐**증상이 같아도 처방이 다르다**

| 대상 | 방법 |
|---|---|
| **마테**(길쭉한 띠) | 열마다 위·아래 7px 띠의 **RGB만 속살 색으로** 덮는다. 알파(찢긴 톱니 모양)는 **그대로 둔다** → 찢긴 결은 살고 검은 자국만 사라진다 |
| **메모·라벨·프레임**(임의 모양) | 바깥 5px 띠 안의 찌꺼기 픽셀만 골라 ⒜색은 `distance_transform_edt` 로 **가장 가까운 성한 픽셀** 색을 가져오고 ⒝**알파는 0**. 마지막에 알파만 `gaussian_filter(0.7)` 로 부드럽게(안 하면 톱니 모양대로 갉아먹은 자국이 남는다) |
| **해상도까지 모자란 것** | ⛔**수술로 못 고친다.** 없는 정보는 안 살아난다 → **다시 뽑는다** (여름 프레임 `pf_sm*` 이 그랬다 — 455~600px인데 표시는 626px) |

- **원본은 지우지 않는다** → `docs/stickers/_원본-격자찌꺼기-2026-07-31/` · `마테-창업자-2507/_원본-톱니자국-2026-07-31/`
- 고친 뒤 **컷 검수 게이트(`check-cutouts.mjs`)를 다시 돌린다.**
