## 1️⃣ 🔎 리서치로 «새로» 확인한 것 셋

### ① ✅ 「구글 고유번호로 문을 지킨다」가 **규칙에서 진짜로 된다**
> Firebase 공식 «Security Rules and Firebase Authentication» —
> *"`firebase.identities` = 그 계정에 붙은 모든 신원의 map. 키는 `email`·`phone`·`google.com`… 값은 그 제공자의 고유번호 목록."*
> 예 = `request.auth.token.firebase.identities["google.com"][0]`

⭐ 그래서 **갈아타기 보험 ①(⛔Firebase UID 금지 · 열쇠는 구글 `sub`)이 규칙 단에서 성립한다.** 설계가 살았다.

⚠️⚠️ **함정 하나 — 이름이 겹친다.**
   규칙 안의 `request.auth.token.sub` 은 **구글 sub 가 아니라 «Firebase UID»** 다.
   📌 우리 설계문에 「열쇠 = 구글 sub」라고 적혀 있으니, 코드로 옮길 때 **`sub` 이라는 «글자»만 보고 집으면 정반대 값을 집는다.**
   ✅ 앱 쪽에서 구글 번호를 집는 자리 = `user.providerData.find(p => p.providerId === 'google.com').uid`

### ② ⛔ `signInWithPopup` 이 TWA 에서 도는지 — **여전히 「모른다」**
찾은 것은 *"TWA 에서 소셜 로그인은 리다이렉션 문제로 안 된다"* 는 **개인 글**과 **2017년 Chrome 61 이슈**뿐이다.
⛔ **공식 문서에도, 최근 근거에도 답이 없다.** → **「모른다」로 둔다.** 그래서 **실물로 잰다**(이 문서가 그 준비다).

### ③ 🔢 실측 — 파이어베이스를 넣으면 앱이 얼마나 무거워지나
| 넣는 것 | 원본 | 압축(gzip) |
|---|---|---|
| `app` ＋ `auth` 만 | 171KB | **35KB** |
| `app` ＋ `auth` ＋ **`firestore`** | 684KB | **167KB** |

⭐ **결론 = 「로그인한 사람이 로그인할 때만」 불러온다**(`import()` 로 늦게 부르기).
   → 로그인 안 한 유저는 **0KB**. 지금 앱 첫 화면 속도가 안 바뀐다.
⏳ 더 줄일 길(나중에) = Firestore SDK 대신 **REST** 를 직접 부르면 **132KB 를 더 던다**. 지금은 «단순한 쪽»을 고른다 — 손으로 짠 것보다 버그가 적다.

## 2️⃣ 🔒 만든 것 ⓐ — 보안 규칙 `firebase/firestore.rules`

한 줄 = **로그인한 사람이 «자기 칸»만 읽고 쓴다.** 그 밖은 전부 막힌다.

```
match /users/{gid} {
  allow read, write: if isGoogleUser() && googleId() == gid;
  match /{doc=**} { allow read, write: if isGoogleUser() && googleId() == gid; }
}
```

⛔ **이름은 영문으로 썼다** — 규칙 언어가 한글 이름을 받는지 **확인 못 했다.** 설명만 한글로 달았다.
⚠️ **이 환경에선 규칙을 «시험 삼아 돌려볼» 수 없다**(에뮬레이터가 `gstatic` 을 받아야 하는데 프록시가 막는다).
   → 그래서 **콘솔이 문법을 봐 주고, 되는지 안 되는지는 아래 판이 실물로 잰다.**
