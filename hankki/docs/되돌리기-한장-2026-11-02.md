# ⏪ 되돌리기 한 장 (운영 1단계 · 2026-11-02)

📮 창업자 = 「문제가 발생했을때 즉각대응할 수 있어야해」
⭐ 나쁜 판이 나갔을 때 **고치는 것보다 먼저 되돌린다** — 유저가 오래 안 보게.

## 언제 쓰나
- 배포 뒤 앱이 안 열림 · 하얀 화면 · 주요 화면 깨짐 · 아침 점검(ops-check) 메일이 «배포 직후» 옴
- ⛔ 작은 글자 오류는 되돌리지 말고 고쳐서 낸다(규칙 39 — 나간 기능을 함부로 끄지 않는다)

## 🤖 안드로이드·웹 (몇 분이면 된다)
1. 창업자가 「되돌려」라고 말한다 (⛔클로드가 혼자 판단해서 하지 않는다 — 배포다)
2. 클로드가 마지막으로 성공한 배포의 커밋을 찾는다
   `actions_list` → deploy-hankki 의 `conclusion: success` 중 나쁜 판 «직전» `head_sha`
3. 나쁜 커밋을 «되돌리는 커밋»을 새로 만든다 (⛔`reset --hard`·강제 푸시 금지 — 기록을 지우지 않는다)
   ```bash
   git checkout claude/chatgpt-conversation-link-kvn5ph && git pull
   git revert --no-edit <나쁜커밋>..HEAD     # 여러 개면 범위로
   npm --prefix hankki run build && npm --prefix hankki run smoke
   git push origin claude/chatgpt-conversation-link-kvn5ph
   ```
4. Actions 초록불 확인(배포 확인 = Actions 결론 하나뿐) → 창업자 폰에서 앱 다시 열기
5. 그 다음에 원인을 찾아 고친 판을 다시 낸다

## 🍎 아이폰 (되돌리기가 «없다»)
- 아이폰은 웹을 구워 넣어서, 이미 나간 판은 앱스토어에서 «내릴» 수만 있다.
- 그래서 막는 건 **나가기 전**이다: 굽기 전 관문 · 단계적 출시(3단계 · 일부 유저부터)
- 나쁜 판이 나갔으면 = 고친 판을 바로 굽고 «빠른 심사 요청»(❓ ASC 메뉴 위치는 그때 최신으로 확인)
