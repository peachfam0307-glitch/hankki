# 🤖 조사 질문 ③ — Gemini 로 유튜브 영상 읽기 (붙여넣기용)

> ⭐ 네 번째 답이 **Gemini 에 YouTube URL 을 그대로 넣는 공식 경로**를 알려줬다.
> ⛔ 그런데 그 답이 스스로 *"바로 개발하기 전에 한 가지를 더 파는 게 좋다"* 며
> **「18세 미만 접근 제한」을 「꽤 큰 변수」**로 남겼다. 그게 이 질문이다.

## 📋 이거 하나만 통째로 복사해서 붙여넣기

```
⛔ 이 질문은 「Gemini API 로 유튜브 영상을 분석하는 것」만 묻습니다.
   captions.download·yt-dlp·부정경쟁방지법 이야기는 하지 마세요. 그건 이미 답을 받았습니다.

저는 한국에서 요리 레시피 앱을 운영합니다.
- 구글 플레이 정식 출시 상태
- 콘텐츠 등급 「3세 이상」
- 유료 아이템(디지털 재화) 판매 예정
- 서버가 거의 없는 1인 개발 · 신용카드 등록을 피하고 싶습니다

만들려는 것: 유저가 «공개» 유튜브 요리 영상 URL을 넣으면,
Gemini 에 그 URL을 그대로 전달해 재료·조리순서·단계별 타임스탬프를 JSON으로 받는 기능.

아래 6개를 "공식 문서 원문 인용 + 출처 URL"과 함께 알려주세요.
추측이면 추측이라고, 확인 못 한 것은 "확인 못 함"이라고 명시해 주세요.

1. 🚨 연령 제한
   Gemini API(및 Vertex AI) 이용약관에 「18세 미만 이용 금지」 또는
   연령 관련 제한이 있습니까? 원문을 인용해 주세요.
   있다면 — 그 제한은 (a) API를 쓰는 개발자에게 적용됩니까,
   (b) 그 앱을 쓰는 «최종 사용자»에게도 적용됩니까?
   콘텐츠 등급이 「3세 이상」인 앱이 백엔드에서 Gemini를 호출하는 것은 문제가 됩니까?

2. 🚨 비용
   Gemini API 로 「유튜브 URL 1개」를 분석할 때 토큰이 어떻게 계산됩니까?
   - 10분 / 20분 / 30분 영상 각각 대략 몇 토큰입니까?
   - 2026년 현재 무료 티어(free tier)로 이 기능을 쓸 수 있습니까?
     쓸 수 있다면 하루 몇 건까지입니까?
   - 유료라면 20분 영상 1편당 미화/원화로 대략 얼마입니까?
   - 🚨 신용카드 등록 없이 쓸 수 있는 범위가 있습니까?

3. 제한값
   - 한 요청에 넣을 수 있는 YouTube URL 개수
   - 분석 가능한 영상 «길이» 상한
   - 하루 YouTube URL 요청 수 상한
   - 비공개·연령제한·지역제한 영상은 어떻게 됩니까?

4. Gemini API 직접 vs Vertex AI 경유
   상용 모바일 앱 백엔드에는 어느 쪽이 나은지, 다음 기준으로 비교해 주세요.
   약관 / 연령 제한 / 데이터 처리(입력이 학습에 쓰이는지) / 비용 / 카드 등록 여부

5. 데이터 처리
   유저가 넣은 URL과 Gemini 결과가 «모델 학습»에 쓰입니까?
   무료 티어와 유료가 다릅니까? 끄는 방법이 있습니까?
   (개인정보처리방침에 뭐라고 적어야 하는지도 알려주세요)

6. 종합 — 위 1~5를 볼 때
   「3세 이상 · 1인 개발 · 카드 등록 회피」인 앱이
   이 기능을 넣어도 되는지, 넣는다면 어떤 구성이 가장 안전한지 하나만 추천해 주세요.
```

## 🎯 이 답으로 무엇이 갈리나

- **1번이 「최종 사용자에게도 18세 제한」이면** → ⛔**이 길은 죽는다**(우리 앱은 3세 이상).
  그럼 남는 건 ⓐ′(붙여넣기)뿐이다.
- **2번 원가가 크면** → 「영상 1편 = 열쇠 몇 개」가 커진다. ⛔**카드 등록이 필요하면 우리 원칙과 충돌**한다.
- **3번 길이 상한이 짧으면** → 창업자가 콕 집은 **「20~30분 영상」**을 못 읽는다.
- **5번이 「학습에 쓰인다」면** → **개인정보처리방침을 또 고쳐야 한다**(8/27에 갓 게시했다).

## ⛔ 답이 오면 내가 걸러낼 것

- **「대체로 무료입니다」류의 뭉뚱그린 답은 근거가 아니다** — 토큰 수와 단가를 숫자로 받는다
- **연령 제한은 «개발자»와 «최종 사용자»를 반드시 갈라서** 읽는다 — 섞으면 정반대 결론이 난다
- **약관은 개정된다** — 만들기 직전에 다시 확인한다
