# 🌲 운영 큰 틀 설계안 — 「아프면 우리가 먼저 안다」 (2026-11-02 · 창업자 판정 대기)

> 착수 문서 = `운영-큰틀-설계-착수-2026-11-01.md` (창업자 원문·네 층·콘솔 실물 2장)

> 표시 = ✅확인(파일·공식) · 🟡짐작 · ❓모름

## 0. 한 줄
**신호는 여러 곳에서 나도, 모으는 곳·판정하는 곳·알리는 곳은 «하나씩»만 둔다.**
구멍마다 장치를 따로 붙이면(땜질) 장치끼리 또 구멍이 난다. 10/21 계기판이 아무도 모르게 죽어 있던 것이 그 실례다(✅ worker.js:376-378).

## 1. 뼈대 — 한 줄기
```
[신호]                         [모으기]          [판정]               [알리기]            [보기]
앱 오류(웹·아이폰·갤럭시) ─┐
워커 셋(오류·크론 결과)  ──┼→ 우리 워커 한 곳 → 매일·매시 크론 → 창업자 폰 알림 1통로 → ops 한 화면
벽 사용량(C~G)          ──┤                    (임계 넘나?)      (구매 알림 길 재사용)
배포·스모크 결과         ──┘
              ＋ 바깥 감시 1개 (GitHub Actions 정기 실행) — «우리 워커가 죽은 것»은 워커 자신이 못 알리니까
```
- **알리기 통로는 이미 있다** — 구매 알림(v14.69 · ✅ worker-push.js:92-133). 새로 안 만든다.
- **「조용함 = 고장」 원칙** — 매일 아침 한 번 「다 정상」 한 줄을 보낸다(심장 박동). 안 오면 그 자체가 경보다.
  → 계기판·알림 통로·크론이 «죽어서 조용한 것»과 «멀쩡해서 조용한 것»이 갈린다.

## 2. 네 층에 무엇을 놓나
| 층 | 놓는 것 | 근거 |
|---|---|---|
| ① 나가기 전 | **스모크 시계 한 곳** — 모든 판이 같은 「가짜 오늘」을 쓴다 ＋ 1일·말일·12/31·2/29 판을 따로 돈다 | ✅ 날짜 쓰는 판 14개가 제각각(11/1 배포가 막힘) |
| | **흔들리는 판 표시** — 실패하면 혼자 한 번 더, 그래도 실패면 막는다. 다시 돈 횟수는 기록 | ✅ smoke-par.mjs:120-129 「같은 판이 3배까지 흔들린다」 |
| | 오래 쓴 폰 상태 판(레시피 300·일기 1년·옛 버전 데이터) | 🟡 지금 판은 대부분 새 폰 기준 |
| ② 나간 뒤 | **앱 오류 → 우리 워커** (식별자 없이 · 글 길이 자름 · 기기당 하루 상한) | ✅ 지금은 ErrorBoundary 가 폰에만 남김(ErrorBoundary.jsx:24-35) |

| | **바깥 감시** — GitHub Actions 정기 실행이 사이트·워커 셋·심장 박동을 확인, 실패면 알림 | 🟡 이미 쓰는 도구라 0원(Actions 무료 한도는 아직 안 봤다) |
| ③ 터졌을 때 | **되돌리기 한 장** — 「이 순서로 누르면 몇 분 안에 이전 판」. 이미 스모크를 통과한 커밋만 대상 | ✅ 지금 문서 0 · 자동 업데이트라 나쁜 판도 바로 퍼진다(vite.config.js:40) |
| | **원격 끄기 스위치** — 기능별로 워커에서 읽는다. 아이폰도 심사 없이 그 기능만 끈다 | ✅ 아이폰은 웹을 구워 넣어 되돌리기가 느리다 |
| | 아이폰 **단계적 출시**(7일 1→100% · 일시정지 30일) | ✅ 애플 공식 |
| ④ 커졌을 때 | **벽 C~G 사용량을 같은 크론이 재고 70%면 알림** | ✅ 벽 문서: 계기판 C·D뿐, 알림 0 |
| | 5만 명 다시 셈 — Pages 월 205GB(한도 100GB의 약 2배) · Firestore 읽기 무료의 3~5배 | 🟡 가정 포함(조사 A4) |

## 3. 신고 — 따로 고치지 않고 «한 번에»
- 오류를 보내면 **Play 「비정상 종료 로그」·애플 「진단」 신고와 privacy.html 항목**이 필요하다(✅ 두 곳 공식 정의).
- 지금 두 신고 모두 진단 없음(✅ 창업자 캡처 11/1·11/2). 그런데 `gate_fail` 은 이미 오류 글을 보낸다(✅ stats.js:566-572).
- 애플엔 「대략적인 위치」가 있고 Play 엔 없다(✅ 캡처) — 두 신고가 서로 다르다.
- **그래서 ②의 앱 오류 보고를 켜는 날, 세 곳(Play·애플·privacy.html)을 같은 날 같이 맞춘다.** 애플은 「연결 안 됨 · 추적 안 함 · 앱 기능 목적」으로 낼 수 있다(✅ 공식).

## 4. 세 번 흔들어 본 것 (절대원칙 33)
**1차 · 사람**
- 갓 깐 유저 화면이 하얗게 멈춤 → 지금은 아무도 모름 → ②로 잡힌다.
- 통계 끄기를 켠 유저 → 오류도 안 보내야 하나? ❓ **창업자 판정**(약속을 지키면 그 사람 오류는 못 본다).
- 창업자 본인이 밤에 알림 폭탄 → 고칠 것: **같은 오류는 한 번만, 묶어서** 보낸다(시간당 1통 상한).

**2차 · 사고 (일부러 망가뜨려 보기)**
- 오류 보고 코드가 스스로 오류 → 무한 반복 → 고칠 것: **보고 실패는 다시 보고하지 않는다 · 기기당 하루 상한**.
- 우리 워커가 죽음 → 워커 크론도 같이 죽어 못 알림 → 고칠 것: **바깥 감시(Actions)** 를 둔 이유.
- 알림 통로(폰 구독)가 만료 → 조용해짐 → 고칠 것: **심장 박동**이 안 오면 알 수 있다.
- 나쁜 배포가 자동 업데이트로 바로 퍼짐 → 고칠 것: **되돌리기 한 장 ＋ 원격 스위치**.
- 계기판 자체가 죽음(10/21 실제) → 심장 박동에 「계기판 정상」을 넣는다.

**3차 · 규모·시간**
- 평소: 5만 명 × 월 2건 ≈ 하루 3,300건 → 워커 하루 10만의 약 3% 🟡(1인 월 2건은 가정).
- **폭주:** 5만 명이 다 같은 버그를 맞고 기기당 하루 5건이면 하루 25만 → 워커 한도 초과 → 고칠 것: **같은 오류가 일정 수를 넘으면 워커가 「이제 그만」을 돌려주고 앱이 멈춘다**(전역 상한은 비용 방어용으로만 · 절대원칙 32).
- 1년 뒤: 오류 기록이 쌓임 → 보관 기간을 정한다(예: 30일 뒤 자동 삭제) 🟡 privacy.html 보관 기간과 맞춰야 한다.

## 5. 길 비교 — ② 앱 오류를 어디로 보내나
| | 우리 워커 | Sentry | GA4 이벤트 |
|---|---|---|---|
| 데이터 위치 | 우리 손 | 해외 제3자 → 국외 이전 항목 추가 | 이미 미국 이전 신고 있음 |
| 알림 | 구매 알림 길 재사용 | 내장 | ❓ 확인 못 함 |
| 1천 명 | 0원 🟡 | 0원(무료 5k) ✅ | 0원 🟡 |
| 5만 명 | 0원 🟡(한도 3%) | 월 $29 ＋ 초과(단가 ❓) | ❓ |
| 손 | 묶기·소스맵을 직접 | 다 있음 | 스택 없음 |
**추천 = 우리 워커.** 알림 통로·워커·D1 이 이미 있고, 데이터가 밖으로 안 나가서 신고를 가장 가볍게 낼 수 있다. Sentry 는 유저가 크게 늘어 손이 모자랄 때 다시 본다.

# 🔁 2판 — 더 단순하게 (창업자 2026-11-02 00:17 「더 심플하고 정확하게 · 어디서 발생했는지도 알 수 있어?」)

## 「어디서」를 알 수 있나 — 실측
- ✅ 지금은 **못 안다**: 앱 오류는 폰에만 남고(ErrorBoundary.jsx:24-35), 빌드에 소스맵이 없다(`vite.config.js` 에 sourcemap 설정 0 · `dist/assets/*.map` 0개).
  → 오류를 받아도 위치가 압축된 코드 한 줄(`index-xxxx.js:1:48211`)로만 온다.
- ✅ 알 수 있게 하는 법 = 빌드 때 **「숨긴 소스맵」**(hidden)을 만든다 — 지도 파일은 만들되 사이트엔 안 올리고 우리만 갖는다. 받은 위치를 지도로 풀면 **파일·줄·함수 이름**이 나온다. (출처: Vite PR #11505 · Vaadin 문서 — Vite 공식 설정 문서는 이 세션에서 못 열었다 ❓)
- 함께 싣는 것 = 앱 판(v14.70) · 기기 갈래(웹/갤럭시/아이폰) · **보던 화면**(stats.js:355 `지난화면` 이 이미 있다) · 직전 화면 몇 개.
  → 「아이폰 v14.70 · 레시피 상세 → 메모 붙이기 누름 · RecipeDetailScreen.jsx 812줄 postit 읽다가」 꼴로 온다.

## 단순하게 줄인 것 (1판 → 2판)
| 1판 | 2판 | 왜 |
|---|---|---|
| 워커 크론 점검 ＋ 바깥 감시(Actions) — 점검하는 곳 둘 | **점검은 GitHub Actions 한 곳** | 워커가 죽어도 밖에서 본다 · 점검 코드가 한 벌 |
| 오류를 D1 표에 쌓고 묶기 직접 | **워커는 받아서 로그에 찍기만** → Cloudflare 기본 기록 화면(Observability · 검색·묶어보기 있음)에서 본다 | 표·묶기 코드를 안 만든다 · 무료 하루 20만 건 · 3일 보관 ✅ |
| 알림 길 하나(폰) | 폰 알림 ＋ **Actions 실패 메일**(GitHub 이 저장소 주인에게 보낸다 🟡) | 폰 알림 길이 죽어도 메일로 안다 |
- 결과: 새로 만드는 것 = ①앱 오류 보내는 짧은 코드 ②워커에 받는 문 하나 ③Actions 점검 한 판 ④숨긴 소스맵 ＋ 푸는 스크립트. 나머지는 이미 있다.

## 더 단순한 길 — Sentry 를 쓰면
- 위치 풀기·묶기·알림·판별 추적이 **다 만들어져 있다**(✅ 가격 페이지 · 무료 = 오류 5천 · 사용자 1명).
- 대신 **오류가 해외 회사로 간다** → privacy.html 국외 이전 항목 ＋ 두 신고 «제3자» 칸이 바뀐다(지금 Play 「제3자와 공유 없음」 ✅캡처).
- 5만 명이면 유료(월 $29 ＋ 초과 ❓).
- ⚖️ 「우리 손이 덜 든다」 vs 「약속·신고가 더 바뀐다」 — **창업자 판정**.

## 3각도 다시 (2판 기준)
- 사람: 소스맵이 판마다 달라 «옛 판» 오류를 새 지도로 풀면 틀린다 → **판마다 지도를 따로 보관**(v14.70 지도는 v14.70 오류에만).
- 사고: Actions 정기 실행은 저장소가 60일 조용하면 꺼질 수 있다 🟡 → 꺼지면 심장 박동이 안 와서 안다.
