## 한 줄

**모델이 나빴던 게 아니라 «줄을 잘못 세웠다».**
답 길이 상한(8000 토큰)과 앱 대기(120초)가 **서로를 모르는 숫자**였고, 그래서 어느 날은 되고 어느 날은 안 됐다.

## 🌲 뿌리

`worker-tidy.js` 의 모델 차례가 이랬다:

```
const 차례 = [
  ...(image ? [{ model: VISION_MODEL, 눈: true }] : []),   // ← 사진이 있으면 «눈»이 맨 앞
  ...모델차례(env).map((m) => ({ model: m, 눈: false })),
]
```

그리고 눈 모델의 답 길이가 **8000 토큰**이었다(`VISION_MAX_TOKENS`).
⛔ 그 8000 은 **2026-09-01 에 우리가 «올린» 값**이다 — 그때 4000 이 「생각」에 다 쓰여 잘렸기 때문에.
   📌 그때는 맞는 처방이었는데, **앱이 120초에 놓아주는 구조(선반 방식)가 그 뒤에 생겼다.**
   두 숫자가 서로를 모른 채 각자 옳았고, 만나는 자리에서 갈렸다.

🔢 앱 대기 = `tidy.js` 의 `선반간격 5000ms × 선반횟수 24` = **120초**
🔢 눈 모델이 8000 토큰을 다 쓰면 그 시간을 **구조적으로** 넘는다 → 앱은 떠나고 워커는 계속 돌아
   **뉴런은 태우고 결과는 버린다.**

## ✅ 고침 셋 (2026-09-13 · 창업자 ⓒ 확정 · 워커 붙여넣기 완료)

1. **모델 차례를 뒤집었다** — 빠른 글자 모델이 맨 앞, **눈은 「빈손일 때만」 도는 보험**
2. **`VISION_MAX_TOKENS` 8000 → 2000**
   🔢 왜 2000 인가 = 레시피 한 편 JSON 이 한글 기준 **600~900 토큰**(창업자 실물 「가지덮밥」·「멸치볶음」으로 셈) — 두 배 넘는 여유
3. `capacitor://localhost` — **서버엔 있는데 저장소엔 없던** 줄을 맞췄다(규칙 36)

## ⛔⛔ 다음 사람에게 — 이걸 다시 밟지 않으려면

- ⛔ **눈 모델을 다시 «맨 앞»에 세우지 말 것.** 사진을 보는 게 좋아 보여도, 그 길은 «느린 길»이다.
- ⛔ **답 길이 상한을 늘릴 땐 앱 대기(120초)와 «같이» 본다.** 한쪽만 늘리면 오늘이 되풀이된다.
- ⭐ **잣대 = 「이 값을 다 쓰면 앱이 기다리는 시간 안에 끝나나?」** 안 끝나면 그 값은 틀린 값이다.

📌 **두 곳에 있는 숫자가 서로를 모르면 반드시 갈린다.**
   우리가 이미 아는 사고와 같은 모양이다 — 「같은 이름을 여러 곳에 손으로 적어 뒀다」(coach.js)·
   「저장소 파일 ≠ 도는 서버」(worker.js 묶음1장). **이번엔 「숫자 둘이 서로를 모른다」였다.**
