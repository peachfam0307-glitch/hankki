# 📔 요리 기록 → 다이어리 — 방향 확정 (2026-08-05 밤)

> 창업자: *"사실 나도 그 탭은 안 쓰거든…"* · *"거기가 사실 지금 제일 죽은 탭이야"*
> → *"**만들었어요 누르면 그냥 다이어리로 바로 저장되면 안돼?**"*
> → *"**다이어리는 별개로. 나는 요리하면서 저 스티커 안누를 것 같긴해..**"*
> → ✅ *"**다이어리에 저장했어요 라는 문구만 뜨고 자동으로 저장 달력에표시. 달력에 스티커는 자기가 알아서.**"*

---

## ✅ 확정 — 세 줄

| 언제 | 무엇 |
|---|---|
| **「만들었어요」 누름** | **「다이어리에 저장했어요」 토스트만.** ⛔시트 안 뜬다 |
| **동시에** | **달력에 자동 표시** |
| **스티커·사진·일기** | **유저가 알아서.** 내킬 때 달력에서 열어 붙인다 |

⭐ **강요가 0이다.** 「꾸미러 가기」 버튼조차 안 붙인다 — 그것도 재촉이다.
📌 `docs/리텐션-설계원칙-2026-07-30.md` 의 ⛔재촉 금지 · ⛔"3개 모으면 잠금 해제" 금지와 정확히 같은 선이다.

## 1️⃣ 왜 죽었나 — 진단 (실물 확인 2026-08-05)

⭐⭐ **만든 사람이자 18년차 주부가 안 쓴다.** 그러면 꾸미기 문제가 아니다.

| | 무엇 | 왜 |
|---|---|---|
| **①** ⭐제일 크다 | **타이밍** | 「만들었어요」는 **요리 직후**에 누른다. 하루 중 제일 바쁜 순간이다 — 손 젖어 있고 상 차려야 하고. **거기서 별점·사진·팁 네 칸을 채우라고 한다** |
| ② | **마찰** | 폼 네 칸. 「한 번 톡」으로 끝낼 길이 없다 |
| ③ | **보상** | 달력에 **파란 점 하나.** 한 달을 요리해도 화면이 안 변한다 |
| ④ | **출구** | 레꾸는 **공유 카드**로 나가는데 기록은 앱 안에서 죽는다 |

⛔⛔ **①을 안 고치면 시트 안을 아무리 예쁘게 만들어도 여전히 안 쓴다.**

### ⛔ 클로드가 여기서 자리를 잘못 골랐다
시안 A 를 「스티커 한 번 톡」으로 내놨는데 **그것도 결국 «시트»였다.**
창업자 *"나는 요리하면서 저 스티커 안누를 것 같긴해"* — **맞다.**
📌 **요리 직후엔 시트 자체가 부담이다. 시트 «안»을 고칠 게 아니라 시트를 «없애야» 했다.**

## 2️⃣ 고칠 곳 — 코드상 거의 없다

`src/screens/RecipeDetailScreen.jsx` `onCook()` 이 **이미 저장은 하고 있다**:

```js
addDiary(entry)        // ← 저장은 여기서 이미 끝난다
cook(r.id)
setLogEntry(entry)     // ← ⛔ 이 한 줄이 폼을 연다
nav.showToast('만들었어요! 요리 기록에 남겼어요')
```

- **`setLogEntry(entry)` 를 빼면** 창업자가 말한 대로 된다
- 토스트 문구를 **「다이어리에 저장했어요」** 로
- ⚠️ 「오늘 이미 기록이 있으면」 분기(`existing`)도 같은 처리 — 시트를 안 연다

⭐ **즉 이 부분은 «빼는» 일이다.** 새로 만드는 게 아니다.

## 3️⃣ 달력 — 여기가 진짜 만들 곳

지금 = 파란 점 하나 (`CookCalendar` in `src/screens/MyRecipesScreen.jsx`)

**바꿀 것**
- 점 → **그날 만든 음식 아이콘** (우리 236컷이 바로 값을 한다)
- 유저가 스티커를 붙였으면 → **그 스티커가 칸에 보인다**
- 칸을 누르면 → **그날 다이어리**가 열린다

⭐ **한 달이 채워지는 게 보이는 것** — 지금 제일 없는 것이고, 그게 다음 달을 채우게 만든다.

## 4️⃣ 다이어리 — 별개 화면 (창업자 *"다이어리는 별개로"*)

요리하는 사람과 다이어리 쓰는 사람은 **같은 사람이지만 다른 순간**이다.

**들어갈 것** (시안 B 기준 · 아티팩트에 그려 뒀다)
- **종이 한 장** — 손글씨 날짜
- **폴라로이드 사진** — ⛔회색 네모가 아니라. 마테로 붙은 느낌
  ⭐ **그 레시피의 꾸민 표지가 이미 있으면 그게 들어가 있다** → 열자마자 빈 종이가 아니다
- **두 칸** — 「그날 이야기」 ＋ 「다음엔 이렇게」 (지금은 후자 하나뿐이라 «레시피 개선 메모»지 «그날의 기록»이 아니다)
- **스티커 줄** — 톡 누르면 붙고 끌어서 옮긴다. **`DecorEditor` 엔진 그대로 재사용**

## 5️⃣ ⭐ 이게 팩 판매 걱정을 푼다

창업자가 계속 말한 **「다꾸가 아니고 레시피만 꾸미는거라 돈 주고 살까」** —
그 걱정의 뿌리는 **꾸밀 자리가 표지 하나뿐**이라는 것이었다.

| | 개수 |
|---|---|
| 표지 | **레시피 수**만큼 |
| 다이어리 | **해먹은 횟수**만큼 ⭐계속 늘어난다 |

## 6️⃣ 우리가 이미 적어둔 것 (새로 발명할 게 아니다)

> **「요리 기록을 남기면 그날의 스티커가 서랍에 들어와요」** · *기록을 남기게 만듦 = 결산의 연료*

⭐ 창업자가 오늘 말한 **「남는 스티커 여기저기 붙이면 좋지」** 와 같은 방향이다.

### ⛔ 지킬 선 (같은 문서)
- ⛔ **스트릭(연속 며칠) 금지** — 끊기면 죄책감. 누적은 괜찮다
- ⛔ **평가 금지** — 달성률·점수·"잘했어요". **숫자는 세고 평가는 안 한다**
- ⛔ **「획득! 🎉」 팝업 금지** — 조용히 서랍에 들어오고 유저가 발견한다
- ⛔ **유니코드 이모지 금지** · ⛔ **이미 있는 스티커를 잠그지 않는다**
