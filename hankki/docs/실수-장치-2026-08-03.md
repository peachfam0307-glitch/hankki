## 2️⃣ 장치 — 만든 것

### ⓐ `.claude/hooks/subst-guard.sh` — **조용한 실패를 막는다** (유형 C)

⭐ **오늘 사고의 진짜 뿌리는 「두부」가 아니라 「파이썬 `.replace()`」였다.**
못 찾아도 **아무 말 없이** 원문을 그대로 돌려준다 → 파일은 저장되고, 나는 "고쳤어"라고 말하고,
창업자가 화면에서 볼 때까지 아무도 모른다. **실패가 성공처럼 보인다.**

- 막는 것 = `sed -i` · 파이썬 `.replace(` **＋ 파일 쓰기**가 한 명령에 있는 것
- 안 막는 것(일부러) = 화면에만 뿌리는 것 · Edit 툴(스스로 에러를 낸다) · 검색
- 대신 쓰는 도구 = **`tools/subst.py`** — 못 찾으면 **죽고**, 「혹시 이 줄 아니냐」까지 보여준다

**✅ 시험**: 오늘 사고 모양 → `exit 2` · `sed -i` → `exit 2` · 안전한 것 3가지 → `exit 0`
**⭐ 그리고 만든 지 5분 만에 나를 실제로 막았다** (이 문서 쓰다가 `sed -i` 를 치려다 걸렸다).

### ⓑ `hankki/scripts/check-text.mjs` — **두 번째 방어선** (유형 C)

훅은 「내가 그렇게 편집하는 것」을 막고, 이건 **「어떤 경로로든 새어 들어온 결과」**를 막는다.
한 겹만 두면 새 경로가 생겼을 때 그대로 나간다.

유저가 읽는 칸(레시피 제목·메모·재료·순서 ＋ 장바구니 이름·설명)에서
`\n` · `\t` · `/n/n` · `undefined` · `[object Object]` · `NaN` 을 잡는다.
**`npm run smoke` 체인 = 하나라도 있으면 배포가 막힌다.**

**✅ 시험**: 레시피 메모에 `\n\n` 되살리기 → 잡음 · 장바구니 설명에 → 잡음 · 원복 → 통과

### ⓒ `hankki/scripts/check-claims.mjs` — **「모른다 해놓고 추천」을 잡는다** (유형 A)

⭐⭐ **한계를 「적는 것」과 그 한계 위에서 「추천하지 않는 것」은 다른 일이다.**
나는 §8에 *"앱 가능 여부는 미확인"* 이라 정직하게 적어놓고, 같은 문서 비교표엔 ✅를 박고
추천 순서 ②번에 올렸다. **적어두면 정직한 줄 알았는데, 창업자가 읽는 건 표와 추천이다.**

문서 제목에서 이름을 뽑아 → 「미확인·못 읽었·추측」 문장의 **앞자리**에 그 이름이 있고
→ 같은 문서의 ✅·추천 줄에 또 나오면 경고. `npm run claims` · **세션 시작 브리핑에 자동으로 뜬다.**

⚠️ **실패가 아니라 경고다** — 글을 읽고 판단하는 일이라 오탐이 있을 수밖에 없다.
배포를 막으면 시끄러워서 곧 꺼버리게 된다.

**✅ 시험**: 정정 «전» 문서 → 「네이버」 정확히 짚음 · 정정 «후» → 통과 · 전체 108개 문서 소음 **2건**

⭐⭐⭐ **만드는 동안 두 번 틀렸고, 그게 이 장치의 값어치다:**
1. 처음엔 이름을 **볼드 안**에서 뽑게 짰다 → **오늘 사고를 못 잡았다**(「네이버 커넥트」는 맨 글자였다)
2. 고쳐서 낱말을 다 쪼갰더니 **108개 문서에서 52건** → 「이미」·「다시」·「필요」까지 이름이 됐다
📌 **규칙 12 그대로 — 만들면 옛 값으로 돌려봐야 내 가정이 틀린 걸 안다.** 52 → 18 → **2**.

## 3️⃣ ⛔ 장치로 못 만드는 것 (정직하게)

| 유형 | 왜 못 만드나 | 대신 |
|---|---|---|
| **A** 미확인 단정 (일부) | 「Play Console 표시 최소치를 모른다」는 걸 코드가 알 수 없다. **모른다는 걸 모르는 상태**라서 | ⓒ가 «문서에 적힌 것»만 잡는다. 나머지는 규칙 1-1 |
| **B** 창업자 원본 훼손 | 「다듬어도 되는 것」과 「손대면 안 되는 것」의 경계가 글마다 다르다 | ⏳ 4️⃣ 참고 |
| **E** 말을 잘못 읽음 | 「부탁 안 한다고 했잖아」를 코드가 못 센다 | — |
| **F** 순서 잘못 | 무엇이 급한지는 상황마다 다르다 | — |

⛔ **이걸 「규칙 추가」로 때우지 않는다.** 규칙은 이미 14개고, 오늘 어긴 것 중 상당수가 이미 규칙에 있었다.
**못 잡는 건 못 잡는다고 적어두는 게 낫다** — 잡는 척하면 다음 사람이 방심한다.

## 4️⃣ ⏳ 다음 (유형 B — 창업자 원본)

창업자가 준 원문을 `docs/창업자-원문/` 에 **받은 그대로** 저장하고,
`basics.js` 에서 「파운더의 실사용 레시피」로 표시된 것(지금 4편 — 대구뭉티기·공심채볶음·묵채·훈제오리깻잎볶음)은
**원문 파일이 있어야** 통과하게 한다. 다듬었으면 **원문과 나란히** 보여준다.

⛔ 완전 자동 대조는 안 된다 — 창업자가 *"네가 알아서 써서 달아줘"* 라고 승인한 경우도 있다(풀무원 콩국물).
**「원문이 남아 있는가」만 강제하고, 「같은가」는 사람이 본다.**
