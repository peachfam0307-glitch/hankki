## 5️⃣ 🔑 **로그인 — 이게 진짜 갈림길이다**

우리는 **GitHub Pages 를 감싼 TWA** 라 로그인에 함정이 하나 있다.

⛔ **`signInWithRedirect` 는 우리 앱에서 안 된다** — 크롬이 남의 집 저장칸을 막으면서
   파이어베이스가 쓰는 **숨은 iframe** 이 죽었다.
✅ **구글 공식 문서가 답을 못 박아 뒀다** — *"파이어베이스 호스팅이 «아닌» 곳에 올렸으면 **`signInWithPopup` 을 쓰라**"*
   ＋ 다른 길 = **구글 로그인 버튼으로 자격증명을 받아 `signInWithCredential()` 로 넘기기**

| 갈래 | 로그인을 누가 만드나 | 품 |
|---|---|---|
| 파이어베이스(1·2) | **구글이 다 해준다** — 버튼 하나 | ⭐ 제일 적다 |
| 드라이브(11) | 구글 로그인 ＋ **권한 하나 더**(「구글 드라이브의 앱 데이터」) | 중간 |
| Cloudflare D1(7) | **우리가 붙인다** — 구글 로그인으로 받은 표를 Worker 가 검증 | 제일 많다(그래도 몇십 줄) |

⚠️ **정직하게 — TWA 안에서 `signInWithPopup` 창이 실제로 뜨는지 나는 «안 눌러봤다».**
   원리상 TWA 는 진짜 크롬이라 될 가능성이 크지만, **되는 걸 본 적은 없다.**
   ✅ **어느 갈래를 고르든 제일 먼저 할 일 = 빈 화면에 로그인 버튼 하나 놓고 폰에서 눌러보기.**

📌 **그래서 제미나이의 1번 추천(ⓓ 드라이브)이 «제일 안전한 길»은 아니게 됐다.** 후보엔 남기되 **⚠️를 단다.**

### ⭐ 페이블이 덧붙인 실무 조언 둘 (설계에 넣는다)

- **사진은 «별도 서브컬렉션 문서»로 갈라** 목록은 글자만 읽고 상세에서만 사진을 읽는다 → 송신 한도가 풀린다
- **base64 는 33% 부푼다** — 185KB → 문서 247KB · 640px 64KB → 85KB.
  ⭐ 페이블 계산 = 800px **280명** · 640px **800명** (⚠️레시피 30편 중 15편 사진 «만» 가정 · **일기를 안 셌다**)
  📌 **우리 실측 8.5MB/명 은 일기 사진까지 넣은 값이라 더 보수적이다. 우리 숫자를 쓴다.**
- ⭐⭐ **「내보내기(export) 경로를 항상 유지하라」** — 무료 조건은 바뀐 전례가 있다(Firebase Storage 2026-02).
  📌 우리는 **이미 있다**(백업 파일 저장). ⛔클라우드가 생겨도 **그 버튼을 없애지 않는다.**

## 1️⃣4️⃣ ⭐⭐⭐ **셋을 다 읽고 «내가» 새로 본 것 — 로그인과 저장소는 «따로» 고른다**

두 AI 가 「Firebase 냐 Cloudflare 냐」로 다투는데, **그건 두 가지를 한 덩어리로 봐서 그렇다.**

| 층 | 무엇이 필요한가 | 후보 | 갈아탈 수 있나 |
|---|---|---|---|
| 🔑 **로그인** | 「누구인지」 ＋ 구글 계정 붙이기 | **Firebase Auth**(무료·**카드 X**·5만 MAU·구글이 비번·해킹을 다 맡는다) | ⛔ 갈아타면 유저가 다시 로그인해야 한다 |
| 📦 **저장소** | 글자·사진을 담아둘 곳 | Firestore / **D1** / 드라이브 | ✅ **갈아탈 수 있다** — 옮기면 된다 |

⭐⭐ **이렇게 갈라 보면 창업자가 지금 걸 판돈이 훨씬 작아진다.**
   · **로그인은 Firebase Auth 로 거의 굳어도 된다** — 공짜, 카드 없음, 우리가 제일 못 만드는 부분,
     그리고 **어느 저장소를 골라도 그대로 쓴다**(Worker 도 Firebase 가 준 표를 검증하면 된다).
   · **저장소만 나중에 정해도 된다** — 심지어 쓰다가 바꿔도 유저는 모른다.

📌 **그래서 제미나이의 「몰아라」와 페이블의 「나눠라」는 «둘 다 맞다».**
   로그인은 한 곳(구글)으로 몰고, 저장소는 갈아탈 수 있게 느슨하게 둔다.

⛔ **딱 하나 못 갈아타는 것 = 로그인.** 그러니 **로그인 실험이 제일 먼저다**(TWA 에서 창이 뜨나).

> ⭐ **로그인 = Firebase Auth 로 공통.** 아래는 **「저장소」만** 고르는 표다.

### ⭐ 그리고 셋(제미나이·페이블·나)이 **입을 모은 순서**가 하나 있다

> **「ⓐ 로 먼저 낸다 → 사람이 늘면 사진을 얹는다」**

## 1️⃣8️⃣ 🎯🎯 **넷이 «다 같이» 말한 것 — 여기가 답이다**

> ⭐ 제미나이·페이블·지피티가 **서로 다르게 조사하고도 겹친 자리**. 이건 우연으로 보기 어렵다.

| | 셋 다 같은 말 |
|---|---|
| **1** | 🚨 **영구 스티커 팩을 팔려면 «서버 승인»이 반드시 필요하다** — 클라이언트로는 절대 안 된다 |
| **2** | ✅ **그 서버 = 이미 있는 Cloudflare Worker 로 «된다»** (Web Crypto 로 RS256 → OAuth → Play API) |
| **3** | ✅ **잔량 원장 = D1** (`purchaseToken` UNIQUE) · ⛔폰에도 드라이브에도 두면 안 된다(조작·롤백 가능) |
| **4** | ⛔ **사진을 서버에 올리는 건 «지금 하지 않는다»** |
| **5** | ⛔ **R2 · Firebase Cloud Storage 는 뺀다** (카드) |
| **6** | ⭐ **글자·텍스트부터. 그것만 살아도 대부분이 해결된다** |
| **7** | ⛓ **로그인이 생기는 순간 「국외이전 처리방침 ＋ 계정삭제(앱 내＋웹 URL) ＋ 데이터보안 재신고」가 세트로 붙는다** |

### 🧭 그래서 **넷의 답을 겹치면 그림이 하나로 모인다**

| 층 | 무엇 | 왜 |
|---|---|---|
| 📦 **평소 저장** | 폰 안 — **`localStorage` → IndexedDB** | 5MB 벽을 없앤다. 사진이 많은 사람이 지금 여기서 막힌다 |
| 💾 **잃지 않기** | **내보내기/가져오기**(이미 있다) ＋ **드라이브 「지금 백업 / 지금 복원」 단추** | 우리 용량 0 · 유저 15GB · 카드 0 |
| 🔑 **누구인지** | 구글 로그인 (Firebase Auth **또는** Worker 직접 검증) | 결제에 필요하고, 백업에도 쓴다 |
| 💳 **결제·잔량** | **Worker ＋ D1** | 셋 다 같은 말 · 카드 없음 |
| ☁️ **파이어베이스** | ⏳ **「다기기 실시간 동기화」가 «진짜 요구»로 확인되면 그때 · 텍스트만** | 지금 넣을 이유가 없다 |

⛔⛔ **이 그림엔 「파이어베이스가 지금 필요하다」는 자리가 없다.**
   📮 창업자 = *"파이어베이스는 내가 확정한게 아니라"* — **재조사 결과가 그 의심을 뒷받침한다.**
   ⭐ 파이어베이스가 나쁜 게 아니라 **지금 단계에 «필요한 일이 없다».** 나중에 넣을 자리는 남겨 둔다.

## 2️⃣0️⃣ ✅ **바뀐 할 일** (⛔전부 재심사 승인 «뒤» · 지금은 0)

## 2️⃣2️⃣ 🚨🚨🚨 **지피티 재답 — 내 질문 1·2 의 답이 왔다. «드라이브 길이 죽었다»**

내가 1️⃣6️⃣ 에서 물어달라 한 두 가지에 지피티가 **약관 원문을 열어** 답했다 (확인일 2026-08-19 · 약관 최종수정 2022-07-08 · 페이지 갱신 2026-07-22 = **지금 유효**).

### ⛔ 질문 1 의 답 — **백업 금지 조항이 «실재»한다. `appDataFolder` 도 예외가 아니다**

> Google Drive API 이용약관: *"**Backup of user or app content from a developer's app or project to Drive.**"*
> = 개발자 앱의 유저 콘텐츠·앱 콘텐츠를 드라이브에 백업하는 용도는 **구글의 사전 서면 동의 없이 허용되지 않는다.**

| `appDataFolder` 에 넣는 것 | 판정 |
|---|---|
| 테마 설정·마지막 동기화 시각·환경설정 | ✅ 명시된 용도 |
| **유저가 만든 레시피·일기·사진 전체 복사본** | ⛔ **「user or app content backup」에 정면으로 해당** |
| 앱 삭제·기기 변경 대비 복원 파일 | ⛔ **목적 자체가 백업이라 직접 걸린다** |

⭐ **지피티가 자기 앞 답(Q8 의 드라이브 추천)을 스스로 철회했다.** 페이블의 경고(1️⃣3️⃣)가 맞았다.

### ⛔ 질문 2 의 답 — **브라우저는 refresh token 을 «못 받는다». Worker 에 두는 길은 있지만 약관이 그대로 막는다**

- GIS 토큰 모델 = **짧은 access token 뿐** · 갱신은 «버튼 클릭 같은 유저 동작»에서만 → 무인 자동 백업 불가
- Worker 가 Authorization Code + offline 으로 refresh token 을 보관하면 기술적으론 되지만 → **백업 서면 동의 문제가 그대로**
- 브라우저(IndexedDB)에 refresh token 저장 = ⛔ XSS 탈취 위험 · 구글 자체가 안 준다

### ✅ 그래서 갈래표가 «확» 줄었다

| 갈래 | 판정 |
|---|---|
| ~~ⓒ 사진만 유저 드라이브~~ · ~~ⓓ 드라이브로 전부~~ | ⛔⛔ **죽은 길 — 약관.** 제미나이 1번 추천·지피티 첫 답도 같이 죽었다 |
| ✅ **유저가 «자기 손으로» 백업 파일을 자기 드라이브에 올리는 것** | **약관 무관** — 앱이 Drive API 를 안 부르니까. ⭐**지금 우리 `shareBackup`(공유 시트 → 드라이브 앱)이 정확히 이 방식이다. 이미 합법으로 하고 있다** |
| 자동 클라우드 복원이 필요하면 | **그 용도가 «허용된» 저장 서비스로** = Firestore 든 D1 이든 «우리 저장소»에 |

## 2️⃣3️⃣ 🎯🎯🎯 **최종 그림 — 전수조사 끝. 남은 판정 «둘»** (⭐이게 현행이다)

죽은 길을 다 걷어내면 이렇게 남는다:

| 층 | 답 | 상태 |
|---|---|---|
| 📦 평소 저장 | 폰 안 · **`localStorage` → IndexedDB**(5MB 벽 제거) | ✅ 넷 합의 · 우리 백로그(7/17)와 일치 |
| 💾 내보내기 | **파일 저장·공유**(사진까지 통째) — 유저가 자기 드라이브에 «직접» 올리는 건 합법 | ✅ **이미 있다** · ⛔클라우드가 생겨도 안 없앤다 |
| 💳 결제·잔량 | **Worker ＋ D1** (`purchaseToken` UNIQUE · acknowledge) | ✅ 넷 합의 · 카드 0 |
| ☁️ **클라우드 저장**(창업자 1번) | **로그인하면 글자 데이터가 살아나는 것** — 사진은 지금 안 올린다 | ⏳ **아래 판정 ①** |
| 🔑 로그인 | 구글 로그인 | ⏳ **아래 판정 ②** |

### ⏳ 창업자가 정할 것 — 이제 진짜 둘뿐이다

| | 물음 | 갈래 | 내 추천(⛔판정은 창업자) |
|---|---|---|---|
| **①** | **글자 데이터를 «어느 우리 저장소»에 올리나** | ⒜ **Firestore**(서울 리전 · 1GB · 규칙만 쓰면 서버코드 0 · 업체 둘) ／ ⒝ **D1**(5GB · 결제 원장과 «같은 집» · Worker 코드를 우리가 짠다 · 업체 하나) | 지금 안 정해도 된다 — **로그인 실험(TWA 팝업) 결과를 보고** 정하는 게 안전 |
| **②** | **로그인 검증을 누가 하나** | ⒜ Firebase Auth(제일 쉽다) ／ ⒝ Worker 직접(업체 하나) | ①과 같이 정하면 된다 — ①⒜면 ②⒜, ①⒝면 ②⒝가 자연스럽다 |

⭐⭐ **결국 «짝» 선택이다** — **「파이어베이스 짝」**(쉽다·업체 둘) vs **「Cloudflare 짝」**(집 하나·손 조금 더).
   둘 다 카드 0 · 놀아도 안 멈춤 · 한도 넘으면 청구 대신 막힘. **어느 쪽이든 원칙은 안 깨진다.**
📌 그리고 이건 8/16 의 「파이어베이스 확정」과 **다르다** — 그땐 대안을 안 지우고 골랐고,
   지금은 **12갈래를 전수로 지우고 남은 둘**이다. 창업자가 뭘 고르든 근거가 선다.

승인 뒤 첫 실험 = **TWA 에서 구글 로그인 창이 뜨나** (⛔어느 짝을 골라도 여기서 막히면 다 못 간다)

### 드라이브 반전
제미나이가 "유저 각자의 드라이브(15GB)에 넣으면 공짜에 무제한!"이라고 1등으로 추천했는데,
**약관을 열어보니 "앱이 유저 데이터를 드라이브에 백업하는 건 구글 허락 없이 금지"라고 적혀 있었다.**
지피티가 원문을 확인하고 자기 추천을 스스로 취소했다.
다만 **유저가 자기 손으로** 백업 파일을 자기 드라이브에 올리는 건 괜찮다 —
그리고 **우리 앱의 「백업 공유하기」가 이미 딱 그 방식이다.** 모르고 이미 제일 안전하게 하고 있었다.
