# 1️⃣ 팩 하나당 딱 하나 + **축이 겹치면 안 넣는다** ⭐ 규칙

## 규칙 ① 팩 하나에 모션이거나 효과이거나 **딱 하나**

**팩을 사는 이유를 만든다.** 사는 이유가 **그림 몇 장**이면 유저는 하나 사고 만다.
그림은 다음 팩과 비슷해 보여도 **움직임은 눈에 확 띄고 한 번 쓰면 계속 쓴다.**

**그런데 1+1은 안 된다 — 팩이 매달 나오기 때문이다.**
처음에 "모션 1 + 효과 1"로 잡았다가 창업자가 바로 잡아 줬다:
*"유료팩당 효과나 모션 1개. 각각 1개 총 2개가 아니라 그냥 1개씩. 왜냐면 **매달 나오는건데** 부족해."*

| | 팩당 2개(1+1) | **팩당 1개** ✅ |
|---|---|---|
| 만들어 둔 것으로 | **6개월** 버팀 | **1년** 버팀 |
| 매달 새로 만들 양 | 2개 | 1개 |

## 규칙 ② **축이 겹치는 건 팩에 안 넣는다** ⭐⭐ (더 중요)

> 창업자 2026-07-30: *"있자나 모션이 다 비슷비슷해 효과도 그렇고.. 이게 문제네"*
> *"냠냠도 둥실도 콩콩도 통통이랑 비슷. 살랑 갸웃 비슷. 효과들은 다 거기서 거기 ㅠㅠ"*

세어 보니 **정확히 맞는 지적**이었다.

| 모션 9개가 실제로 쓰던 축 | 개수 |
|---|---|
| **위아래로 움직인다** (통통·콩콩·냠냠·둥실·쿵착지) | **5개** |
| 기울어진다 (갸웃·살랑) | 2개 |
| 물 위 부유 (찰랑) · 종이 3D (펄럭) | 각 1개 |

| 효과 9개가 실제로 쓰던 방향 | 개수 |
|---|---|
| **위로 뜬다** (하트·뽀글·김모락·맛있는것들) | **4개** |
| **아래로 떨어진다** (눈·꽃잎·낙엽·물방울) | **4개** |
| 제자리 깜빡 (반짝이) | 1개 |

**개수는 9개인데 종류는 3~4가지.** 나머지는 **속도와 그림만** 달랐다.
그래서 아무리 늘려도 "또 비슷한 거"로 보였던 것이다.

### 📌 그래서 규칙을 이렇게 바꿨다

> **모션을 늘릴 땐 시간(속도)을 바꾸지 말고 축(무엇이 변하는가)을 바꾼다.**
> **효과를 늘릴 땐 그림(무엇이)을 바꾸지 말고 방향(어디로 가는가)을 바꾼다.**

`MOTIONS` 의 `axis` · `FX_KINDS` 의 `dir` 이 그 축·방향이다. **팩에 넣기 전에 이걸 먼저 본다.**

### 🆕 그래서 새로 만든 것 — 축이 안 겹치는 것들

| 축 (모션) | 이름 | 어떻게 다른가 |
|---|---|---|
| **좌우로 걸어간다** | **아장아장** | **자리를 옮긴다.** 위아래로 뛰는 애들과 인상이 근본적으로 다르다 |
| **한 바퀴 돈다** | **빙글** | 대부분 멈춰 있다가 가끔 휙. 계속 돌면 어지럽다 |
| **부르르 떤다** | **부르르** | **빠르고 작다.** 통통(느리고 큼)과 정반대 |
| **크기만 변한다** | **콩닥** | 자리 이동이 **0**. 두 박자(쿵-닥)라야 심장으로 읽힌다 |
| **좌우로 뒤집힌다** | **두리번** | 그림 1장으로 "돌아본다"를 만드는 **유일한** 방법 |

| 방향 (효과) | 이름 | 어떻게 다른가 |
|---|---|---|
| **바깥으로 터진다** | **팡!** | 뜨지도 떨어지지도 않는 유일한 방향. 조각마다 날아가는 쪽이 달라야 '터졌다'로 보인다 |
| **머리 둘레를 돈다** | **빙빙** | 제자리도 아니고 지나가지도 않는다. 그림 자체는 안 돌게 되돌린다 |
| **가로로 지나간다** | **슝** | 세로로만 오가던 것들과 축이 90도 다르다 |
| **뒤에 깔려 숨쉰다** | **후광** | 앞에 뜨는 조각이 아니라 **뒤**. 그래서 인상이 완전히 다르다 |

## ⛔ 하면 안 되는 것

| 금지 | 왜 |
|---|---|
| 한 팩에 두 개 넣기 | 그 팩만 팔린다 + 재고가 두 배로 빨리 바닥난다 |
| **축이 겹치는 걸 팩에 넣기** | **"또 비슷한 거"가 된다.** 돈 주고 산 값어치가 안 난다 |
| **속도만 바꿔서 새 모션이라고 하기** | 개수는 늘어도 종류는 안 는다 (이번에 실제로 그랬다) |
| 이미 무료로 준 걸 팩에 다시 넣기 | **한 번 준 것은 빼앗지 않는다** — 팩 값어치도 0이 된다 |
| 배분표와 코드가 어긋난 채로 두기 | 팩을 팔 때 **뭐가 딸려 가는지 아무도 모르게 된다** |

모션 `콩콩`·`냠냠`·`둥실`·`쿵착지`(위아래) · `살랑`(기울기)

**코드·CSS 그대로 있고, 이미 저장된 표지도 계속 정상 동작한다.** 팩에만 안 넣는 것이다.
(빼기 전에 ①어떤 기능에 묶였는지 ②실제로 쓰는지 ③쓰임이 다른지 본다 — 저장된 표지가 쓰고 있다)

## 🌨 남은 문제 — 계절 낙하 효과는 **배경으로 옮기는 게 맞다**

`눈`·`낙엽`·`꽃잎`은 **떨어져야 눈이고 낙엽이다.** 아무리 해도 서로 닮는다.
→ 이 셋은 **스티커 효과 말고 배경 한 겹**으로 옮긴다.
   표지 **전체**에 눈이 내리는 게 스티커 하나 위에 내리는 것보다 훨씬 예쁘고,
   **스티커 효과 자리는 축이 다른 것들로 채울 수 있다.**
→ 마침 **시안 C(배경 효과 60종)** 가 통째로 그 얘기다. → 4️⃣ 후보 2

## ⚠️⚠️ 재고 한계 — **매달 새 축을 만드는 건 물리적으로 불가능하다** (창업자 지적 2026-07-30)

> 창업자: *"우리 가을만해도 유료팩이 3개야 ㅋ 겨울은 크리스마스 설날. 봄은 벚꽃, 여행?
> 여름은 물놀이 바다등등 **적어도 유료팩이 계절당 2개씩** 나올텐데 저거 효과 나중에도 계속 쓸 수 있나?
> 배경도 중간에 하나씩 넣어야 할 것 같은데.. **진짜부족할것 같아..**"*

**맞는 걱정이고, 내 12개월 배분표의 근본 한계다.** 실제 팩 계획을 세어 보면:

| 계절 | 팩 |
|---|---|
| 가을 | 추석 · 가을 다꾸 · 가을 수채화 · 핼러윈 = **4개** |
| 겨울 | 크리스마스 · 설날 = 2개 |
| 봄 | 벚꽃 · 여행 = 2개 |
| 여름 | 물놀이 · 바다 = 2개 |
| **합** | **연 10~12팩** |

### 왜 "매달 새 모션"이 불가능한가 — **축은 유한하다**

그림 **한 장**으로 만들 수 있는 움직임의 축은 **물리적으로 정해져 있다**:
`위아래` `기울기` `좌우 이동` `회전` `진동` `크기` `좌우 반전` `3D` — **여덟 개쯤이 끝**이다.
효과 방향도 `뜸` `낙하` `터짐` `궤도` `가로` `뒤` — **여섯 개쯤**.
**우리는 이미 그 중 대부분을 썼다.** 매달 하나씩 쓰면 **1년이면 바닥난다.**

### ✅ 답 ① — "나중에도 계속 쓸 수 있나?"

- **산 사람은 영원히 쓴다.** 한 번 판 건 안 뺏는다.
- **코드(축)는 얼마든지 재사용한다** — 그건 우리 비용 절감이다.
- ⛔ **단, 이미 판 것과 똑같은 걸 다시 팔면 안 된다.** 그림이 달라야 한다.

### ✅ 답 ② — **같은 축에 다른 그림을 끼우면 새 효과가 된다** ⭐ 이게 해법이다

`낙엽`·`눈`·`꽃잎`이 서로 닮아 보였던 이유 = **같은 낙하 코드에 그림만 다른 것**이라서다.
**뒤집어 보면** — 낙하 코드 **하나로 계절마다 새 효과를 만들 수 있다**는 뜻이다.
비용은 **거의 0**(SVG 조각 하나 그리면 끝, 시트도 안 뽑는다).

| 팩 | 같은 축 | 새 조각 |
|---|---|---|
| 벚꽃 | 낙하 | 벚꽃잎 |
| 바다 | 궤도 | 조개·불가사리 |
| 설날 | 터짐 | 복주머니·엽전 |
| 여행 | 가로지름 | 구름·비행기 |

### ✅ 답 ③ — **배경은 재고가 거의 무한하다**

색조합 × 질감 × 빛 = 조합이 **수백 가지**. 시안 C가 60종을 제시했고 그것도 일부다.
그리고 **그림이 0장** 들어서 **창업자 손이 아예 안 간다.**
→ 창업자 말대로 *"배경도 중간에 하나씩"* 이 **정확히 맞는 판단이다.**

### 📋 그래서 규칙을 이렇게 고친다 — 팩의 「하나」를 **세 등급**으로

| 등급 | 무엇 | 연 몇 개 | 어느 팩에 |
|---|---|---|---|
| 🥇 **새 축** | 진짜 새로운 움직임 | **3~4개만** | 사람이 몰리는 큰 팩(추석·크리스마스·벚꽃·여름 대표) |
| 🥈 **같은 축 + 새 조각** | 낙하에 벚꽃잎, 궤도에 조개 | 4~5개 | 나머지 계절 팩 |
| 🥉 **배경 연출** | 색·질감·빛 | 4~5개 | 사이사이 팩 + 이벤트 |

**→ 팩 하나당 하나**는 그대로 지키면서 **재고가 안 마른다.**
지금 만들어 둔 **새 축 9개**(모션 5 + 효과 4)를 🥇로 아껴 쓰면 **2~3년치**가 된다.
(매달 새 축을 쓰면 1년, 아껴 쓰면 3년 — **같은 재고인데 3배**다)

⚠️ **큰 팩과 작은 팩을 구별해야 한다.** 다 똑같이 대접하면 큰 팩이 안 커 보인다.
   🥇를 받은 팩이 그 계절의 **간판 팩**이고, 나머지는 그 옆에 붙는다.

⏳ **창업자 최종 확정 대기.** 등급 배분(3~4 / 4~5 / 4~5)과 어느 팩이 🥇인지가 확정되면 배분표를 다시 짠다.

## 🎨 기본 배경 정리 — **기본은 단색만. 그라데이션·질감·빛은 유료 팩 몫** (창업자 확정 2026-07-30)

> *"색·그라데이션 이거 넣으려면 우리 기본배경에 있는거 빼야해. 지금 레꾸에 있는 모눈 도트
> 스프라이트 다 겹쳐. **기본배경에는 색깔만 있는 배경** 줘야할 듯"*
> *"**유료 배경효과에 그라 넣으려면 우리 기본으로 준 노을, 세이지 빼야한단 뜻이야**"*

### 뺀 이유 두 가지

**① 무늬가 겹친다.** 마스킹테이프에 이미 **모눈·도트·스트라이프**가 있다.
   배경에도 같은 무늬가 있으면 표지가 무늬 천지가 되고, 무늬끼리 싸운다.

**② 팔 것을 먼저 공짜로 주면 안 된다.** 그라데이션을 유료 배경 팩으로 팔 거면
   **`노을`·`세이지`를 기본으로 주고 있으면 안 된다.**
   ⭐ 그리고 **이미 준 걸 나중에 회수하는 건 더 안 된다** → **정식 출시 전인 지금이 정리할 마지막 타이밍.**
   (출시 후엔 쓰던 사람이 생겨서 못 뺀다)

### 결과

| | 개수 | 목록 |
|---|---|---|
| ✅ **기본(무료)** | **15** | 단색 14 **＋ 모눈** — 기본·크림·피치·하늘·라일락·크라프트·**모눈** / 딥세이지·웜토프·클레이·더스티로즈·라벤더·스모키블루 / 딥플럼·미드나잇 |
| 🔒 **그라데이션 팩** (`bg`) | 5 | 웜크림·민트·파스텔 · 노을·세이지 |
| 🔒 **종이 질감 팩** (`bgpaper`) | 2 ＋α | 도트·스트라이프 ＋ 만들 것(줄노트·크라프트지·린넨·수채지) |

### ⭐ 모눈만 무료인 이유 (창업자 확정 2026-07-30 *"나두... b가 좋아"*)

**모눈은 장식이 아니라 「노트」다.** 우리는 레시피를 **적는** 앱이라 모눈종이는 **기본 도구**에 가깝다.
다이어리 앱에서 모눈을 팔면 쪼잔해 보인다. 도트·스트라이프는 **순수 장식**이고 마테에 이미 있다.

📌 **기준: 무료로 줄지는 「아까운가」가 아니라 「없으면 앱을 못 쓰나」로 정한다.**
   - 모눈 = 없으면 노트 느낌이 안 남 → **준다**
   - 도트·스트라이프·그라데이션 = 없어도 됨 → **판다**

📌 **그리고 무료가 초라하면 유료도 안 팔린다.**
   단색만 14개면 배경 탭을 열었을 때 *"다 그냥 색이네"* 가 되고, 그 인상이면 팩을 살 마음이 안 생긴다.
   **모눈 한 장이 그 인상을 바꾼다.** — 유료는 **무료가 이미 괜찮을 때** 팔린다.

⚠️ **숨김 = 지운 게 아니다.** `hidden: true` 는 **피커에만 안 뜨게** 하고 `bgStyle()` 은 그대로 찾아 준다.
   → 이 배경으로 **이미 저장한 표지는 계속 정상으로 보인다.**

📌 **앞으로 배경을 새로 만들 때:** 단색이면 기본에, **그 외(그라데이션·질감·빛·계절)는 전부 팩**으로.
   기본에 하나 넣을 때마다 **팔 수 있는 게 하나 줄어든다**는 걸 기억한다.

## 🖼 배경(표지 전체) 연출 — 유료냐 이벤트냐 (창업자 질문 2026-07-30)

> 창업자: *"표지전체 아이디어 너무 좋아. 나도 그거 말하고 싶었어. 계절별로 너무 예쁠 것 같아.
> 계절아니어도 예쁠 것 같고. 이건 유료로 갈지 아님 이벤트성으로 풀지 네 의견을 듣고싶어."*

### 클로드 의견 = **이벤트성으로 하나 지금 풀고, 나머지는 팩에 얹는다. 단독 판매는 안 한다.**

**⛔ 배경 단독 판매를 말리는 이유 — 배경은 한 번에 하나만 쓴다.**
스티커는 20장 사면 20장 다 붙이는데 배경은 사도 표지 하나에 **하나만** 깔린다.
두 개 사도 한 번에 하나만 보인다 → **산 만큼 못 쓰는 물건**이라 두 번째를 살 이유가 약하다.
**스티커와 성질이 근본적으로 다르다.**

**✅ 대신 팩의 「마무리」로는 최강이다.**
"가을 팩 = 스티커 20장 + 낙엽 배경" 이면 팩 하나로 표지가 **통째로** 가을이 된다.
스티커만 20장 주는 것보다 **완성도가 확 달라 보인다.** 배경이 팩을 완성시킨다.

| 언제 | 무엇 | 왜 |
|---|---|---|
| **지금(출시)** | 무료 배경 3~4종 + **출시기념 여름 물결 1종** | 스토어 스크린샷 한 장으로 "예쁘다"를 증명해야 하는데 **배경이 스크린샷에서 제일 잘 먹힌다.** 무료로 하나 안 주면 **뭘 사는 건지 모른다** |
| **매달 팩** | 팩마다 배경 1종 얹기 | 팩이 "완성된 한 세트"로 보인다 |
| **시간대 연출**(아침·낮·노을·밤) | **무료로 앱 전체에** | 팔 게 아니라 **앱의 인상**이다. 저녁에 열면 노을빛이 도는 앱 = "정성 들인 앱". 팔면 대부분이 못 봐서 그 효과가 0이 된다 |

**⭐ 배경만의 강점 — 그림이 한 장도 안 든다.**
CSS만으로 되니 **창업자가 시트를 안 뽑아도 된다.**
= 팩 일정과 **무관하게 언제든** 낼 수 있다 → 이벤트로 쓰기 딱 좋다("이번 주만 벚꽃").
⚠️ 단, **처음부터 "이번 주만"이라고 말한 것만** 이벤트로 한다.
   그냥 준 걸 나중에 회수하면 안 된다(**한 번 준 것은 빼앗지 않는다**).

**⚠️ 배경 만들 때 지킬 것 — 멈춰도 예뻐야 한다.**
저장 사진엔 움직임이 안 담긴다(한 장으로 찍는다).
**빛·질감·그라데이션은 멈춰도 예쁜데, 떨어지는 눈은 멈추면 점 몇 개다.**
→ 배경은 **빛·질감 위주 + 떨어지는 건 곁들이는 정도.**

# 4️⃣ 시안에 없는 것 — 내가 더 찾아서 정리한 것

> 창업자 *"저게 다는 아닐거 아냐."* → 시안은 **뭘 만들지**를 알려준다.
> 여기 적는 건 **우리 앱에서만 생기는 제약과 기회** — 시안엔 있을 수 없는 것들.

## ⚠️ 우리만의 제약 4가지 (모르고 만들면 사고 난다)

### ① 캐릭터가 **그림 1장**이라 부분 모션이 안 된다
눈 깜빡·입 벌리기·손 흔들기는 **눈/입/손이 따로 있어야** 한다.
꼬르곰·펭펭은 통짜 PNG라 **몸 전체를 움직이는 것만** 된다.
→ 부분 모션을 하려면 **컷을 나눠서 다시 뽑아야** 한다(=자산 작업). 지금은 안 한다.
→ 시안 D의 07(음식 모션 8종) 중 커피 저어짐·면 움직임 같은 것도 같은 이유로 못 한다.

### ② 저장·공유 이미지에는 **움직임이 안 담긴다**
레꾸자랑 카드·표지 저장은 `html-to-image` 로 **한 장을 찍는 것**이라
움직이는 스티커는 **어느 한 순간**으로 굳어 찍힌다.
⚠️ 그 순간이 하필 **제일 기울어진 프레임**일 수 있다.
→ **규칙: 모션의 진폭을 작게.** 어느 프레임에서 멈춰도 이상해 보이지 않아야 한다.
  (그래서 `찰랑`은 ±4도, `냠냠`은 ±5%로 잡았다. 20도씩 도는 모션은 안 만든다)

### ③ 표지 한 장에 스티커가 **20장씩** 붙는다
애니메이션 20개가 동시에 돈다.
→ **`transform` 과 `opacity` 만 쓴다.** `width`·`top`·`margin` 을 애니메이션하면
  브라우저가 매 프레임 화면 배치를 다시 계산해서 **싼 폰에서 뚝뚝 끊긴다.**
→ `will-change` 는 모션 붙은 것에만(이미 `[class*="hk-m-"]` 한 줄로 제한해 뒀다).

### ④ **움직임 끄기**를 켠 사람은 아무것도 안 움직여야 한다
`@media (prefers-reduced-motion: reduce)` 로 모션·효과를 전부 끈다 (`styles.css` 맨 아래).
멀미·발작 유발을 피하는 접근성 기본이고, 스토어 심사에서도 본다.
→ **새 모션은 반드시 `hk-m-` / `hk-fx-` 접두어를 지킨다.** 그래야 저 한 줄에 같이 걸린다.

## 📌 새 모션·효과를 추가할 때 지킬 것 (체크리스트)

1. **배분표에 먼저 적는다** — 어느 팩·어느 달인지 정하고 나서 만든다. (안 그러면 무료로 새어 나간다)
2. **그 팩에 이미 하나가 있는지 본다** — 팩당 딱 하나.
3. `MOTIONS` / `FX_KINDS` 에 `pack` 과 `sheet`(시안 어디서 왔는지)를 같이 쓴다.
4. CSS 클래스는 **`hk-m-` / `hk-fx-` 접두어**로 (움직임 끄기에 같이 걸리게).
5. **`transform`·`opacity` 만** 애니메이션한다.
6. **진폭은 작게** — 캡처가 어느 프레임에서 멈춰도 괜찮게.

8. `npm run build` + `npm run smoke` 통과 (게이트가 팩당 1개를 강제한다).

## 🔧 이번에 같이 고친 것 — 여름·가을 꼬르곰·펭펭에 모션이 안 붙던 버그

> 창업자 2026-07-30: *"여름의꼬르곰펭펭(모션,효과 없어)"*

**원인.** 모션·효과를 붙일 대상을 **이름 규칙(`gp_` 로 시작)** 으로 판정하고 있었다.
그런데 여름 곰펭은 `sm_`, 가을 곰펭은 `au_b` 로 들어와서 **캐릭터인데 검사에 안 걸렸다.**
**네 군데**가 전부 같은 이름 규칙을 복사해 쓰고 있어서 **넷 다 동시에 빠졌다.**
(기본 모션 · 모션 바 노출 · 효과 렌더 · 붙일 때 모션 박기)

**고침.** 이름 대신 **이미 있는 분류(친구들 탭)** 로 판정한다.
```js
export const FRIEND_IDS = new Set(
  STICKER_GROUPS.filter((g) => g.tab === 'buddies').flatMap((g) => g.items),
)
```
→ 새 계절 곰펭을 어떤 이름으로 넣든 **친구들 탭에만 넣으면** 모션·효과가 자동으로 붙는다.

📌 **교훈: 이름 규칙(접두어)으로 분류하지 말고, 이미 있는 분류(탭)를 쓴다.**
같은 실수를 오늘 두 번 했다 — `asset-map.mjs` 의 `CAT()` 도 **라벨 글자**로 분류하다 깨졌다.
**표시용 이름은 분류 기준이 아니다.**

⚠️ 그리고 이 버그는 **게이트를 만들면서 네 번째 자리를 발견했다.** 손으로 셋을 고치고
"다 고쳤다"고 생각했는데, 게이트가 `DecorEditor.jsx` 의 네 번째를 잡아냈다.
**같은 규칙이 여러 곳에 복사돼 있으면, 눈으로는 반드시 하나를 놓친다.**

# ✅✅ 간판 팩 방식 = **채택 확정** (창업자 2026-07-31 *"이거 추천대로"*)

## 규칙 — 계절마다 **대표 팩 하나만** 새 모션·효과를 받는다
| 계절 | 간판 (새 축 1개) | 나머지 팩 |
|---|---|---|
| 가을 | **추석** | 가을 다꾸 · 수채화 · 핼러윈 |
| 겨울 | **크리스마스** | 설날 |
| 봄 | **벚꽃** | 여행 |
| 여름 | **물놀이** | 바다 |

- 새 축을 **1년에 4개만** 쓴다 → **지금 재고 9개로 2~3년.**
- 간판이 아닌 팩은 **배경**을 받는다(배경은 색×질감×빛이라 **재고가 거의 무한** · 그림 0장).
- ⛔ **한 계절에 새 축을 두 개 이상 쓰지 않는다.** 그러면 다시 1년 만에 바닥난다.
- ⛔ **이미 무료로 준 모션을 팩에 다시 넣지 않는다**(한 번 준 것은 안 빼앗는다).

## 왜 「계절 단위 번갈기」가 아니라 이것인가
창업자가 낸 대안은 *"가을팩에는 팩마다 1개씩 넣고 겨울에는 빠지고 대신 배경효과"* 였다.
⚠️ 그 경우 **겨울 팩이 전부 모션 없음**이라 그 계절을 산 사람이 손해 본 기분이 든다.
간판 방식은 **어느 계절에나 「움직이는 게 들어간 팩」이 하나는 있다.**

📋 배분은 `src/components/Stickers.jsx` 의 `MOTIONS`·`FX_KINDS` `pack` 필드와 **항상 같아야 한다**
(게이트 `scripts/test-motion.mjs` 가 팩당 1개를 강제한다).
