# 1️⃣ 팩당 모션 1개 + 효과 1개 ⭐ 규칙

## 왜 이렇게 하나

팩을 사는 이유가 **그림 몇 장**이면, 유저는 팩 하나만 사고 만다.
그림은 다음 팩과 비슷해 보이지만, **움직임은 눈에 확 띄고 한 번 쓰면 계속 쓴다.**
그래서 **팩마다 그 팩에만 있는 움직임 1 + 효과 1**을 붙인다.
→ *"그래야 골고루 사지"*(창업자)

## ⛔ 하면 안 되는 것

| 금지 | 왜 |
|---|---|
| 한 팩에 모션 3개 몰아 넣기 | 그 팩만 팔리고 나머지가 죽는다 |
| 이미 무료로 준 모션을 팩에 다시 넣기 | **한 번 준 것은 빼앗지 않는다** — 팩의 값어치도 0이 된다 |
| 모션 없는 팩 내기 | 팩끼리 구별이 안 된다 |
| 배분표와 코드가 어긋난 채로 두기 | 팩을 팔 때 뭐가 딸려 가는지 아무도 모르게 된다 |

# 3️⃣ 시안에 없는 것 — 내가 더 찾아서 정리한 것

> 창업자 *"저게 다는 아닐거 아냐."* → 시안은 **뭘 만들지**를 알려준다.
> 여기 적는 건 **우리 앱에서만 생기는 제약과 기회** — 시안엔 있을 수 없는 것들.

## ⚠️ 우리만의 제약 4가지 (모르고 만들면 사고 난다)

### ① 캐릭터가 **그림 1장**이라 부분 모션이 안 된다
눈 깜빡·입 벌리기·손 흔들기는 **눈/입/손이 따로 있어야** 한다.
우리 꼬르곰·펭펭은 통짜 PNG라 **몸 전체를 움직이는 것만** 된다.
→ 부분 모션을 하려면 **컷을 나눠서 다시 뽑아야** 한다(=자산 작업). 지금은 안 한다.

### ② 저장·공유 이미지에는 **움직임이 안 담긴다**
레꾸자랑 카드·표지 저장은 `html-to-image` 로 **한 장을 찍는 것**이라
움직이는 스티커는 **어느 한 순간**으로 굳어 찍힌다.
⚠️ 그 순간이 하필 **제일 기울어진 프레임**일 수 있다.
→ **규칙: 모션의 진폭을 작게.** 어느 프레임에서 멈춰도 이상해 보이지 않아야 한다.
  (그래서 `찰랑`은 ±4도, `냠냠`은 ±5%로 잡았다. 20도씩 도는 모션은 안 만든다)

### ③ 표지 한 장에 스티커가 **20장씩** 붙는다
애니메이션 20개가 동시에 돈다.
→ **`transform` 과 `opacity` 만 쓴다.** `width`·`top`·`margin` 을 애니메이션하면
  브라우저가 매 프레임 화면 배치를 다시 계산해서 **싼 폰에서 뚝뚝 끊긴다.**
→ `will-change` 는 모션 붙은 것에만(이미 `[class*="hk-m-"]` 한 줄로 제한해 뒀다).

### ④ **움직임 끄기**를 켠 사람은 아무것도 안 움직여야 한다
`@media (prefers-reduced-motion: reduce)` 로 모션·효과를 전부 끈다 (`styles.css` 맨 아래).
멀미·발작 유발을 피하는 접근성 기본이고, 스토어 심사에서도 본다.
→ **새 모션을 추가할 땐 반드시 `hk-m-` / `hk-fx-` 접두어를 지킨다.** 그래야 저 한 줄에 같이 걸린다.

## 📌 새 모션·효과를 추가할 때 지킬 것 (체크리스트)

1. **배분표에 먼저 적는다** — 어느 팩 건지 정하고 나서 만든다. (안 그러면 무료로 새어 나간다)
2. `MOTIONS` / `FX_KINDS` 에 `pack` 과 `sheet`(시안 어디서 왔는지)를 같이 쓴다.
3. CSS 클래스는 **`hk-m-` / `hk-fx-` 접두어**로 (움직임 끄기에 같이 걸리게).
4. **`transform`·`opacity` 만** 애니메이션한다.
5. **진폭은 작게** — 캡처가 어느 프레임에서 멈춰도 괜찮게.
6. 색은 **뮤트 톤**으로 (골드 `#d8b673` · 핑크 `#dc9aa1` · 크림 `#f1e8d6` 계열).
   흰 스티커 위에 흰 파티클을 놓지 않는다 → 눈(❄️)에 연회색 테두리를 준 이유.
7. `npm run build` + `npm run smoke` 통과.

## 🔧 이번에 같이 고친 것 — 여름·가을 꼬르곰·펭펭에 모션이 안 붙던 버그

> 창업자 2026-07-30: *"여름의꼬르곰펭펭(모션,효과 없어)"*

**원인.** 모션·효과를 붙일 대상을 **이름 규칙(`gp_` 로 시작)** 으로 판정하고 있었다.
그런데 여름 곰펭은 `sm_`, 가을 곰펭은 `au_b` 로 들어와서 **캐릭터인데 검사에 안 걸렸다.**
세 군데(`Stickers.jsx` 기본 모션 · `DecorEditor.jsx` 모션 바 · `DecorLayer.jsx` 효과 렌더)가
전부 같은 이름 규칙을 쓰고 있어서 **셋 다 동시에 빠졌다.**

**고침.** 이름 대신 **이미 있는 분류(친구들 탭)** 로 판정한다.
```js
export const FRIEND_IDS = new Set(
  STICKER_GROUPS.filter((g) => g.tab === 'buddies').flatMap((g) => g.items),
)
```
→ 새 계절 곰펭을 어떤 이름으로 넣든 **친구들 탭에만 넣으면** 모션·효과가 자동으로 붙는다.

📌 **교훈: 이름 규칙(접두어)으로 분류하지 말고, 이미 있는 분류(탭)를 쓴다.**
같은 실수를 오늘 두 번 했다 — `asset-map.mjs` 의 `CAT()` 도 **라벨 글자**로 분류하다 깨졌다.
**표시용 이름은 분류 기준이 아니다.**

## 🏷 같이 고친 것 — `리컬러 프레임` → `색 바꾸기`

> 창업자: *"프레임에서 리컬러프레임->색바꾸기로 바꿔줘 (데코랑 이름 같아야지)"*

데코 탭엔 `색 바꾸기` 그룹이 있는데 프레임 탭만 `리컬러 프레임` 이었다.
**같은 기능인데 이름이 다르면 같은 기능인 줄 모른다.**
'리컬러'는 우리끼리 쓰는 말이고, **유저가 보는 글자는 `색 바꾸기` 하나로 통일**한다.
