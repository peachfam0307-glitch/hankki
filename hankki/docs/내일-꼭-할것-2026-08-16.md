## ⑤ 🔓🔓 [제일 큼] 일기 잠금이 «잠금이 아니다» — 설계를 다시 짜야 한다

📮 창업자 2026-08-16 = *"그리고 **일기잠금 의미없어. 비번 잊으면 잠금 풀게 해뒀잖아.
누구든 비번 몇번 틀리면 잠금풀면 일기 다 봄**"* · *"**이것도 뭔가 다른방법이 필요해.**"*

⭐⭐⭐ **창업자 말이 정확히 맞다. 실물로 확인했다.** `src/components/LockSheet.jsx` 178~179줄 =
> *"되찾는 길이 없어서 **잠금을 아예 없애는 것**밖에 안 돼.
> 일기 글과 사진은 그대로 남아 — **잠긴 날들이 전부 다시 열릴 뿐이야.**"*

⛔⛔ **그 버튼은 비번을 «모르는» 사람도 누를 수 있다.**
「비번 잊었어요」 → 「잠금 없애기」 = **비번 없이 전부 열리는 정문**이다.
📌 폰을 빌려준 사람·가족·잃어버린 폰을 주운 사람 누구나 두 번 눌러 다 본다.

⛔⛔ **어제(v10.85) 내가 «우회 코드 안 만든다»고 CLAUDE.md 에 적어놓고,
정작 「잠금 해제」를 우회로로 만들어 뒀다.** 규칙을 적은 사람이 규칙을 어긴 자리다.

### 갈래 넷 — ⛔창업자 판정 필요(규칙 11 · 내 맘대로 고르지 않는다)

| | 방법 | 좋은 점 | 잃는 것 |
|---|---|---|---|
| ⒜ | **잠금 없애기 = 잠긴 일기를 «같이 지운다»** | 훔쳐볼 길이 사라진다 | 진짜 잊은 사람은 **내용을 잃는다** |
| ⒝ | **비번으로 «진짜 잠근다»(암호화)** | 제일 안전 — 비번 없이는 못 푼다 | 잊으면 **영영 못 본다.** 되돌릴 길 0 |
| ⒞ | **해제를 없애고 힌트만** | 코드가 가장 단순 | ⒝와 같은 위험인데 안전하진 않다(저장은 평문) |
| ⒟ | **지금 그대로 두고 «문구»만 정직하게** | 오늘 바로 됨 | **창업자가 지적한 문제가 그대로 남는다** |

⭐ **내 의견 = ⒜가 현실적이다.** 우리 원칙은 *"조용히 지우지 않는다"* 인데 ⒜는 **지운다고 미리 말하고 확인받는다.**
⒝는 «되돌릴 길 0»이라 백업까지 얽힌다(잠근 일기는 백업에서도 잠금이 풀린다 — 아래 참고).
⛔ **다만 정하는 건 창업자다.** 이 표를 그대로 들고 가서 고르게 한다.

⚠️ **같이 봐야 하는 것** — 백업에는 **잠금 비번이 안 들어간다**(`diaryLock.js` 가 localStorage 에 따로 둔다).
그래서 **백업 파일을 남에게 주면 잠근 일기가 그냥 읽힌다.** 잠금을 다시 짤 때 이 자리도 같이 정해야 한다.
(v10.92 에서 「옮긴 기기에선 잠금이 풀려요」라고 **알리기만** 해뒀다 — 알린 것이지 고친 게 아니다.)
