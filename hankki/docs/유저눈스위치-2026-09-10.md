# 👀 유저 눈으로 보기 — 스위치 (2026-09-10 · ⭐현행)

> 📮 창업자 = *"이게 나랑 유저랑 보이는 화면이 다르니까 테스트하기가 너무 어렵네"*
> → *"ㅇㅇ 유저 눈 스위치부터 만들어줘"* → *"유저 눈 스위치로 갈게"* → *"a로가"*

## 무엇인가

**설정 → 「유저 눈으로 보기」** — 운영자 폰을 «일반 유저»로 만들어 보는 스위치.
⛔ 운영자 표식(`hankki:founder`)이 있는 기기에만 보인다.

## 켜면 무엇이 바뀌나

| | 유저 눈 끔 | 유저 눈 켬 |
|---|---|---|
| 화면 | 운영자 배지 · 열쇠 ∞ | 일반 유저와 «똑같다» |
| 워커로 가는 운영자 열쇠 | 보낸다 | **안 보낸다** (hankki-ocr · hankki-tidy 둘 다) |
| 개인 한도(월 5장) | 우회 | **진짜로 받는다** |
| 계기판의 「창업자」 | 오른다 | **안 오른다** |
| 통계(GA4) | `internal` | **`internal` 그대로** ⭐ |

⭐ **통계만 «일부러» 스위치를 안 따른다** — 창업자가 눌러 보는 것이 「유저 행동」으로 쌓이면 숫자가 망가진다.
　 (창업자 물음 = *"유저 눈 스위치 켜면 통계도 안 잡히게 되는거야?"* → 아니다)

## ⚠️ 되돌리기 — «표시»만 되돌아온다

스위치를 끄면 화면은 무제한으로 돌아오지만 **그동안 쓴 열쇠는 안 돌아온다.**
워커가 「남은 수」가 아니라 **«쓴 수»를 기기 통(`d:<uid>` · `a:<sub>`)에 누적**하기 때문이다.

📌 그래서 **「열쇠가 다 떨어져 막히는 화면」은 그 달에 사실상 «한 번»** 볼 수 있다.
　 여러 번 봐야 하면 **시크릿 모드**로 본다(기기 번호가 새로 생긴다).

## ⛔⛔ 처음엔 «반쪽»이었다 — 옷만 갈아입고 신분증은 그대로 냈다

첫 판(v13.11 시도)은 **화면만** 바꾸고 서버로는 계속 운영자 열쇠를 보냈다. 그래서 —
⑴ 계기판의 「창업자」가 계속 올랐다 (9월 실측 = 창업자 42 · 유저 12)
⑵ 서버가 「무제한」이라 답해 **「사진 고르기」 선택 창이 안 뜨는 버그가 그대로 남았다**

🔎 뿌리 = **다섯 곳이 각자 `localStorage` 를 직접 읽어** 유저 눈을 아예 안 봤다.
✅ `ocr.js` 의 `열쇠헤더()` **한 곳**으로 모았다 ＋ `tidy.js` 도 같은 잣대.

## 🐛 파다가 물은 «진짜 버그» 셋

| 버그 | 무슨 일이 나나 | 고침 |
|---|---|---|
| **운영자 열쇠에 ASCII 밖 글자** | HTTP 헤더는 ISO-8859-1 만 싣는다 → `fetch` 가 통째로 죽어 **AI 읽기·다듬기가 아무 말 없이 먹통** | 못 실을 열쇠는 «안 싣고 그냥 보낸다» (절대원칙 34 — 실패의 모양을 바꿨다) |
| **주소의 `＋` 가 공백이 된다** | `URLSearchParams` 가 `+` 를 공백으로 디코드 → 조용히 «다른 열쇠»가 되어 서버에서 탈락. ASCII 검사는 통과한다 | 주소 원문에서 그대로 떼어 쓴다 ＋ `trim()` |
| **`saveOcrLeft` 가 서버의 「무제한」을 버렸다** | 창업자 확정 ⓐ(2026-09-02 *"서버가 말해준다"*)가 **한 번도 안 돌고 있었다** | 담는다 |
