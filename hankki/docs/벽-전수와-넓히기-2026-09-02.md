# 🧱 벽을 «전부» 세어봤다 — 언제 닿고, 어떻게 넓히나 (2026-09-02 · ⛔지나간 판단이다 — 맨 아래 「수만 명 시험」이 현행)

> 📮 창업자 = *"5mb찰때마다 설계해야하는거야?"* · *"그럼 본질적인 걸 바꾸는거야? 용량넉넉하게"*
> 　　*"설계를 할때는 **좁게보지말고 넓게봐야해.** 다음에 또 이런상황이 벌어지지않을까. **그 시점이 언제인가.**
> 　　계속 반복하는 작업을 하지않게 넓게 설계를 해야지. **유저는 계속 늘어날거고, 갑자기 늘어날 수도 있잖아.**"*

⛔ **내가 두 번 좁게 봤다.**
　⑴ 아침 = *"캡처가 4.7MB 를 먹는다"* → 전수로 세니 **자랑카드가 1등**이었다
　⑵ 낮 = *"폰 서랍 5MB 를 넓히자"* → 창업자가 짚은 건 **「유저가 늘면 어디가 먼저 터지나」**였다. **그건 다른 벽이다.**

📌 그래서 이번엔 **벽을 전부 세고, 각각 「몇 명에서 닿나」를 숫자로** 냈다.

---

## 1️⃣ 벽 일곱 — 전수

| | 벽 | 지금 값 | 누구 것 | 유저 수에 비례? |
|---|---|---|---|---|
| **A** | **폰 서랍 `localStorage`** | **5MB** | 유저 각자 폰 | ❌ 각자 |
| **B** | 폰 창고 `IndexedDB` | 기기 여유의 일부(창업자 폰 = 10.5GB 중 289MB 씀) | 유저 각자 폰 | ❌ 각자 |
| **C** | **사진에서 글자 읽기**(Google Vision) | **전역 월 900** (무료 1,000 아래) | 우리 | ✅✅ |
| **D** | **AI 정리**(Workers AI) | **전역 하루 200** (무료 ≈260) | 우리 | ✅✅ |
| **E** | 워커 요청 수 (Cloudflare) | 하루 10만 | 우리 | ✅ 여유 큼 |
| **F** | **클라우드 저장**(Firestore 무료) | 저장 1GiB · **읽기 5만/일** · 쓰기 2만/일 | 우리 | ✅✅ |
| **G** | 웹 내려받기(GitHub Pages) | 월 100GB 안팎(⚠️**확인 못 함**) | 우리 | ✅ |

## 2️⃣ ⭐ 「그 시점이 언제인가」 — 유저 수로 환산

| 벽 | 닿는 시점 | 셈 근거 |
|---|---|---|
| **A 폰 서랍** | **🔴 이미 닿았다** (창업자 폰 4.88MB) | 자랑카드 5~7장 **또는** 일기 4장 **또는** 캡처 65장 |
| **D AI 정리** | **🟠 하루 «활발한» 40~67명** | 한 명이 하루 3편 정리 = 200÷3 ≈ 67명. 사진 경로는 **C 의 일 120** 이 먼저 막아 ≈40명 |
| **C 글자 읽기** | **🟠 새 유저 45명** (몰려오면) / 꾸준하면 월 180명 | 웰컴 20장을 다 쓰면 900÷20 = **45명**. 정상 사용(월 5장)이면 900÷5 = 180명 |
| **F 클라우드 읽기** | **🟡 하루 200명** | 켤 때 레시피 250편을 읽으면 1인 250회 → 50,000÷250 |
| **F 클라우드 저장** | 🟢 5,000명 | 글자만 1인 0.2MB → 1GiB |
| **E · G** | 🟢 훨씬 뒤 | |

### 🚨 그래서 순서가 이렇다
```
지금        A 폰 서랍 (터짐)
40~70명     D AI 정리가 마른다
45~180명    C 글자 읽기가 마른다
200명/일    F 클라우드 읽기
```
⭐⭐ **유저 100명 안쪽에서 C·D 가 먼저 마른다. IndexedDB 는 그 벽과 아무 상관이 없다.**
　 창업자 물음(*"갑자기 늘어나면"*)이 정확히 이 자리를 짚은 것이다.

---

## 3️⃣ 닿으면 «무슨 일»이 나나 — 이게 제일 중요하다

| 벽 | 닿으면 | 나쁨 |
|---|---|---|
| **A 폰 서랍** | ⛔**데이터를 잃는다** — 저장이 통째로 실패 | 🔴🔴 **제일 나쁘다** |
| **D AI 정리** | 규칙 파서 판으로 나간다(재료 0개일 수 있다) | 🟠 값이 깎인다 |
| **C 글자 읽기** | **기본 인식(무제한)으로 계속 된다** | 🟢 **안 끊긴다** — 이미 설계돼 있다 |
| **F 클라우드** | 그날 동기화가 멎는다(폰 데이터는 그대로) | 🟠 |
| **E · G** | 느려지거나 잠깐 안 열린다 | 🟠 |

⭐⭐ **핵심 = 「잃는」 벽은 A 하나뿐이다.** 나머지는 **깎이거나 멎을 뿐 안 잃는다.**
　 📌 그러니 **A 를 먼저 없애는 게 맞다.** 그건 좁게 본 게 아니라 «제일 나쁜 것 먼저»다.

## 4️⃣ ⭐⭐ 「반복하지 않으려면」 — 본질은 «넓히기»가 아니라 «미리 아는 것»

📮 창업자 = *"계속 반복하는 작업을 하지않게"*

⛔ **오늘 왜 반복이 됐나** — 벽에 닿은 걸 **창업자가 데이터를 잃고서야 알았다.**
　 값을 키워도 언젠가 또 닿고, 그때도 **터지고 나서** 안다. **키우기만 해선 반복이 안 끝난다.**

✅ **끝내는 법 = 벽마다 「몇 % 찼나」를 재고, 차기 «전»에 우리가 안다.**

| 벽 | 계기판이 있나 | 누가 언제 |
|---|---|---|
| **C 글자 읽기** | ✅ **있다** — `?quota=1` 「이번 달 몇 건 / 900」 | 창업자 확정 2026-08-31 *"이건 꼭 해야해"* |
| **D AI 정리** | ✅ **있다** — 「오늘 몇 편 / 200」 | 〃 *"tidy도 붙여줘"* |
| **A 폰 서랍** | ⛔ **없다** ← **오늘 사고의 뿌리** | — |
| **F 클라우드** | ⛔ 없다 | — |

📌 **창업자가 8/31 에 이미 이 답을 냈다.** 그때 워커 둘에 계기판을 붙였고, **폰에만 안 붙였다.**
　 오늘 터진 곳이 정확히 그 «안 붙인 곳»이다.

## 5️⃣ ▶️ 그래서 할 일 — 넓게, 세 겹

### 🥇 1겹 · **잃는 벽(A)을 없앤다** — 이번 판
| | |
|---|---|
| ⓐ **버그 셋** | 축소 루프가 자랑카드를 뭉개고 클라우드에서 사라지게 하는 것 ／ 임시저장이 주석과 달리 사진을 담는 것 ／ 캡처 수명(창업자 확정) |
| ⓑ **사진을 IndexedDB 로** | 5MB → **기기 여유**(창업자 폰 기준 사진 **수만 장**). ⭐**유저 수와 무관하게 영구히** 안 찬다 |
| ⓒ **폰 계기판 ＋ 경보** | 설정에 「저장 공간 ○○%」 ＋ **80% 에서 미리 알린다.** ⛔지금은 100% 에서 «잃고 나서» 안다 |

### 🥈 2겹 · **마르는 벽(C·D)에 «미리» 대비** — 다음 판
| | |
|---|---|
| ⓓ **통이 마르기 «전»에 우리가 안다** | 계기판은 있는데 **아무도 안 본다.** 70% 넘으면 창업자에게 알리는 길을 만든다 |
| ⓔ **마를 때 유저에게 정직하게** | C 는 이미 됨(기본 인식). **D 는 조용히 멎는다** → 「지금은 규칙으로 정리했어요」를 말해야 한다 |
| ⓕ **한도를 올리는 건 «돈»** | 무료 티어를 넘기면 과금. ⛔**창업자 판정**(9월 결제와 한 몸) — 내가 못 정한다 |

### 🥉 3겹 · **클라우드(F)는 «설계로» 미리 막는다** — 클라우드 만들 때
| | |
|---|---|
| ⓖ **바뀐 것만 읽는다** | 켤 때 250편을 다 읽으면 1인 250회 → 하루 200명이 벽이다. `updatedAt` 으로 «바뀐 것만» 읽으면 1인 수 회 → **수천 명까지 간다** |
| ⓗ | 이건 **이미 구현계획에 있다** — 잊지만 않으면 된다 |

## 6️⃣ ⛔ 안 하는 것 (넓게 봐도 «지금은» 아니다)
· **글자까지 IndexedDB 로** — 글자는 다 합쳐 0.2MB 라 벽과 무관. 앱 «켜는 길»을 바꾸는 위험만 진다
· **일기 사진·decor 를 더 줄이기** — 벽(A)이 없어지면 **안 해도 되는 일**이 된다
· **C·D 한도 올리기** — 돈이 든다. 창업자 판정 · 9월 결제와 한 몸
· **서버를 우리가 새로 세우기** — 지금 구조(무료 티어 안)가 «돈이 안 나가는» 유일한 이유다

# 📈 수만 명 시험 — 절대원칙 32 로 다시 쟀다 (2026-09-02 · ⭐여기가 현행이다)

> 📮 창업자 = *"**절대원칙 설계기조는 유저가 수만명이되어도 문제없이 돌아가게 만든다야. 근시안적인 설계는 지양.**"*

⛔ 위 절(1️⃣~7️⃣)은 **유저 200명까지**만 봤다. **1만 명을 넣어 다시 잰다.**

## 🔢 유저 1만 명이면 — 벽마다

| 벽 | 1만 명이면 | 판정 |
|---|---|---|
| **A 폰 서랍 / B 폰 창고** | 유저 «각자» 폰이다 — **1만 명이든 100만 명이든 값이 같다** | ✅ **유저 수 무관** |
| **C 글자 읽기** 월 900 | 월 5장씩만 써도 **월 5만 건 필요** (56배) | ⛔ **무너진다** |
| **D AI 정리** 하루 200 | 하루 1편씩만 정리해도 **하루 1만 편** (50배) | ⛔ **무너진다** |
| **E 워커 요청** 하루 10만 | 1인 하루 10회 = **딱 10만** | ⚠️ **아슬아슬** |
| **F 클라우드 저장** 1GiB | 1인 글자 0.2MB × 1만 = **2GB** | ⛔ 넘는다 |
| **F 클라우드 읽기** 5만/일 | 켤 때 250편을 읽으면 1인 250회 → **250만/일** | ⛔⛔ **50배 무너진다** |
| **G 웹 내려받기** | 첫 방문 4.1MB × 1만 = **41GB/월** | ⚠️ 여유는 있으나 급증 시 위험 |

## ⭐⭐ 그래서 «구조»로 갈리는 것 셋

### ㉠ **폰 안에서 도는 일 = 수만 명이 와도 그대로다** ← 지키자
레시피 저장·보기·꾸미기·일기·타이머는 **서버를 한 번도 안 부른다.**
📌 **이게 우리 최대 강점이다.** ⛔그 일들을 서버로 옮기는 설계를 하지 않는다 — 옮기는 순간 **유저 수가 곧 돈**이 된다.
⭐ **그래서 「사진을 폰 창고(IndexedDB)로」는 근시안이 아니다** — 수만 명에서도 값이 안 변하는 «옳은 쪽»이다.

### ㉡ **전역 상한은 수만 명에서 «불공평하게» 터진다** ← 고쳐야 한다
지금 C·D 는 **전역**(월 900 · 하루 200)이다. 1만 명이면 **먼저 온 45명이 다 쓰고 나머지 9,955명은 «AI 가 아예 안 되는 앱»을 본다.**
⛔ 그건 「모자란 것」이 아니라 **「망가진 것」으로 보인다.**
✅ **유저당 한도가 주 잣대**가 되어야 하고, 전역은 **비용 방어용으로만** 남긴다(＝지금 있는 `PER_USER_MONTHLY` 를 앞세운다).
⚠️ 그러면 **비용이 유저 수에 비례해 늘어난다** → 🔢 Vision 2원/건 × 월 5장 × 1만 명 = **월 10만원**. ⛓**결제와 한 몸**(창업자 판정).

### ㉢ **읽기가 「유저 수 × 데이터 수」로 늘면 반드시 죽는다** ← 설계로 막는다
F 읽기가 **50배**로 제일 크게 무너진다. 뿌리는 **켤 때마다 전부 읽는 것**이다.
✅ **바뀐 것만 읽는다**(`updatedAt`) → 1인 250회 → **수 회**. 같은 5만/일로 **수천~수만 명**까지 간다.
📌 이건 **이미 구현계획에 있다** — 클라우드를 만들 때 **반드시** 지킨다.

## ✅ 그래서 이번 판(1겹)은 «근시안이 아니다» — 다시 확인했다
| 하는 것 | 수만 명 시험 |
|---|---|
| 사진 → 폰 창고(IndexedDB) | ✅ 유저 수 무관 · **영구** |
| 폰 계기판 ＋ 80% 경보 | ✅ 유저 수 무관 · **「미리 아는」 장치** |
| 버그 셋(카드·임시저장·캡처 수명) | ✅ 유저 수 무관 |

## ⏭ 수만 명을 위해 «추가로» 해야 할 것 (이번 판 밖 · 순서대로)
| 순 | 무엇 | 왜 |
|---|---|---|
| **1** | **C·D 를 「유저당」이 주 잣대가 되게** | 전역만이면 수만 명에서 **불공평하게 터진다**(㉡) |
| **2** | **클라우드는 «바뀐 것만» 읽기** | 안 하면 **50배**로 죽는다(㉢) · 만들 때 같이 |
| **3** | **C·D 통 70% 경보** | 마르기 «전»에 우리가 안다 |
| **4** | **무료량 × 유저 수 = 비용**을 결제 판정에 넣는다 | 월 5장 × 1만 명 = **월 10만원** |
| **5** | 웹 내려받기(G) 실제 한도 확인 | ⚠️**아직 확인 못 했다** — 숫자를 모른다 |

⛔ **1~4 를 「나중에」로 미루되 «잊지 않게» 여기 적어 둔다.** 유저 40명에서 계기판이 먼저 알려준다.
