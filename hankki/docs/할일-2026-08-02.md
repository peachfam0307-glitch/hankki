## 🐛 새로 들어온 버그 — **레시피 가져오기에서 사진 2장 → 1장만 들어온다** (2026-08-02 창업자 폰)

> *"**공유가 아니라 레시피 가져오기에서 2장 가져오면 1장만 입력된다고.**"*

⛔ **내가 처음에 「공유 2장」으로 잘못 적었다.** 창업자가 바로잡아줬다 — **가져오기(OCR)** 쪽이다.
⭐ **긴 레시피는 캡처가 2~3장이 되는 게 흔하다** → 재료는 1장, 순서는 2장에 있는 식.
   **한 장만 들어오면 레시피가 반쪽이 된다.**

### 🔎 코드상 후보 둘 (근거 줄번호까지)

**ⓐ 이미 찬 칸은 «덮지 않는다» — `EditorScreen.jsx` 260~261줄** ⭐가장 유력
```js
ingredients: prev.ingredients.trim() || r.ingredients.join('\n'),
steps:       prev.steps.trim()       || r.steps.join('\n'),
```
→ **1장 올려 채워진 뒤 2장째를 올리면 통째로 무시된다.** (`||` 라서 앞이 차 있으면 뒤를 안 본다)

**ⓑ `ocr.busy` 가드에 두 번째 장이 씹힌다 — 같은 파일 221줄**
```js
const runOcr = async (img) => { if (!img || ocr.busy) return   // ← 여기
```
→ 225줄에서 `setOcr({busy:false})` 하지만 **React state 갱신은 비동기**다.
   237줄이 곧바로 `setCropImg(다음 장)` 을 하므로, 두 번째 `runOcr` 가 **busy=true 로 읽고 조용히 리턴**할 수 있다.

✅ **설계 자체는 맞게 돼 있다** — 199줄에서 여러 장을 받고, 206줄에서 대기열에 넣고,
   233줄에서 `ocrAccum` 에 텍스트를 모아 **마지막에 한 번에 파싱**한다. `multiple` 도 붙어 있다(362줄).
   **그러니 「기능이 없는 것」이 아니라 「어딘가에서 끊기는 것」이다.**

### 내일 갈라볼 것 (재현 5분이면 갈린다)
1. **한 번에 2장 선택** — 두 번째 크롭 화면이 뜨나? → 안 뜨면 **ⓑ**
2. **1장 하고 또 1장** — 두 번째가 무시되나? → 그러면 **ⓐ**
3. 둘 다면 **둘 다 고친다** (ⓐ는 「이어붙이기」로, ⓑ는 ref 로 busy 관리)

📌 이미 **`appendLines`(212줄)** 라는 이어붙이기 함수가 있다 — 지정 칸(`ingredients`/`steps`)엔 쓰는데
   **자동 분류(`all`) 경로에선 안 쓴다.** 고칠 때 그 함수를 그대로 쓰면 된다.
