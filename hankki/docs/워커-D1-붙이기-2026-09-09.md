## 📋 순서 — 세 단계

### ① 창고 만들기

```
Cloudflare 로그인
 → 왼쪽 메뉴 「Storage & Databases」 (저장소·데이터베이스)
 → 「D1 SQL Database」
 → 「Create Database」 단추
 → 이름칸에  hankki  라고 적기
 → 만들기
```

⭐ **표(테이블)는 안 만들어도 된다** — 워커가 처음 돌 때 스스로 만든다.

### ② 워커에 이어 붙이기

```
왼쪽 메뉴 「Compute」 → 「Workers & Pages」   ⛔ 2026-09-09 실물 확인 — 화면엔 「Workers & Pages」라고 적혀 있다
 → hankki-ocr 고르기
 → 「Settings」(설정) 탭
 → 「Bindings」(바인딩)
 → 「Add binding」(추가) 단추
 → 「D1 database」 고르기
 → Variable name 칸에  DB  라고 적기      ⛔ 대문자 DB · 다른 이름이면 안 붙는다
 → D1 database 칸에서  hankki  고르기
 → 「Add binding」 으로 마무리
```

### ③ 코드 붙여넣기

```
같은 화면에서 「Edit Code」(편집)
 → 코드 «전체» 지우고 → 클로드가 준 파일 붙여넣기
 → 「Deploy」(배포)
```

## ✅ 다 됐는지 확인하는 법

폰 브라우저로 이 주소를 연다 (열쇠는 클로드에게 물어볼 것):

```
https://<워커주소>/?quota=1&key=<열쇠>
```

⛔ **그 주소를 채팅·저장소에 적지 않는다** — 열쇠가 딸려 간다.

숫자가 «전과 비슷하게» 나오면 잘 된 것이다.

## 🔢 왜 D1 인가 — 실측으로 골랐다 (2026-09-09)

📮 창업자 = *"내가 정한거는 그때의 ai가 정해준거고 지금또 달라졌을 수있으니까
테스트해서 더 리스크,구멍이 없는걸로 해야지"*

같은 조건(같은 사진 동시 2·5·20개 · 60판)으로 셋을 재봤다:

| 창고 | 틀린 횟수 | 빠르기 |
|---|---|---|
| **KV** (지금 쓰는 것) | ⛔ **20번 중 3번** (열쇠 2장 깎임) · 들쭉날쭉 | 5ms |
| DO | ✅ 0번 | 3ms |
| **D1** | ✅ **0번** | **3ms** |

**정확도가 같아서 나머지로 갈렸다:**
1. 청소가 **한 줄**이다 (DO 는 유저마다 알람이 돌아야 한다 — 3000명이면 알람 3000개)
2. 창업자가 이미 「결제·잔량은 Worker ＋ D1」로 확정해 뒀다 (2026-08-19·20)
3. 나중에 전역 900 세기도 같은 표에서 고칠 수 있다

⚠️ **정직하게 — D1 이 나쁜 점**: 데이터베이스가 «하나»라 아주 많아지면 DO 보다 먼저 밀린다.
월 46건이라 한참 여유롭다. 수만 명이 되면 그때 다시 잰다.
