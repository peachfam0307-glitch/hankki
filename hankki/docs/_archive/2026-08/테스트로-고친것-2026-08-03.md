⛔ **이걸 「테스터 피드백」으로 포장하면 거짓말이다.**

✅ **대신 이렇게 쓴다** — 「실기기 테스트에서 발견 → 고침 → 새 버전 배포」. 그것도 **테스트다.**

## 6️⃣ 🤖 그리고 «다시 안 나게» 만든 장치

⭐ **이게 3부 ②번(「프로덕션 준비됐다고 어떻게 판단했나」)의 답이기도 하다.**
고친 것만 나열하면 *"많이 깨졌었네"* 로 읽힌다 — **「같은 게 다시 안 나게 했다」가 준비됐다는 근거다.**

배포 전에 자동으로 도는 검사 **14개**:

| 검사 | 막는 것 |
|---|---|
| 저장 스모크 | 핵심 흐름이 터지면 배포 차단 |
| 해상도 · 컷 검수 | 그림이 깨지거나 잘리면 차단 |
| 음식 탭 | 중복·깨진 참조·빈 이름표 |
| 문체 · 화면 글자 | 말투 어긋남 · 코드 부스러기 노출 |
| 파서 · 링크 규칙 | 레시피 인식 회귀 |
| 종료 · 모션 · 제철 · 카드 제목 | 각 기능 회귀 |
| 이번 주 레시피 재고 | 「매주 온다」 약속이 끊기기 전에 |

📌 **하나라도 실패하면 배포가 안 나간다.** 이건 자랑이 아니라 **되풀이를 구조로 막은 것.**

## 7️⃣ 📝 답변 초안 (3부 ①번 · 8/16에 다듬어 쓴다)

⭐⭐ **「우리는 계속 해왔다」가 이 답변의 뼈대다** (창업자 2026-08-03 *"그런 부분을 어필해봐 우리는 계속 해왔다고"*).
   목록만 나열하면 *"많이 깨졌었네"* 로 읽힌다. **「받는다 → 고친다 → 내보낸다」가 멈춘 적이 없다**를 보여준다.

> 저희는 **의견을 받고 고쳐서 새 버전을 내보내는 일을 테스트 기간 내내 멈추지 않았습니다.**
> 테스트를 시작한 7월 17일부터 지금까지 **앱 버전을 8.5에서 9.46까지 올렸고, 그 사이 결함 23건을 수정**했습니다.
>
> **① 사용자 의견으로 기능을 만들었습니다.**
> *"기능이 많은데 처음엔 뭐가 있는지 모르겠다"* 는 말을 듣고 **첫 방문 안내 기능**을 만들었으며, 이후 장보기·공유 화면까지 넓혔습니다.
> *"배경이 단조롭다"* 는 의견에는 **움직이는 배경**을 새로 만들어 추가했습니다.
> *"음식 사진이 있으면 좋겠다"* 는 의견으로 만든 **음식 그림 자동 표시 기능**은 테스트 기간 중 34종을 더해 218종까지 늘렸고,
> *"추천 식재료가 더 다양했으면 좋겠다"* 는 의견에는 품목을 늘리고 레시피 재료와 자동으로 연결되게 개선했습니다.
>
> **② 실제 기기에서 쓰며 결함을 찾아 그때마다 고쳤습니다.**
> 가장 심각했던 것은 **레시피 저장이 되지 않던 문제**로, 특정 버전부터 저장이 전부 실패하고 있었습니다.
> 그 밖에 앱이 정상적으로 종료되지 않던 문제, 저장 버튼이 반응하지 않는 것처럼 보이던 문제,
> 이미지가 흐리게 표시되던 문제, 레시피 텍스트 인식 오류 등을 수정했습니다.
>
> **③ 정확하지 않은 안내를 걷어냈습니다.**
> 실제로는 이미 동작하는데 「곧 출시」로 표시되던 기능을 바로잡고,
> 링크 자동 인식처럼 결과가 부정확한 기능은 **정확해질 때까지 비활성화**했습니다.
> 사용자에게 부정확한 정보를 주느니 기능을 끄는 쪽을 택했습니다.
>
> **④ 같은 문제가 다시 나오지 않도록 만들었습니다.**
> 저장 오류를 고친 뒤에는 **같은 종류의 오류가 있으면 배포 자체가 중단되도록** 자동 검사를 추가했고,
> 이런 검사를 하나씩 늘려 현재 **배포 전에 14가지 검사**가 실행됩니다. 하나라도 실패하면 배포가 진행되지 않습니다.
>
> 저희에게 테스트는 마지막 점검 절차가 아니라 **앱을 만드는 방식 그 자체였습니다.**

📌 **왜 이 순서인가** — ①의견 → ②찾아 고침 → ③정직하게 걷어냄 → ④되풀이 차단.
   **「받는다 → 고친다 → 안 되풀이한다」가 한 흐름으로 읽힌다.** 각각 따로 쓰면 그냥 목록이 된다.
⭐ 마지막 한 줄이 이 답변의 핵심이다. 창업자가 실제로 그렇게 해왔다.

⚠️ **여기엔 「품앗이 테스터가 알려줬다」는 말을 넣지 않았다** — 사실이 아니다.
   품앗이는 서로 설치·실행을 해주는 관계지 리뷰를 주고받는 사이가 아니다
   (창업자: *"누군지도 모르고 덧글로 주고받는 사람들인데 리뷰를 어떻게 부탁하라는거야"*).
   ⛔ **그쪽엔 아무것도 더 부탁하지 않는다.**
✅ **대신 가족·지인 의견이 있다** — 그건 ↓ 8️⃣ 에 따로 쓴다.

## 8️⃣ 📝 답변 초안 (파트1 ③번 · *"받은 의견 요약 + 수집 방법"*)

⭐ **8/02엔 이 칸을 *"자세한 피드백 없었다"* 로 끝냈다. 그게 제일 아까웠다 — 실은 있었다.**

> 의견은 두 가지 경로로 받았습니다.
>
> **첫째, 실제 사용자에게 직접 들었습니다.** 가족과 지인이 앱을 써 보고 준 의견으로 세 가지를 만들었습니다.
> ① *"기능이 많은데 처음엔 뭐가 있는지 모르겠다"* → 첫 방문 시 핵심 기능을 짚어주는 **안내 기능**을 만들었고, 테스트 기간 중 장보기·공유 화면까지 넓혔습니다.
> ② *"레시피에 음식 사진이 있으면 좋겠다"* → 제목을 입력하면 **음식 그림이 자동으로 붙는 기능**을 만들었고, 테스트 기간 중 34종을 더해 218종까지 늘렸습니다.
> ③ *"추천 식재료가 더 다양했으면 좋겠다"* → 큐레이션 품목을 늘리고, 레시피 재료와 자동으로 연결되도록 개선했습니다.
> ④ *"배경이 단조로워서 움직이는 효과가 있으면 좋겠다"* → **움직이는 배경**을 만들어 테스트 기간 중 추가했습니다.
>
> **둘째, 앱 안에 상시 창구를 두었습니다.** 설정 화면의 '한끼연구소'에서 의견·설문·오류 신고를 받고 있으며, 별도의 익명 설문 링크도 함께 운영합니다. 로그인 없이 익명으로 보낼 수 있습니다.
>
> 이 밖의 결함은 대부분 개발자가 실제 기기에서 사용하며 직접 발견했고, 그때마다 수정해 새 버전을 배포했습니다.

⚠️ ⛔ **「비공개 테스트 중에 처음 들었다」는 표현은 쓰지 않는다** — ②③은 테스트 시작 전에 시작했다.
   대신 **「테스트 기간 중 넓혔다」**는 사실 그대로 쓴다.
⚠️ 접수 건수를 쓰려면 **창업자가 구글 폼 응답 탭을 확인**해야 한다(저장소는 모른다).
