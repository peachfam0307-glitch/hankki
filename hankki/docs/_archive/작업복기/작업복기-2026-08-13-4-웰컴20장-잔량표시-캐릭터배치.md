## 2️⃣ 📢 잔량 표시 — 「카운트가 안 된다」의 진짜 원인

- 창업자 *"글자안나오는데"* → 내가 OCR 문제로 오해 → 창업자 *"**아니 카운트가 안된다고**"*.
- 🔎 원인 = **서버는 `left` 를 매번 보내고 있었는데 앱이 `data.text` 만 꺼내 쓰고 그 줄을 통째로 버렸다**(`src/ocr.js`).
- ✅ 배관을 잇고 `getOcrLeft()` 를 만들었다. 화면 = **「가져오기」 제목 바로 아래 맨 위**.
  - ⛔ 첫 판은 아래쪽 카드 «안»에 넣었다가 창업자가 물렸다 — *"너무 안보여. 가져오기 바로 아래넣어야지"*.
- 상태마다 문구가 다르다(여기서 오해가 나면 곧장 분쟁이 된다):
  | 상태 | 문구 |
  |---|---|
  | 웰컴 중 | **처음 한 번만** 드리는 20장이에요 / 다 쓰면 **매달 무료 5장** |
  | 웰컴 소진 후 | 매달 5장씩 채워져요 |
  | 3장 이하 | 다 써도 기본 인식으로 계속 읽어 드려요 |
  | 0장 | 이번 달 무료 AI 스캔을 다 썼어요 / 기본 인식으로 계속 / 다음 달에 **무료 5장** |
- ⛔⛔ **「익월부터」로 못박지 않는다** — 8월에 17장만 쓴 사람은 이월된 3장을 9월에 쓰고 **그 9월에 2장 더** 쓴다(worker 실측).
  「다 쓰면(조건) · 매달(주기)」만 두 경우 다 맞다.

## 4️⃣ 🔢 카운트 설계 — 「사진 1장 = 1장」 최종 확정

- 창업자 *"스캔했다가 취소해도 카운트되는거지?"* → 「한 묶음 = 1장」 코드를 만들었다(worker `b:{uid}:{batch}` KV).
- ⛔ **그런데 안 쓰기로 정했다** — 창업자 *"리스크를 감수하고싶진않은데.."* → *"그래 원래대로 1장에 1장 하자. 2장레시피 잘없기도하고 있어도 50원이야;;"*
  - 8/16 재신청 사흘 앞이라 **서버를 안 건드린다.**
- ✅ 대신 **안내를 정확히** — 2장 이상 고른 직후 토스트 `사진 2장이라 AI 스캔 2장을 써요` ＋ 안내 상자 「사진 1장에 AI 스캔 1장씩」.
- ⛔⛔ **내가 확인 없이 「저장 안 해도 카운트가 맞다」고 답했다** — 문서엔 **반대로**(「저장 성공 시 1 차감」) 적혀 있었다. 정정 후 판정 요청.

## 6️⃣ 📐 패드에서 터진 것들

- 뿌리 = **비율(%) 기반 폭**. `flex: 0 0 41%` 가 폰 168px → 패드 500px+ 가 된다(정사각 썸네일이라 높이도 같이 커져 세로 스크롤 여백이 사라진다).
- 고친 것 = 홈 두 상자(3칸 고정 → `auto-fit` ＋ 가운데 모음) · 장보기 좌우 2단 · 가로 목록 카드 상한 200px · 앨범 격자 · 레시피 상세 왼쪽 칸 고정.
- ⛔⛔ **「float 요소에 `position: sticky` 가 먹는다」고 잘못 단언했다** — 안내 코치가 떠서 **스크롤 자체가 안 된 상태**로 쟀다.
  코치를 닫고 재니 스크롤 900에서 y=−461. ✅ 래퍼 `.cover-col` 을 만들어 래퍼에 걸었다.

## ⛔ 오늘 내가 틀린 것 (되풀이 금지)

1. **「카운트 안 된다」를 OCR 문제로 오해** — 창업자가 두 번 말해야 알아들었다.
2. **확인 없이 「저장 안 해도 카운트가 맞다」고 답함** — 문서엔 반대로 적혀 있었다.
3. **「1년 가까이」는 지어낸 기간** — 2026-07-26 확정 → 08-13 구현 = **18일**. 스티커 문서의 「1년 가까이」도 실제로는 **7일**이었다.
4. **「310개 문체를 고쳐야 한다」** — 실제는 **111편 중 1개**. `basics.js` 가 자동 변환하는 걸 확인 안 했다.
5. **「float 에도 sticky 가 먹는다」** — 스크롤이 막힌 상태로 쟀다.
6. **옛 매끈 곰을 새 자리에 씀** — 핀에 금지라고 박혀 있는데.
7. **백틱 함정을 하루에 세 번** — 템플릿 문자열 «안» 주석에 백틱을 써서 스크립트가 깨졌다.
8. **셀렉터를 이름으로 잡아 「화면이 안 바뀐 걸」 못 봤다** — 홈 상단바에도 같은 이름 단추가 있었다(규칙 18).
