## 3️⃣ 오늘 낸 사고와 뿌리

### ⚠️ 사고 A — 「달걀·두부」에 계란이 없었다

컨택트시트에서 **번호만 보고** 재고를 골랐고, **넣은 뒤에 이름표를 붙여 다시 보지 않았다.**
`ni_25`는 계란이 아니라 **식빵**이었고(빵 그룹 `ni_09`와 같은 그림) 달걀은 애초에 안 들어갔다.
창업자 화면에서 잡혔다.

📌 **교훈 — 「고른 것」이 아니라 「들어간 것」을 본다.** 고를 땐 번호로 보고, 확인은 이름표를 붙여서 한다.

### ⚠️ 사고 B — 구름 말풍선의 «속이 뻥 뚫렸다»

진한 판에 얹으니 안이 비어 보였다. 재보니 그 덩어리 크기가 **7397px = 선만**(다른 컷은 5만~6만).
**그림의 검은 외곽선에 틈이 있어서** `binary_fill_holes` 가 속을 못 메웠다.

- **처방** = `--join` 을 5 → **25** (닫는 커널을 키운다). 7397 → **61531** 로 채워졌다.
- **덤** = 같은 옵션으로 **파티폭죽 색종이·해님 햇살**처럼 본체에서 떨어진 조각도 한 컷이 된다.
- **찾는 법** = 무게중심 둘레 9×9의 **알파 평균 < 100** 이면 속이 빈 컷.
- 그래도 안 닫히는 건 **버린다** (창업자 *"그런거는 그냥 버리자"*).

### ⚠️ 사고 C — 프레임 톱니가 몇 번이나 반복됐다

- **뿌리** = **늘려서 자르면 요철도 늘어난다.** 그 시트만 2배 확대해 잘랐는데 흐림은 `긴변×0.007` 고정.
- **뿌리 2** = **흰 그림에 흰 테를 두르면 경계가 사라진다** (프레임의 흰 파도·돛, 한끼문구 10의 흰 다이컷).
- 결국 **창업자가 직접 자른 12컷**으로 갔다. 창업자 *"내가 다 잘랐어 이미지 넘길게"*.

*"이 앱으로 이런 게 돼요"* 를 **글 한 줄 없이** 보여준다.

### 어떻게 옮겼나 — 눈대중이 아니라 숫자로

처음엔 화면 녹화 영상에서 좌표를 재려 했다. 그런데 **앱 백업 파일에 그게 숫자로 다 들어 있었다.**

```
설정 → 백업 → 다운로드 → 파일로 전달
```
⚠️ 복사(클립보드)는 텍스트가 길어 폰에서 튕긴다. **다운로드 → 파일 첨부**가 맞다.

옮긴 값 = `decorBg: 'sea'` + 스티커 7개의 `x·y·s·r` + `motion`·`fx` + 손글씨 색·글꼴.
⛔ **이 숫자를 손으로 만지면 창업자가 맞춰둔 균형이 깨진다.**

### 확인한 것

- 홈 「최근 저장」 **첫 칸**에 온다 (`RAW_BASICS` 맨 앞 → `savedAt` 이 최신)
- 「오늘 뭐 해먹지?」 추천에도 뜬다
- **살아 움직인다** — 홈 썸네일을 1.75초 간격으로 두 장 찍어 비교 → **차이 8.14**
- `pageerror` 0 · 게이트 전부 통과

### 내가 채운 값 (창업자 확인 필요)

- **시간 15분 · 1인분** — 밥 130g·계란 1개 기준으로 내가 추정했다

### 답변의 원칙 — 「정직」이 곧 통과 전략

창업자: *"테스터들이 얼마나 사용했는지 난 잘몰라;;"* · *"깔아만 놓은건지… 자세한 피드백은 없었어"* · *"없었어"*(의견 폼 응답)

⭐ **모르는 걸 지어내지 않고 그대로 썼다.** 구글이 반려하는 1순위가 *"좋은 피드백을 받아 개선했습니다"* 같은 **근거 없는 좋은 말**이다. 대신 우리에겐 진짜가 있었다 —
**결함 6건을 실제로 찾아 고쳤고, 배포 전 자동 검사가 파이프라인에 걸려 있다.**

### 낸 답 (요지)

| 칸 | 요지 |
|---|---|
| 모집 | 대상 사용자와 같은 지인·가족 12명에게 직접 부탁. 14일 유지할 12명 채우는 데 여러 번 부탁이 필요해 쉽지 않았다 |
| 참여도 | 12명 14일 유지. **사용 기록을 서버로 안 보내 통계가 없다.** 일부는 설치 후 가볍게 둘러본 정도. 지인이라 동기가 약해 덜 깊이 쓴 점이 실사용자와 다르다. 그래서 **내가 실기기로 반복 사용 + 배포마다 자동 테스트** |
| 의견 | 창구는 열어뒀으나 **구체적 결함 보고는 없었다.** 결함 6건은 내가 직접 찾아 고쳤다 (목록) |
| 대상 | 매일 집밥 하는 30~40대. 캡처해둔 레시피를 다시 못 찾는 사람 |
| 가치 | 모으고 → 자동 정리 → 장보기로 잇고 → 요리 모드. 표지를 꾸며 공유 = **해야 할 일이 아니라 남기고 싶은 기록** |
| 설치 예상 | **0~1만** (⛔「모름」은 계획이 없다고 읽힌다) |
| 무엇을 바꿨나 | 6건 중 두 건을 **「어떻게」** 고쳤는지 구체적으로 (앞 칸과 중복 회피) |
| 준비 판단 | 배포마다 자동 점검으로 오류 시 배포 중단 · 방침·데이터 보안·콘텐츠 등급 제출 · **남은 개선은 업데이트로** (⛔「완벽하다」 금지) |

### ⭐ 답변 사이의 «앞뒤 맞춤»이 핵심

검토자가 제일 잘 보는 게 **서로 어긋나는 답**이다. 실제로 한 곳을 고쳤다 —
「모집이 얼마나 쉬웠나」에 **어려웠음**을 골랐는데 모집 답변엔 어렵다는 말이 없어서, 한 문장을 붙여 맞췄다.

한 줄로 읽으면: **「테스터 참여는 얕았지만 개발자가 직접 메웠다」** 는 일관된 이야기.

### 테스터 유지 걱정에 대한 답

창업자: *"심사가 2주걸리면 지우는 사람들 생길수도 있어 3주깔아달라고 했거든"* · *"오늘이 2주잖아.. 2주뒤면 한달을 깔아야한다는건데"*

1. **14일은 「신청 자격」이다** — 심사 내내 새로 쌓으라는 게 아니다
2. **「참여(opt-in)」 ≠ 「설치」** — 앱을 지워도 opt-out이 아니다. 옵트아웃은 테스터가 opt-in 페이지에서 직접 눌러야 한다
   ⚠️ **단 이 문장을 공식 문서에서 그대로 확인하지는 못했다.** 거의 확실하지만 100%는 아니다
3. ⛔ **확실한 것 = 테스터를 목록에서 빼지 말 것**
4. 테스터에겐 *"쓰지 말고 지우지만 말아달라"* 로 부탁하면 부담이 확 준다
