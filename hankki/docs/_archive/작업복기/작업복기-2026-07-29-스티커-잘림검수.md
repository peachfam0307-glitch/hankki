## 1. 검수 방법 (앞으로도 이걸로)

`투명판(체커보드) 위에 올려서 눈으로` + `자동 검사` 두 가지를 같이 했다.

**자동 검사 규칙**: PNG의 **테두리 1픽셀 줄에 불투명(알파 ≥ 200) 픽셀이 닿아 있으면 = 잘림 의심.**
투명 여백으로 둘러싸여 있어야 정상이다. 스크립트는 스크래치패드에 두고 필요할 때 다시 씀
(짧아서 재작성이 빠름 — 폴더 하나 받아 `테두리에 닿은 픽셀 수`를 위/아래/왼/오 별로 출력).

앱 자산 폴더 전부 훑음: `photo`(374) · `sharepool`(76) · `curation`(27) · `ui`(5) ·
`candy`/`candy2`/`kitchen`/`line`(각 8) · `src/assets`(2).

## 2. 진짜 원인 — 컷 도구가 **격자 칸 안에서만** 덩어리를 찾았다

`tools/cutout-stickers.py`의 `slice_grid`가 예전엔
`ndimage.label(fg[y0:y1, x0:x1])` — **셀을 먼저 잘라내고 그 안에서** 덩어리를 찾았다.
그래서 **스티커가 격자선을 조금이라도 넘으면 넘은 부분이 통째로 사라졌다.**

→ **전체 이미지에서 한 번에 덩어리를 찾고, 무게중심으로 셀에 배정하고, 전역 좌표로 크롭**하도록 고쳤다.
여백(pad)도 옆 칸에서 가져오므로 이제 격자선에 안 잘린다.

### 두 번째 원인 — 위성 조각이 조용히 버려짐
다이컷 **흰 테두리가 배경으로 지워지면서** 반짝임·하트·김 같은 작은 장식이 본체와 끊겨
별개 덩어리가 된다. 그게 `min_area`·`keep_frac`에 걸려 **말없이 사라졌다.**
(계량컵 옆 하트 747px, 냄비 옆 김 2351px에서 실제 발생)

→ 버린 조각을 `slice_grid.dropped`에 모아 **실행할 때 경고로 찍게** 했다.
```
⚠️ 셀06 근처 작은 조각 747px 버림 (중심 318,485) — 확인 필요
```
경고가 뜨면 그 컷만 눈으로 보고 손으로 챙기면 된다. **앞으로 새 시트 자를 때 이 줄을 꼭 볼 것.**

## 4. 덤으로 잡은 것 — **PHOTO_RATIO 59개가 실제 그림과 안 맞았다**

`Stickers.jsx`의 `PHOTO_RATIO`(가로÷세로)는 꾸미기 캔버스에서 **스티커 상자 크기**를 정한다.
그림은 `objectFit: contain`이라 **찌그러지진 않지만**, 값이 틀리면
**그림이 상자보다 작게 나오고 주변에 빈 클릭 영역**이 생긴다.

- `wt_*` 22개 + `sm_gom_bbq` — **이번에 내가 컷을 바꾸고 비율을 안 고쳐서 생긴 것**(미배포 상태에서 발견).
  예: `wt_lemon` 3.8319인데 실제 2.7927 → 테이프가 상자의 3/4만 채움.
- `fh_k01~fh_k37` **35개는 원래부터 어긋나 있었다**(이번 작업과 무관, HEAD에도 그대로).
  한식 아이콘이 계속 실제보다 작게 나오고 있었던 것.

→ **373개 전부 실제 PNG 크기로 다시 계산해 넣음. 지금 어긋남 0.**
검증도 자동화: 등록된 키에 PNG 없는 것 0 / PNG인데 미등록 0(`ob_naeng`은 온보딩 장면이라 제외 정상).

⚠️ **앞으로 스티커 PNG를 교체하면 `PHOTO_RATIO`도 같이 고칠 것.** 잊기 쉬움 — 이번에도 잊었다.

## 7. 교훈

- **"잘렸다"는 눈으로 봐야 안다.** 투명판(체커보드) + 테두리 닿음 자동검사를 컷 직후에 돌릴 것.
- 자동 도구는 **말없이 버린다.** 버릴 땐 반드시 경고를 찍게 만들어야 한다(이번에 추가).
- 그림을 바꾸면 **그림을 참조하는 숫자(비율)도 같이 바뀐다.** 자산 교체 = 항상 2곳.
