## 2. 오늘 제일 큰 것 — 「어디서든 글씨 수정」 (창업자 최우선)

창업자 원문 —
> *"일꾸에서 바로 글자수정은 안돼? 지금은 글을 다 쓰고 꾸미거나 다 꾸미고 그 사이에 맞춰서 글을써야해.
> **어느 탭이든 글자를 누르면 글자가 수정되고 이미지를 누르면 이미지가 수정되어야 하는데**
> 탭을 옮겨다니면서 수정해야하면 안쓰게돼"*
> *"(속지든 글쓰기등 일꾸레꾸 **어디서든 글씨수정가능하게** 만들어줘. **이게가장 중요**)"*
> *"유저가 여기저기 탭 안누르고 글쓸때 편하게 사용한다는 의미야."* · *"편하게 만들어줘 **귀찮고 번거로우면 안써.**"*

### 어떻게 풀었나
⭐ **인스타 스토리·캔바 문법을 가져왔다** — 도구를 띄우는 기준이 **「어느 탭인가」가 아니라 「지금 치고 있나」**다.

```jsx
const writing = mode === 'write' && !!paperEdit
const [typing, setTyping] = useState(false)
const showWriteTools = writing || typing      // 글씨·크기 줄이 «치는 동안» 따라온다
```
- `focus`/`blur` 는 **bubble 을 안 한다** → `onFocusCapture` / `onBlurCapture` 로 받는다
- 글씨체 칩에 `onPointerDown={(e) => e.preventDefault()}` — **안 그러면 칩을 누르는 순간 커서가 날아간다**
- 글칸(`paperEdit`)을 꾸미기 탭에서도 그대로 깔아 둔다 → 탭 왕복이 사라졌다

### ⛔ 딸려온 문제와 그 처방
글칸을 살려 두니 **스티커를 글칸 «위»로 못 끌게 됐다.**
범인 = `PaperSheet` 의 `overSticker={zIndex:1}`(「글은 가려지면 안 된다」).
→ 꾸미기 층에 **`zIndex: 2`**. 재현판이 잡았다.

## 3. 틀린 것 · 고친 것 (오늘 것만)

### ⛔⛔ ① 「글자색 4개뿐」이라고 창업자에게 잘못 말했다
`TEXT_COLORS` 를 **리터럴 `key:` 정규식으로만 세어** 스프레드 11개를 통째로 놓쳤다. **실제 15색.**
```js
export const TEXT_COLORS = [
  { key: 'white', … }, { key: 'charcoal', … }, { key: 'coral', … }, { key: 'mustard', … },
  ...STICKER_COLORS.filter(…).map((c) => ({ key: `t_${c.key}`, … })),   // ← 이 11개를 못 셌다
]
```
→ **화면에 그려진 것을 세는** `_measure-글자색.mjs` 로 다시 확인.
📌 **진짜 문제는 「없다」가 아니라 「15개 중 7개가 255px 밀려 안 보인다」였다.**

### ⛔⛔ ② 「불편하다」의 «이유»를 내가 정했다
창업자가 상하좌우 반전을 원한 이유를 나는 *"손잡이가 크기·회전 동시라 돌리기 어렵다"* 로 짚었다.
창업자 — *"**돌리는건 잘돼**"*. 진짜 이유는 **돌리면 ✕ 가 같이 돌아 스티커를 잡으려다 지워지는 것**.
📌 규칙 18 그대로 — **증상의 이유를 내가 정하면 처방이 통째로 빗나간다.**

### ⛔⛔ ③ v9.93 회귀 — 글자 효과가 «맨 앞 한 글자»에만 (창업자 제보)
모션을 붙이려고 감싼 `span` 을 `position:absolute` 로 뒀다.
⭐ **`width: 'max-content'` 상자는 «자식이 폭을 정한다»** — 자식을 전부 절대배치하면 상자가 0px 로 쪼그라든다.
→ `display: 'inline-block'`. **규칙 12로 옛 코드를 되돌려 「상자 0px · 0.00배」 실패까지 확인.**

### ⛔ ④ 하트가 글자 «속»에서 나왔다 (창업자 지적)
> *"하트효과가 글자 윗부분부터 시작해야하지 않아?"*

효과 조각의 y 는 **퍼센트**(`top: ${y}%`)다. 캐릭터 상자는 세로로 길어 y=12% 가 「위쪽」이지만
**글자 상자는 납작해서** 같은 12% 가 **글자 한가운데**가 된다.
→ `StickerFx({ lift })` — 글자엔 상자 위쪽으로 띄운다.

### ⛔⛔ ⑤ 「setLogEditing 여는 코드가 없다」고 말했는데 틀렸다
첫 grep 이 0줄이었고 재시도에 `MyRecipesScreen.jsx:397` 이 나왔다.
**규칙 17 위반** — 못 찾은 것을 「없다」로 바꿔 말했다. 왜 0줄이었는지는 아직 모른다.

### ⛔ ⑥ bash 백틱이 `subst.py --new` 안에서 명령 치환됐다 — 오늘 두 번
`editingId`·`onText` 두 낱말이 주석에서 **통째로 사라졌다.**
→ **`--new` 안에 백틱을 쓰지 않는다.** 코드에도 경고를 적었다.

### ⛔ ⑦ 검수판 레이아웃이 세 번 어긋났다
①좁은 창에서 그려 제목이 갇힘 ②`grid` 가 블록이라 폭이 창 전체(`width:max-content` 로 고침)
③body 높이가 창 높이(격자 바닥 `getBoundingClientRect().bottom` 으로 고침)

### ⛔ ⑧ 오늘 마지막 판에서도 검사가 «거짓 실패»했다
「고르기 모드가 켜졌나」를 `document.body.innerText.slice(0, 200)` 로 봤는데
**고르기 바는 화면 «맨 아래»에 뜬다**(200자 밖).
📌 또 규칙 18 — **「없다」가 아니라 내 검사가 거기까지 안 본 것.**

## 6. 오늘 배운 것 (다음에 또 밟지 않게)

1. ⭐⭐ **「검사가 «무엇을» 보는지」가 오늘만 여덟 번 문제였다.**
   리터럴만 센 색 개수 · aria-label 없는 단추 · 앞 검사가 남긴 상태 · 저장 전 localStorage · 200자만 본 innerText …
   📌 **검사가 초록불이어도 「무엇을 보는 초록불인가」를 본다.**
2. ⭐⭐ **`width: 'max-content'` 는 자식이 폭을 정한다.** 자식을 절대배치하면 상자가 사라진다.
3. ⭐⭐ **층은 통과시키고 아이템만 받는다** — `pointerEvents:'none'` ＋ 아이템 `'auto'` ＋ **`zIndex`를 꼭 같이**.
   zIndex 를 빼먹으면 「글은 가려지면 안 된다」 규칙이 스티커를 밑에 깔아버린다.
4. ⭐ **퍼센트 좌표는 상자 모양을 탄다.** 세로로 긴 상자와 납작한 상자에서 같은 12% 는 전혀 다른 자리다.
5. ⭐ **문서의 숫자를 근거로 쓰기 전에 다시 잰다** — 「탭 5개가 꽉 찼다」가 실측으로 틀렸다.
6. ⭐ **`npm run smoke` 는 빌드를 안 한다.** 판정은 **exit code** 로. dist 낡음 게이트가 오늘도 두 번 잡아줬다.
