## 2️⃣ ⭐⭐⭐ 오늘 배운 것 (다음에 또 쓸 것)

### ⓐ **자산을 갈 땐 「날짜로 잠긴 곳」과 「그냥 열린 곳」을 따로 센다**
서랍 9컷만 보고 *"9/1 전이라 아무도 못 봤다"* 고 생각했는데 **틀렸다.**
`scenepool` 은 **날짜 게이트가 아예 없다** — `import.meta.glob` 으로 폴더를 통째로 읽고
폴라로이드 카드가 65% 확률로 거기서 뽑는다. **곰 같은 카롱이 이미 유저 카드에 나가고 있었다.**
📌 **같은 그림이라도 「어느 폴더에 있느냐」로 공개 시점이 갈린다.**

### ⓑ **DOM 에 안 붙인 `<a>` 의 `.click()` 은 무시된다** ← 자랑카드 먹통의 원인 ①
```js
// ⛔ 이러면 아무 일도 안 일어난다
const a = document.createElement('a'); a.href = u; a.download = n; a.click()
// ✅ 붙여야 한다
document.body.appendChild(a); a.click(); a.remove()
```
⭐ **두 증상이 갈린 이유가 정확히 이것이었다** —
랜덤 카드(`ShareDrawCard`)는 append 를 안 해서 **먹통**,
꾸민 표지(`shareCover.js`)는 append 를 해서 **다운로드 팝업**.
같은 뿌리인데 겉모습이 달라서 「두 개의 버그」처럼 보였다.

### ⓒ **공유는 누르기 «전»에 준비해 둔다** ← 원인 ②
폰의 Web Share 는 **사용자가 누른 «직후»에만** 허용된다(user activation).
누른 «뒤에» 캡처를 시작하면 몇 초 사이 허가가 만료돼 `navigator.share` 가 통째로 거절된다.
📌 창업자 말 *"로딩은 돌아가. 그다음이 안돼"* 가 이 증상의 정확한 묘사다.
✅ **미리 캡처** — 카드가 정해지면 백그라운드로 파일을 만들어 두고, 누르면 기다림 없이 공유창.
⚠️ **v8.57 에 *"다음엔 미리 캡처"* 라고 적어두고 미뤄뒀던 처방이다. 오늘 그 값을 치렀다.**

### ⓓ **캡처를 무겁게 만드는 것 셋**
`cacheBust: true`(그림을 전부 다시 내려받는다) · 순차 처리 · `pixelRatio: 2`.
셋 다 고쳤다(끄기 · `Promise.all` · 1.6).

### ⓔ **조용히 실패하지 않는다**
`catch { /* noop */ }` 는 유저에게 **먹통**이다. 이제는 12초 제한을 두고,
끝나든 못 끝나든 **말을 한다** — 「공유가 안 되는 폰이라 사진으로 저장했어요」.
그 문구가 다음 진단의 재료가 된다.

### ⓕ **표시 크기는 접두어가 정한다** ← 111px 소품 답
`DecorEditor.addSticker` 의 `s` 값이 종류마다 다르다:
`pf_` 0.58(626px) · `gp_duo` 0.34 · `gp_` 0.26 · **`dc_`·`ch_` 0.15(162px)** · 나머지 0.22(238px).
📌 **「작아서 못 쓴다」가 아니라 「어느 크기로 붙일 거냐」의 문제였다.**
238px 로 등록하면 3컷이 걸리고, **162px 로 등록하면 0컷**이다.
