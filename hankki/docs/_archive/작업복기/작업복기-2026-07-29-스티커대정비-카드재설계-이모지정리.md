## 2. ⭐ 오늘의 큰 사고 — 스티커 172종이 깨져 나갔다

창업자 폰 제보: **"우리 꾸미기에 추가한 데코에 여름 스티커들 다 깨져."**

**원인 (숫자로)**
| 세트 | 소스 긴변 | 캔버스 표시 | 배율 |
|---|---|---|---|
| 여름다꾸 | **85px** | 238px | **2.8배** |
| 미니 아이콘 | 94px | 238px | 2.5배 |
| 파스텔 | 141px | 238px | 1.7배 |
| (기존 데코) | 198px | 162px | 축소 → 선명 |

원본 시트 한 장(1254px)에 아이템이 **90~100개**라 하나당 85px밖에 안 됐다. 업스케일해도 없는 정보는 안 살아난다.

**⚠️ 이건 우리 문서에 이미 있던 규칙을 어긴 것이다**
`docs/자랑공유-캐릭터리뉴얼.md`: *"작게 붙는 소품·음식·효과 = **25컷 격자**(200~300px 충분). **6컷↑ 금지(흐림)**"*

**⚠️ 검수 구멍 — 투명판만 봤다**
그날 검수는 잘림·투명·비율만 확인했고 **해상도를 안 봤다.**
게다가 **서랍(피커)은 56px로 작게 보여 멀쩡해 보였다.** 캔버스에 올려야 드러나는 문제였다.

**조치**
1. 172종 등록 해제 (낱개 PNG는 보존 — 25컷 격자로 다시 뽑으면 되살아난다)
2. **프레임 48종은 유지** — 1.4~1.6배인데 **짐작하지 않고 실제로 렌더해 확인**하니 멀쩡했다(굵은 단색 선은 확대에 강함)
3. **`scripts/check-sticker-res.mjs` 신설 → 배포 게이트.** 1.7배 초과 확대면 빌드 실패.
   기준도 실측 — 같은 배율로 렌더해 비교하니 2.8배는 꽃잎이 번지고 1.6배 프레임은 멀쩡했다.

## 4. 오늘 생긴 안전장치

`npm run smoke` = **배포 게이트** (하나라도 실패하면 빌드 실패)
```

```

**`docs/스티커-검수-절대원칙.md`** (창업자 "투명판 검수 절대원칙 필수. 저장해둬")
①투명판 ②잘림 ③**해상도** ④비율 ⑤실제 앱 렌더 — 5가지 전부 통과해야 반영.
> 창업자 지시는 '투명판'이었지만, **투명판만으론 부족한 게 오늘 증명됐다.** 그래서 5가지로 늘렸다.

## 5. 배운 것 (다음에 안 틀리려고)

1. **"검수했다"는 말은 아무 의미가 없다.** 뭘 몇 개 중 몇 개 봤는지 숫자로 남겨야 한다.
2. **작게 보이는 곳에서 판단하지 말 것.** 피커 56px에서 멀쩡한 게 캔버스 238px에서 깨진다.
3. **우리 문서에 이미 답이 있는 경우가 많다.** 오늘 사고 2건(해상도·낱말 자르기)은 둘 다 기존 규칙/상식을 안 지켜서 났다.
4. **`slice_grid`의 `keep_frac`은 최대 덩어리 대비 비율**이라 `min_area`를 낮춰도 위성 조각(하트·반짝임)이 안 살아난다.
5. **중복은 눈이 아니라 픽셀로 확인.** 프레임 K는 F와 평균차 0.0이었다.
6. **토큰을 아껴야 한다** — 창업자 지적("카드땜에 토큰 낭비가 어마어마"). 카드 재설계에 반복이 너무 많았다.
   앞으로는 **시안 여러 장 렌더 → 판정 요청**보다 **원인 규명 → 한 번에 제대로**로.
