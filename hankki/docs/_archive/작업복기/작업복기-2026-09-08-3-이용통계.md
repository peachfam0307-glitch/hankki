## 왜 시작했나

창업자가 Play 콘솔 통계와 Firebase 로그인 명단을 캡처로 주고 물었다.

> 📮 *"늘고 있는거 맞지? 유저기"* → *"우리가 유저에 대해 볼수있는 정보가 뭐야?"*
> → *"레시피를 작성하지 않고 쓰는 사람도 알수있어? 로그인하지 않고 사용하는 사람이나.."*
> → ***"콘솔만 업뎃기다리기는 좀.. 막막해 우리도 알수있는 방법이 필요한 듯"***

🔢 **실측으로 뿌리를 찾았다** = `grep -rn "gtag|analytics|logEvent" src/` → **0건.**
분석 도구가 **하나도 없었다.** 그래서 —

| 우리가 볼 수 있던 것 | 못 보던 것 |
|---|---|
| 로그인한 사람 수 (Firebase Auth) | **비로그인 사용자 — 통째로** |
| 설치 수 (Play 콘솔 · 3~7일 지연) | 어제 몇 명이 앱을 열었나 |
| AI/OCR 이용 횟수 (우리 워커) | **어느 화면을 쓰나** |

⭐ **로그인 30명은 「계정을 만든 사람」이지 「앱을 쓰는 사람」이 아니다.** 둘을 못 갈랐다.

## 무엇을 했나 (v12.85 → v12.88)

### 1. 이용 통계를 켰다 (v12.85)

창업자가 Firebase 콘솔에서 Google Analytics 를 켜고 `measurementId` 를 줬다.
앱은 `src/stats.js` 하나로 붙인다. 지킨 것 넷 —

1. **통계가 죽어도 앱은 그대로 돈다**
2. **첫 화면을 안 늦춘다** (idle 로 미룬다)
3. **유저가 끌 수 있고, 끄면 그 자리에서 멎는다** (`ga-disable`)
4. **레시피·일기·사진 내용은 안 보낸다**

＋ `scripts/check-통계고지.mjs` 신설 — **방침과 앱이 어긋나면 배포를 막는다.**

### 2. ⛔ 그 배포가 죽었다 (run 2285) — 그리고 내가 원인을 «두 번» 잘못 말했다

```
13/13 통과 · 자바스크립트 오류 = PAGEERROR Failed to fetch ×2 → exit 1
```

- 처음: *"통계 때문일 것 같다"* (짐작)
- 그다음: 로컬 스모크가 28초 만에 통과하자 **창업자에게 "통계는 범인이 아니야"라고 말했다 — 틀렸다**
- CI 로그 실물을 읽고서야 정정: **통계가 맞다**

⭐ **뿌리** = `firebase/analytics` 가 gtag 를 «자기가» 내려받고, 실패하면 오류를 **밖으로 던진다.**
내 `try/catch` 가 못 잡는다. ⛔ **시험판 탓이 아니다 — 인터넷 나쁜 유저 폰에서 똑같이 난다.**

✅ **고침 = 실패의 «모양»을 바꿨다**(절대원칙 34) —
`firebase/analytics`·`firebase/app` 을 걷어내고 **gtag 를 직접 넣고 `s.onerror = () => {}`**.
못 받아와도 «조용히» 끝난다. 재현판 재실행 = **오류 2개 → 0개.**

### 3. 화면 기록을 붙였다 — 「뭘 많이 썼나」

📮 창업자 = *"내일부터는 우리앱에서 뭘 많이 썼는지도 다 볼수있어?"* ＋
*"**이걸 지금부터 재야 향후 기능추가나 업뎃할때 이용하지**"*

⛔ **저절로는 안 됐다** — 우리 앱은 화면을 바꿔도 **주소가 안 바뀐다.**
GA4 는 주소로 화면을 가르는데 전부 같은 주소라 「한끼를 열었다」로만 뭉쳤다.

✅ `src/App.jsx` 의 **`useEffect [tab, stack]` «한 곳»** — 이러면 `push`·`replace`·`pop`·탭이동
**네 갈래가 다 잡힌다.** ⛔ 부르는 자리마다 심으면 새 화면을 만들 때마다 빠뜨린다.
🔒 `src/stats.js` 의 `보내도되는화면` 자물쇠 = **적힌 15개 이름만 통과.** 목록에 없으면 아예 안 보낸다.

### 4. ⛔⛔ 그 화면 기록이 «안 잡힐» 뻔했다 — 내일 아침 보는 법을 쓰다가 잡았다

처음에 `screen_view` 로 보냈는데, 그건 **GA4 의 예약된 이름이고 앱(네이티브) 스트림의 것**이다.
우리는 웹(TWA)이라 **웹 스트림**이고 웹의 짝은 `page_view` 다.

⭐ **제일 무서운 종류의 버그였다** — 앱은 멀쩡히 돌고, 오류도 안 나고, 스모크도 통과한다.
**콘솔에 숫자가 0 으로 나올 때까지 아무도 모른다.**

✅ `page_view` ＋ 화면 이름을 `page_title` 에 싣는다 → 창업자가 **표준 보고서에서 «그냥»** 본다.
⛔ 맞춤 이벤트로 갔으면 맞춤 측정기준을 따로 등록해야 보여서 **내일 아침에 아무것도 못 봤다.**
＋ `send_page_view: false` (안 그러면 주소가 같아 한 덩어리로 뭉친다)
＋ 첫 화면은 gtag 가 붙기 «전»에 그려지므로 **못 보낸 것을 붙은 뒤에 보낸다.**

⚠️ `support.google.com` 은 이 환경에서 못 연다 — **공식 원문을 직접 못 봤고** 여러 경로로 같은 말을 확인했다.

### 5. 끄는 스위치를 방침 «페이지 안»으로 묻었다 (v12.87)

📮 창업자 = *"이거 꺼짐없앨수는 없어?? 스위치방침을 꼭 그렇게 해야해?"* ＋ *"다른앱에서 본적이 없는데"*
→ 리서치 뒤 → *"우리도 깊이 묻어놓자"* · *"설정에서 딱 안보이게"* · *"개인정보처리방침안에 넣거나"*

**없앨 수는 없다 — 찾아보고 답했다:**
- **Google Analytics 약관 7조** = 거부(opt-out) 수단을 «우회하지 말 것»
- **Play 「사용자 데이터」 정책** = 앱 기능에 «필수가 아닌» 데이터는 켜고 끌 수 있어야 한다

→ 둘 중 하나는 반드시: ⓐ첫 실행 동의 팝업 ⓑ끄는 스위치.
**ⓐ가 훨씬 나쁘다** — 「아니오」 누른 사람이 통째로 안 잡히고 첫 화면을 막는다.

📌 **「다른 앱엔 없다」는 «없어서»가 아니라 «깊어서»였다** —
카카오톡도 있다: `설정 → 카카오 계정 → 서비스 이용 동의`(**4단계 깊이**).
우리는 프로필 첫 화면에 대놓고 있었다. 그게 눈에 띈 진짜 이유다.

✅ **방침 페이지 안으로** — 앱과 «같은 주소»라 저장소를 함께 쓴다.
여기서 끄면 앱도 꺼진다(`storage` 신호를 듣는다 — 방침은 «다른 탭»에서 열리므로 안 들으면 계속 보낸다).

### 6. 게이트를 넓혔다 (`check-통계고지` 검사 6개 → 10개)

방침과 앱이 «기계로» 묶여 있다. 새로 지키는 것 —
① 방침에 **진짜 단추**가 있나(글만 있으면 방침이 거짓말)
② 그 단추가 앱과 **같은 열쇠**를 쓰나
③ 다른 탭에서 꺼도 앱이 그 자리에서 멎나
④ 설정 목록에 **되살아나지** 않았나(끄는 자리가 둘이면 한쪽이 반드시 낡는다)
