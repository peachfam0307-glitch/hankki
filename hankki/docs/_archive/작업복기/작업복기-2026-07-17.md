## 2) 뒤로가기 대장정 — 근본 재설계 (v3.8 → v4.5)
**증상**: 팝업(꾸미기·미리보기·장바구니 시트·아바타…) 열고 뒤로가기 → 가끔/반복 시 앱 종료. 폰마다 다르게 재현(창업자 폰 OK, 남편 폴드7 심함).

**원인(3단 발굴)**:
1. `popAll`(요리완료·저장)에서 `history.go(-n)`이 popstate를 1번만 쏘는데 n번 억제 → 카운터 고착 → 종료.
2. 탭 화면 필터 핸들러가 위에 뜬 상세 화면의 뒤로가기를 가로챔.
3. **최종 보스**: popstate 안에서 터치 없이 `pushState`로 트랩을 재보충 → 크롬 history intervention이 그 칸을 skip-on-back 처리 → 히스토리 바닥 → TWA 종료.

**해결(재설계)**:
- **모달 = 열 때(터치 시점) 진짜 히스토리 칸 1개**(`App.openModal`) → gesture-backed라 intervention에 안 걸림. 뒤로가기는 소비만, 재보충 없음.
- `useModalBack`(조건부 렌더 시트용) / `useLayerBack(isOpen, close)`(인라인 오버레이용) — 전 모달 이관 완료.
- 겹친 모달 동시 닫힘(아바타 시트+픽커)은 마이크로태스크 배칭으로 `go(-n)` 1회.
- 루트 종료 방지 가드: **pointerdown이 아니라 pointerup/click/keydown**에 심어야 터치 기기에서 제스처 인정(폴드7 최종 해결 열쇠).
- 검증: 크롬 intervention 모델 시뮬레이션 15+9개 시나리오 통과 + 실기기(일반 폰+폴드7) 확인.

**교훈**:
- popstate 핸들러 안에서 gesture-less pushState 금지.
- 터치 기기 제스처 인정 시점 = pointerup(터치 끝), pointerdown 아님.
- 화면에 로그를 찍는 임시 진단(localStorage 보존)이 원격 기기 디버깅의 결정타였음.
- "홈에서 뒤로 = 종료 확인창"은 기기에 따라 안 뜰 수 있음(카톡 등 일반 앱도 동일) — 완벽 보장 대상 아님.

## 3) 폴드(넓은 화면) 꾸미기 메뉴 안 보임 → 수정
`.decor-editor`가 화면 전체 폭이라 캔버스(정사각)가 거대해져 서랍을 밀어냄 → **max-width 440px 중앙 정렬**로 해결.

## 4) 조사 3팀 감사 결과 반영
- **iOS**: 치명 없음. 공유받기(Web Share Target)는 iOS 미지원(안내 필요), 잠금화면 타이머 알람 무음(웹 한계), **localStorage 5MB 초과 시 조용한 유실** → 경고 토스트 추가(근본 해결 IndexedDB는 백로그). -webkit-backdrop-filter 2곳 보강.
- **회귀**: 탭 핸들러 가로채기(수정), 공유 인입 히스토리 칸 누락(수정), 프로필 백업 시트 back 미처리(수정).
