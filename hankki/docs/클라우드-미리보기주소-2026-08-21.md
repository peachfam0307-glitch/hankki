## 2️⃣ 고른 길 = **Cloudflare Pages 「직접 업로드」**

⭐ **왜 이걸 골랐나**
· 창업자가 **이미 Cloudflare 대시보드를 쓴다**(OCR Worker 를 거기서 붙여넣고 Deploy 한다) — 새 계정 0
· **명령어(CLI)가 필요 없다** — 대시보드에서 **폴더를 끌어다 놓으면** 끝
· ⭐**주소가 고정된다**(`<이름>.pages.dev`) → Firebase 에 **한 번만** 등록하면 다시 올려도 그대로
· ⛔**열쇠(API 토큰)를 나한테 넘길 일이 없다** — 창업자가 자기 손으로만 올린다

📄 근거 = `developers.cloudflare.com/pages/get-started/direct-upload/` (검색 요약 · 2026-08-21)

### ⚙️ 예비 길 — `cloudflare.com/drop`
2026-07-08 에 생긴 것. **계정도 없이** 폴더를 끌어다 놓으면 주소가 나온다.
⚠️ 단 **60분 뒤 사라진다**(「claim」하면 남는다) ＋ **주소가 매번 바뀐다** → Firebase 등록을 매번 다시 해야 한다.
👉 그래서 **본 길은 Pages**, 이건 막혔을 때만.

## 3️⃣ ✅ 좋은 소식 — Firebase 쪽은 한 칸이면 된다

공식 = *"기본적으로 **localhost 와 프로젝트의 호스팅 도메인**이 승인된 도메인으로 등록되어 있다"* ·
*"기본 도메인은 **web.app** 과 **firebaseapp.com** 의 하위 도메인"*
📄 `support.google.com/firebase/answer/6400741` (검색 요약 · 2026-08-21)

👉 그러니 **`<이름>.pages.dev` 를 「승인된 도메인」에 «한 줄» 넣으면 끝.**
   자리 = **Firebase 콘솔 → Authentication → Settings(설정) → 승인된 도메인**

## 4️⃣ 🗓 내일 순서 — 창업자 손은 «5분»

```
[나] ✅끝났다 — zip 하나로 만들어 뒀다 (27MB · 168개 파일 · 5️⃣ 절 참조)

[창업자] ① Cloudflare 대시보드 → Workers & Pages → Create → Pages → 「직접 업로드」
         ② zip 을 끌어다 놓기 → 주소가 나온다 (`<이름>.pages.dev`)
         ③ 그 주소를 Firebase → Authentication → 설정 → 승인된 도메인 에 붙여넣기
         ④ 폰 크롬으로 그 주소 열기

[창업자] 폰에서 눌러볼 것 = 로그인 → 가져오기 → 설정에서 올리기·내려받기
```

### ⚠️ 정직하게 — 이 판으로 «못» 보는 것 하나
미리보기는 **폰 크롬**에서 열린다. **TWA(설치된 앱) 「안」이 아니다.**
⭐ 그런데 **TWA 안에서 구글 로그인이 되는지는 이미 닫혔다** — 2026-08-21 17:23 창업자 폰,
   `public/fbtest.html` 을 **앱 안에서** 열어 `signInWithPopup` 이 도는 걸 실물로 봤다.
👉 그러니 이 판이 봐야 할 것은 **「우리 앱 코드가 처음부터 끝까지 도는가」**이고, 그건 크롬에서 그대로 드러난다.

### ⛔ 이 판으로 만든 데이터는 «진짜»다
시험판이라도 **같은 구글 계정 · 같은 Firestore** 를 쓴다 → 올린 것은 진짜 클라우드에 쌓인다.
👉 그래서 `cloud.js` 에 **［클라우드 비우기］**(`클라우드비우기`)를 미리 넣어 뒀다. 시험 끝나고 지우면 된다.
