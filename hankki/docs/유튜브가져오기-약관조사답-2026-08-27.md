# 🎥 유튜브 가져오기 — 약관 조사 ①의 «답» (2026-08-27)

> 📮 창업자가 질문 ①을 다시 던져 **AI 두 곳에서 답을 받았다.**
> ⭐ 둘째 답은 **공식 문서를 직접 열람해 인용**했다(약관 Last updated **2026-04-28**).
> ⛔ **나는 그 주소들을 못 연다**(EGRESS_BLOCKED) — 원문을 «내 눈으로» 대조하지 못했다.

## 0️⃣ 한 줄

**자막 길은 죽었다.** 제3자 영상의 자막을 약관 안에서 가져올 방법은 **없다.**
살아 있는 길 = **영상 설명란(description)** 하나. ⭐ 다만 **30일 저장 제한**이 새로 붙는다.

## 1️⃣ 두 답이 «완전히 같은» 것 — 이건 닫혔다

| | 답 | 근거(공식) |
|---|---|---|
| **captions.download** | ⛔ **영상 소유자(편집 권한자)만.** 남의 영상은 403 | *"This method is requires the user to have permission to edit the video."* (원문 오타 포함) |
| **약관 안의 제3자 자막 경로** | ⛔ **없다.** 예외는 «창작자 서면 허락»뿐 | ToS 예외 = 공개 검색엔진 / prior written permission |
| **timedtext · yt-dlp** | ⛔ **위반.** 자동화 접근 금지 ＋ 문서화 안 된 API ＋ 스크래핑 금지 | ToS *"access the Service using any automated means (such as robots, botnets or scrapers)"* · Developer Policies III.D.7 · III.E.6 |
| **설명란 videos.list(snippet)** | ✅ **허용.** 공식·문서화된 경로 | quota **1 유닛** |
| **무료 할당량** | **하루 10,000 유닛** (태평양시 자정 리셋 · 무료) | quota 가이드 |
| **해먹으리가 어느 길인가** | ❓ **둘 다 「모른다」고 답했다** | — |

⭐ **내가 8/27 낮에 처음 말한 *"공식 API 자막은 영상 주인만"* 은 «맞았다».**
   그때 틀린 건 결론이 아니라 **「그래서 길이 없다」로 닫아버린 것**이었다(다른 길을 안 찾았다).

## 2️⃣ 둘째 답이 «새로 가져온» 것 — 여기가 진짜다

### 🚨 ⑴ 30일 저장 제한 (Developer Policies III.E.4)
> *"After 30 calendar days, the API Client must either delete or refresh the stored data."*

**API 로 받은 데이터(설명란 원문 포함)를 30일 넘게 갖고 있으면 정책 위반이다.**

### 🚨 ⑵ 그래서 «우리 코드»에 바로 걸리는 자리가 있다 — 실측
```
hankki/src/App.jsx:338 · :364 · hankki/src/screens/EditorScreen.jsx:440
  → 담을 때 원문을 rawText 로 «기기에 영구 저장»한다 (2026-08-22 에 내가 만든 것)
```
- ⛔ **유튜브 설명란을 그대로 rawText 에 넣으면 그 순간 30일 규정 위반이다.**
- ✅ **고치는 법은 간단하다** — 유튜브에서 온 원문은 **rawText 에 안 담는다**(정리한 결과만 저장).
  ⚠️ 대신 **「파서를 나중에 고쳐도 되돌릴 수 없다」**는 rawText 의 원래 값어치를 유튜브 건에선 포기한다.
- 📌 **AI 둘 다 이건 몰랐다** — 우리 코드는 우리만 안다.

### 🚨 ⑶ 타임스탬프 점프는 «따라갈 수 없다»
- 해먹으리의 **조리 단계마다 00:19·00:27 점프** = 자막의 «타이밍 데이터»가 있어야 나온다.
- 자막을 못 가져오면 **그 기능은 원리적으로 못 만든다.**
- 대안(둘째 답 권고) = **IFrame Player 로 재생**은 합법 · 시각은 **LLM 추정 또는 유저가 직접 지정**
  ⚠️ 추정한 시각이 틀리면 **「눌렀는데 딴 장면」**이 된다 — 그건 «없느니만 못한» 기능이다.

### ⑷ API 서비스 약관 §16.3 — 오디오비주얼 콘텐츠 복제·배포 금지
> *"no rights or licenses are granted to reproduce or distribute audiovisual content …"*

### ⑸ Google Play 지식재산 정책
> *"We don't allow apps that infringe copyright. Modifying copyrighted content may still lead to a violation.
>  Developers may be required to provide evidence of their rights to use copyrighted content."*
> — support.google.com/googleplay/android-developer/answer/9888072

⭐ **「고쳐 썼으니 괜찮다」가 자동으로 성립하지 않는다**는 문장이 저기 박혀 있다.
   ⛓ **8/27 의 유명인 이름 결론과 한 몸이다** — 채널명·창작자명은 **출처 표시로만**, 브랜드처럼 쓰면 안 된다.

### ⑹ 설명란 글의 저작권
- 창작자의 **문장·서술**은 저작물이 될 수 있다.
- **재료 목록·조리 순서는 사실·아이디어라 보호 대상이 아니다** — 8/01 문체부 자료와 같은 논리.
- ✅ **우리 방식(원문 미게재 ＋ 재료·순서만 우리 문장으로)은 저작권상 안전한 편.**
  📌 **남는 문제는 저작권이 아니라 «약관»이다**(30일 저장 · 취득 경로).

## 3️⃣ 원가 — 걱정 안 해도 된다

- `videos.list` = **1 유닛** · **영상 ID 50개를 한 번에 넣어도 1 유닛**
- 하루 10,000 유닛 → **설명란만 쓰면 사실상 한도에 안 닿는다**
- (참고 · 쓸 일 없는 값) captions.list 50 · captions.download 200 · search.list 100
- ⚠️ 한 AI 가 *"videos.list 는 100 유닛"* 이라 적은 블로그가 있다며 **search.list 와 혼동한 오기**라고 짚었다.

## 4️⃣ ⏳ 창업자가 정할 것 — 갈래 셋

| | 무엇 | 좋은 것 | 나쁜 것 |
|---|---|---|---|
| **ⓐ** | **설명란만 읽는다** (＋ 안 되면 유저가 붙여넣기) | 약관 안 · 원가 0 · **지금 있는 붙여넣기 화면을 그대로 쓴다** | 설명란에 레시피가 없는 영상은 **못 읽는다** |
| **ⓑ** | ⓐ ＋ **영상 임베드 재생** | 「영상 보면서 따라 하기」가 된다 | 만들 것이 늘고, 타임스탬프는 여전히 없다 |
| **ⓒ** | **유튜브 가져오기를 접는다** | 위험 0 | 창업자가 말한 **「우리만 안 되면 경쟁력이 없다」**가 그대로 남는다 |

⭐ **내 추천 = ⓐ 먼저.** 근거 셋 —
  ⑴ **새로 만들 화면이 거의 없다** — 붙여넣기·파서·열쇠·편집기가 이미 다 있다
  ⑵ **약관에 안 걸리는 유일한 길**이라 「앱이 내려갈」 위험이 0이다
  ⑶ ⓑ는 ⓐ 위에 얹는 것이라 **나중에 해도 아무것도 안 버린다**

## 5️⃣ ❓ ⓐ를 정하기 전에 «재야 하는» 것 하나

**「한국 요리 유튜브 영상 중 설명란에 재료·순서가 적힌 것이 몇 %인가」**
- ⛔ **아무도 모른다.** 이게 낮으면 ⓐ는 «되다 안 되다» 하는 기능이 된다.
- ⛔ **나는 유튜브를 못 연다** → 창업자가 폰에서 **평소 보는 채널 10개를 열어** 설명란만 보면 답이 나온다.
- ⭐ **이 숫자가 ⓐ의 값어치를 정한다.** 8할이면 훌륭한 기능, 2할이면 안 만드는 게 낫다.

## 6️⃣ 안 바뀌는 것

- ✅ **창업자 확정 「유튜브 가져오기 = 레시피열쇠」는 그대로다**(2026-08-27). 무엇을 읽느냐만 바뀐다.
- ✅ **「실패하면 열쇠를 안 깎는다」도 그대로다** — 설명란이 비어 있을 때가 바로 그 자리다.
- ⏳ **영상 1편에 열쇠 몇 개인가**는 여전히 창업자 판정. 다만 **원가가 거의 0**이라 무겁게 볼 필요가 없다.

## 7️⃣ ⛔ 아직 모르는 것 (짐작으로 채우지 말 것)

1. **원문을 내 눈으로 못 봤다** — 이 환경은 그 주소들을 못 연다. 인용은 창업자가 가져온 것이다.
2. **해먹으리가 어느 길인지는 여전히 모른다** — AI 둘 다 「확인 불가」라고 밝혔다.
   ⛔ **「해먹으리가 한다 = 적법」은 성립하지 않는다**(둘 다 명시).
3. **우리가 재작성한 결과물이 「API Data」로 30일 규정에 걸리는지**는 두 답이 다루지 않았다.
   ⭐ 안전한 쪽 = **원문은 안 남기고 재작성 결과만 남긴다.**
4. **약관은 개정된다**(Last updated 2026-04-28) — **만들기 직전에 다시 확인한다.**

## 🚨 0️⃣ 뒤집힌 것 — 「설명란만 쓰면 안전하다」가 «아니다»

**Developer Policies III.E.4 (8항)**
> *"access or use API Data to create new or derived data or metrics."* — **금지**

그리고 API 서비스 약관은 **API 로 받은 모든 data·content·information 을 「API Data」**로 정의한다.

```
videos.list → description → LLM → 재료 목록 ＋ 조리 단계
```
**이건 문언 그대로 읽으면 「API Data 로 새 데이터를 만드는 것」이다.**

- ⛔ **위 4️⃣ 절에서 내가 「ⓐ 설명란만 = 약관 안, 위험 0」이라고 추천했다. 그 근거가 무너졌다.**
- ⚠️ 다만 **세 번째 답도 이걸 「해석」이라고 스스로 밝혔다** — 구글 문서에
  *"설명란을 LLM 으로 레시피로 바꾸지 말라"* 는 사례가 «직접» 적혀 있는 건 아니다.
- 📌 그래도 **우리는 이미 출시한 앱**이라 「해석이 갈리는 자리」에 기능을 걸 수 없다.

## ⭐⭐ 1️⃣ 그런데 — **우리는 이미 유튜브를 하고 있었다** (내가 코드를 열어서 알았다)

⭐⭐ **그 길은 위 조항들과 «전부» 무관하다** —

📌 **AI 셋 다 이건 몰랐다. 우리 코드는 우리만 안다**(규칙 29).

## 🎬 3️⃣ 정정 — 「타임스탬프 점프는 원리적으로 못 만든다」는 «너무 센» 말이었다

- ⛔ 없는 것은 장치가 아니라 **「몇 초에 무슨 단계인가」라는 «시각 데이터»**다.
- 그 시각을 얻는 길 = ⑴자막(⛔막혔다) ⑵**유저가 직접 찍는다** ⑶**창작자가 준다**(제휴)
- 📌 **⑵는 약관과 무관하다** — 유저가 자기 손으로 「여기!」 하는 것뿐이다.

## 📮 5️⃣ 세 번째 답이 새로 준 사실들

- **저작권법 제2조 제1호** 현행 시행일 = **2026-08-11**
- **Compliance Audit** = 허용 여부가 불확실하면 구글에 «서면 판단»을 받는 공식 창구가 있다

### ⭐⭐ 실측 — 우리 코드에 «이미» 있는 것 둘

```
vite.config.js:67   share_target { title, text, url, files }   ← 공유 시트에 「한끼」가 뜬다
App.jsx:317~318     공유된 «텍스트»에 레시피가 있으면 parseRecipeText 로
                    재료·순서까지 «자동으로» 채운다
```

📌 **즉 「글을 공유하면 재료·순서가 저절로 채워지는 것」이 이미 만들어져 있다.**
   유저가 유튜브 설명란 글을 **길게 눌러 선택 → 공유 → 한끼** 하면 그 자리에서 정리된다. **열쇠 0개.**

### 🔢 탭 수 비교

| | 길 | 탭 |
|---|---|---|
| 해먹으리 | 유튜브 → 공유 → 해먹으리 → (AI가 자막 읽기 기다림) | **3** |
| **우리 (지금 코드로)** | 유튜브 → 더보기 → 설명란 길게 눌러 선택 → 공유 → **한끼** | **5** |
| 우리 (유저가 지금 아는 길) | 복사 → 앱 열기 → 가져오기 → 텍스트 붙여넣기 → 붙여넣기 → 저장 | **8+** |

- ⭐ **3 대 5 다. 3 대 8이 아니다.** 그리고 **그 차이는 코드가 아니라 「유저가 모른다」에서 온다.**
- ⭐ 우리 쪽은 **서버를 안 거쳐서 기다림이 0**이다(사실). ⚠️해먹으리가 몇 초 걸리는지는 **안 재봤다**.

### 🎯 그래서 할 일이 바뀐다

**「만들기」가 아니라 「유저에게 그 길을 알려주기」다.**
- 유튜브 화면 선택지 순서 바꾸기(붙여넣기를 1번·추천으로)
- **「설명란 글 선택 → 공유 → 한끼」를 그림 한 장으로 안내**
- ⚠️ 전부 **폰에서 「유튜브 설명란 글자가 선택·공유 되나」가 참일 때만** 성립한다 → **창업자 10초 확인 대기**

### ⛔ 그리고 잣대를 바로 세운다

우리 문서가 이미 이렇게 적어놨다(`경쟁분석-맘카페침투-2026-07-19.md:33`) —

📌 **가져오기는 「이겨서 얻는 판」이 아니라 「못 하면 잃는 판」이다.**
   목표 = **「해먹으리보다 낫게」가 아니라 「해먹으리만큼 안 불편하게」.**
   ⭐ 이기러 가는 자리는 따로 있다(레꾸·기록·감정 — 우리 북극성).

# 🔄🔄 [네 번째 답] «길이 다시 열렸다» — Gemini 에 YouTube URL 을 그대로 넣는다 (⭐이게 현행이다)

> 📮 창업자가 답을 하나 더 받아 왔다. **답변자가 자기 앞 결론을 스스로 정정했다** —
> *"제가 앞서 「공개 YouTube를 AI로 분석할 공식 경로가 없다」고 말한 부분은 이 Gemini 경로를 빠뜨린 것이므로 정정합니다."*

## 0️⃣ 무엇이 뒤집혔나

**우리는 내내 「YouTube 에서 자막을 «꺼내와서» 우리가 읽는다」를 전제로 따졌다.**
그 전제가 틀렸다. **Google 자신에게 URL 을 주고 「이 영상 읽어줘」 하면 된다.**

```
[막힌 길] 유튜브 → 자막 꺼내기 → 우리 LLM        ⛔ captions.download · timedtext · yt-dlp
[막힌 길] 유튜브 API → 설명란 → 우리 LLM         ⚠️ III.E.4 derived data
[열린 길] 우리 → Gemini 에 «YouTube URL» 전달    ✅ 구글 공식 입력 방식
```

⭐⭐ **핵심 = 우리가 YouTube API 를 «아예 안 부른다».**
   → **API Data 가 없다 → III.E.4 해당 없음** · **자막을 꺼내지 않는다 → 스크래핑 조항 해당 없음**

## 1️⃣ 근거 (답변자 인용 · ⛔나는 원문을 못 봤다)

- Gemini API 공식 문서 = *"YouTube URLs — Public YouTube videos."*
- *"You can pass YouTube URLs directly to Gemini API as part of your request"*
- 할 수 있는 일 = *"describe, segment, and extract information from videos … and **refer to specific timestamps** within a video"*
- Google Cloud 쪽 = *"The YouTube video must be either owned by the account … **or be public**."*
- ⭐ **음성만이 아니라 화면까지 본다** = *"processing information from both the audio and visual streams"*
  → 말로 *"두 숟갈 넣을게요"* 하고 **화면에 굴소스 병이 보이면** 자막보다 오히려 잘 잡는다
- 🗓 2025-03 에 Gemini API 입력 소스로 YouTube URL 이 추가됐다고 한다

## 2️⃣ ⭐ 타임스탬프 점프까지 «살아난다»

```
Gemini → { steps: [ { time: "00:19", text: "…" }, … ] }
   ↓
공식 IFrame Player 로 원영상 표시 → player.seekTo(19, true)
```
- 📌 **해먹으리의 그 기능을 «공식 부품만»으로 만들 수 있다.**
- ⭐ 오늘 낮에 내가 *"타임스탬프는 원리적으로 못 만든다"* → *"장치는 공식이고 시각 데이터가 없을 뿐"* 으로
  한 번 정정했는데, **그 시각 데이터를 구글이 만들어 준다.**

## 3️⃣ 경쟁사 판정도 «바로잡힌다»

| 말 | 판정 |
|---|---|
| 「영상→레시피 기능을 제공한다」 | ✅ 확인됨 |
| 「yt-dlp 로 자막을 긁는다」 | ❓ **확인 안 됨** |
| 「YouTube 약관을 위반한다」 | ❓ **확인 안 됨** |
| 「불법이다」 | ⛔ **더더욱 말할 수 없다** |

- 🧾 해먹으리 약관 인용 = *"The Service uses AI technology to analyze, summarize, and organize information
  from URLs submitted by users"* ＋ *"The Service **does not download or store videos** on Company servers"*
  → **Gemini 식 구조와 앞뒤가 맞는다**(⛔그래도 「Gemini 를 쓴다」고 단정은 못 한다)
- ⭐ **「업계가 다 불법이다」로 볼 이유가 없어졌다.** 오늘 낮 내 답을 여기서 바로잡는다.

## 4️⃣ ⛔ 오늘 이 주제에서 내가 결론을 «네 번» 바꿨다 — 그래서 굳히지 않는다

1. 낮 = *"공식 API 자막은 영상 주인만 → 길이 없다"*
2. 저녁 = *"설명란은 되니까 ⓐ 로 가자"*
3. 밤 = *"III.E.4 때문에 설명란도 위험하다"*
4. 지금 = *"Gemini 로 URL 을 통째로 넣으면 된다"*

📌 **1·3 은 지금도 맞다.** 바뀐 건 **「그래서 길이 없다」는 결론**이고, 매번 **내가 안 본 길이 하나씩 있었다.**
⛔ **그러니 이번에도 「됐다」로 굳히지 않는다.** 아래 넷이 닫히기 전엔 만들기를 시작하지 않는다.

## 5️⃣ 🚨 새로 생긴 미지수 넷 — 이게 다음 조사(③)다

### ⑴ 🚨 **Gemini API 의 「18세 미만」 제한** — 제일 크다
- 답변자가 *"꽤 큰 변수"* 라며 콕 집었다.
- ⛔ **우리 앱 콘텐츠 등급은 「3세 이상」**이다(2026-08-05 확정 · 콘솔 실물).
- 만약 약관이 미성년 이용을 막으면 **등급을 올리거나 그 기능을 못 쓴다.**
  ⛓ 그러면 **「결제 켤 때 넷을 같이」**(등급·데이터 보안·처방침·인앱구매)가 또 걸린다.

### ⑵ 🚨 **원가 — 우리 「$0 계획」이 안 통할 수 있다**
- 우리 3층 구조 2층 = **Cloudflare Workers AI 무료티어**(하루 10,000 뉴런 · 카드 0)인데
  **그건 영상을 못 읽는다.** Gemini 영상 분석은 **토큰 자릿수가 사진과 다르다.**
- ⛔ **20~30분 영상이 흔하다**(창업자가 콕 집은 그 조건).
- 📌 **이 값이 「영상 1편 = 열쇠 몇 개」를 정한다.** ⛔짐작으로 1개라 굳히지 말 것.
- ⛔ **카드 등록**이 필요해지면 우리 원칙(⛔카드 등록 금지)과 정면으로 부딪친다.
